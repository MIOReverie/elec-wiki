# 写作与贡献指南

<Meta time="7 min" level="指南" note="按这套写法，页面读起来才像人讲的课" />

这个站是给人读的，不是给搜索引擎和评分表读的。所以下面这些约定里，凡是关于「写得好不好读」的，都比关于「结构整齐不整齐」的优先。

判断标准很简单：把一段读出声。像饭桌上给同学讲题，就是对的；像 PPT 讲稿或者产品说明书，就重写。

## 目录即结构

```
docs/
├── ee/            电工学      ee/index.md 是课程主页
├── digital/       数字电路
├── analog/        模拟电子
├── embedded/      嵌入式
├── shared/        工具页（公式速查表）
├── guide/         说明页（本页、关于、内容状态、全部页面）
└── .vitepress/
    ├── config.mts             站点配置（导航、搜索、构建）
    ├── data/catalog.ts        自动扫描章节、生成侧边栏与路线图
    └── theme/                 组件、样式、KaTeX 插件
```

新增一节 = 在那个课程的目录里放一个 `.md`。侧边栏、课程路线图、首页统计、内容状态表都会自动更新，不用动 `config.mts`。

## 一页怎么开头

读者点进来第一个问题是「我看得懂吗」。所以页头之后应该尽快回答两件事：这页要解决什么麻烦，读它需要什么底子。

需要底子这件事写进容器里，说人话：

```markdown
::: tip 读这页之前
只要会欧姆定律和二进制位操作，这页就读得动，忘了也能跟上，用到时会重算一遍。中断和定时器的细节这里不展开，看到链接跳过去就行。
:::
```

别写成 `- **需要会**：…` 这种表单。公式符号的说明可以留列表，那个本来就该是列表。

**不要写「结论先行」。** 这个站以前要求每页开头先摆五条结论，结果读者第一屏全是不认识的词，读完也不知道在说什么。结论应该长在机理里，讲完自然落一句，让读者自己走到那儿。

也不要写「这一页要解决什么」「这一节只做一件事」「接下来我们看」这类话。读者不需要被告知你准备讲什么，直接讲。

**例外**：纯查阅的页面（符号表、速查表、内容状态、页面索引、术语表、各课程 `index.md` 的清单部分）该用列表就用列表，别硬写成散文。

## 段落怎么写

这几条是硬规矩，改写完可以拿脚本查（见「提交前检查」）。

| 规矩 | 具体要求 |
| --- | --- |
| 加粗 | 每千字不超过 4 处，只给「术语首次出现」和「容易读错的结论」。不许整句加粗，不许每个列表项都拿加粗开头 |
| 破折号 | 每千字不超过 1 处。绝大多数「——」改成逗号、句号，或者拆成两句 |
| 句长 | 连续三句字数接近就改一句。5 到 12 字的短句可以单独成段 |
| 列举 | 不要为了工整凑三项，不要「首先 / 其次 / 最后」，不要「既…又…还…」 |
| 口头禅 | 「不是…而是」「越是…越」「其实」「真正的」各页每篇最多留一处 |
| 段落开头 | 不能每段都以加粗词冒号起头，也不能每段都先总后分 |

术语第一次出现必须解释，英文术语给全称。这条从建站起就在，不能松。

## 页面骨架

两种骨架都合法，按内容选，不必强行统一。

**分段骨架**（电工学为主，多数模拟、数字章节也用）

```markdown
---
title: 09 · RLC 串联与阻抗
description: 一句话说清本页讲什么
---

# 09 · RLC 串联与阻抗

<Meta time="45 min" level="核心" note="阻抗三角形是本页的核心图像" />

（从具体问题进：一个电压源接 RLC，问电流多大）

## 为什么先看阻抗
…
## 例题
## 工程实例
## 易错点
```

**编号骨架**（嵌入式为主，也用于叙事连贯的章节）

```markdown
## 一、第一个要点
## 二、第二个要点
## 三、第三个要点
```

硬要求只有两条：

1. **每道例题必须有独立锚点**，写成 `::: tip 例 N · 标题` 容器，标题末尾给页内唯一的 `{#ex-…}`（VitePress 1.6 的 markdown-it-attrs 支持）：

   ```markdown
   ::: tip 例 1 · RC 充电电路的完整过程 {#ex-rlc-1}
   ```

   锚点命名用 `ex-<章节关键词>-<序号>`。这样从目录、搜索结果或别的页面都能直接跳到某道题。
2. `title` 前缀带两位序号（路线图按它排序）；`level` 只用 **核心 / 了解 / 可跳过 / 指南 / 工具**；`time` 写成「45 min」。

小标题本身可以是一句话，不必都是名词短语。同级标题不能重名，否则右侧目录会出现两条一样的条目。

## 可用组件

已全局注册，直接用（无需 import）：

| 组件 | 作用 |
| --- | --- |
| `<Meta time="" level="" note="" />` | 页头标签条 |
| `<Prereq id="thevenin" text="自定义文字" />` | 前置知识胶囊，点击开抽屉 |
| `<DemoBox title="" hint="">…</DemoBox>` | 交互演示容器（插槽里放仿真组件） |
| `<FigBox title="" kind="" note="">…</FigBox>` | 图解容器（SVG、波形） |
| `<WavePreset kind="rc" :p="3" />` | 预设波形图，kind 见下方清单 |
| `<Ctrl label="" v-model="x" :min="" :max="" unit="" :log="true" />` | 滑块 |
| `<Seg v-model="m" :options="[{value,label}]" />` | 分段按钮 |
| `<CourseRoadmap course="digital" />` | 自动生成的章节路线表 |
| `<StatusTable />` | 内容成熟度表（全部课程） |

仿真组件按课分组放在 `theme/components/sim/`，命名以 `Demo` 结尾的由 `theme/index.ts` 统一注册。

`<WavePreset kind="…">` 支持：`threephase` `threewire` `rc` `rl` `resonance` `magnetize` `damped` `logic` `source` `ladder` `loadline` `nodepot` `maxpower` `superpose` `sinesum` `phasorref` `reactance` `powertriangle` `pfcurve` `qfamily` `parares` `neutraldisp` `instp3` `twowatt` `traeff` `vadjust` `rotfield` `torslip` `startcurve` `dcmotor` `relaytime` `scancycle` `humanbody` `stepvolt` `rectify3` `loadreg`。

## 公式与排版

- 行内 `$…$`，块级 `$$…$$`，由站点自带的 KaTeX 插件渲染（复用顶层 `katex@0.16`，保证与 CSS 同版本）。
- 不要在 HTML 块里写公式：`<div>`、`<span>` 开头的块级 HTML 内部不解析 Markdown，公式会原样显示。自定义框用 VitePress 容器 `::: tip 标题`。
- 组件属性里禁止英文双引号，Vue 会把它当属性结束符。强调用「」或『』。
- 表格里尽量用短公式，长公式放块级。

## 例题规范

- 用 `::: tip 例 N · 标题` 容器，N 在页内连续编号；
- 容器标题末尾加独立锚点 `{#ex-…}`；
- 按「先猜 → 再算 → 再回代」走：先说清读者该预期的结果和量级，再算，算完代回去看对不对；
- 关键步骤后可以加一行 `> **为什么这么想**`，只写真正的岔路口，不写每一步的复述；
- 数值必须自己算过一遍（可以用 `node -e` 验算），结果保留合理有效数字；
- 有几何意义的题目必须配图，图和数字要对得上。

## 前置知识卡片

正文里的 `<Prereq id="…" />` 胶囊指向 `docs/.vitepress/theme/data/prereq.ts` 里登记的卡片。

- 卡片正文放在 `docs/prereq/<id>.md`（跨课程通用）或 `docs/ee/prereq/<id>.md`（电工学专用）；
- 一张卡片要回答清楚四件事：这是什么、判据是什么、典型数值多少、最容易错在哪。末尾可以带一道带独立锚点的小题；
- 卡片短小是优点，不要为了去 AI 味把它写长。卡片的价值是一眼能查、看完就懂；
- 不要让所有卡片套同一个模具。有的从一道错题进，有的从一句常见误解进，有的直接给判据；
- 新增卡片要同时做三件事：写 md、在 `prereq.ts` 里加条目（含 `group`）、在承重章节里至少引用两处 `<Prereq id="…" />`；
- `group` 取值与 `PrereqIndex.vue` 的 `ORDER` 保持一致（当前：基础、分析方法、暂态、交流、三相、磁路与电机、电子技术、数字电路、模拟电子、嵌入式）；
- `docs/prereq/` 不会被 `catalog.ts` 当作课程章节扫描（已在该文件里显式排除），但每张卡片仍是可直达页面。

## 提交前检查

```bash
npm run lint    # 内容检查：引号、标签配对、$ / $$ 配对、表格列数、重复标题、空链接、未注册组件
npm run check   # lint + 构建到独立目录（含死链检查），CI 跑的就是这个
npm run build   # 完整构建到 docs/.vitepress/dist
```

死链检查已并入构建（`ignoreDeadLinks: false`），链接写错会直接让构建失败。这是有意的：wiki 的第一条底线是点得到。

## 新增一门课

1. 建 `docs/<slug>/index.md`，frontmatter 写 `title: 课程名 · 课程主页`、`description: …`；
2. 在 `docs/.vitepress/data/catalog.ts` 的 `COURSE_META` 里加一条（名称、短名、一句话定位）；
3. 在 `SECTION_LABELS` 里按目录规划分组（二级目录 → 分组标题）；
4. 在 `config.mts` 的 `sidebar` 里加 `'/<slug>/': courseSidebar('<slug>')`。

首页课程卡片、导航下拉、全部页面索引会自动带上新课。

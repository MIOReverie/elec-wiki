# 21 · PLC 与梯形图

<Meta time="25 min" level="了解" note="重点三样：扫描周期、梯形图与逻辑式的互译、双线圈禁忌" />

上一章的自锁电路，要加一个延时、改一个联锁，就得拆线重接。工厂里这类改逻辑的事每个月都有，于是一台机器替掉了整面继电器屏：**PLC**（Programmable Logic Controller，可编程逻辑控制器，面向工业开关量控制的专用计算机）用程序实现同样的触点逻辑，梯形图写起来还像继电器图，改起来只动几行代码。

可「像继电器」只是长相。PLC 里面没有电流，只有一遍遍重复执行的计算。差别就在这儿。

::: tip 读这页之前
先过一遍[第 20 章 · 继电接触器控制](relay.md) 里的自锁与互锁，再带上逻辑代数的基础（<Prereq id="boolean-algebra" />），这页就顺了。

记号认一下：I 是输入位、Q 是输出位、M 是内部中间位、T 是定时器、C 是计数器。PLC 里的「位」就是一个 0/1 变量，触点是在读位，线圈是在写位。

梯形图（ladder diagram，把触点画成横档、母线画成两根竖轨的编程语言）长得像继电器电路图，是 PLC 最常用的编程方式。逻辑式用的记号（$\cdot$ 表示与、$+$ 表示或、上划线表示非）见[符号与约定](../../guide/notation.md)。
:::

## 工作原理：循环扫描

**循环扫描**说的是 PLC 把程序从头到尾一遍遍跑，中间到底发生了什么。这件事搞清楚了，响应延迟和双线圈两个坑自己就能推出来。

加电以后，它不停重复三件事：

```
每个扫描周期：
  ① 输入采样  读所有输入端子 → 输入映像寄存器
  ② 执行程序  按梯形图从上到下、从左到右做逻辑运算 → 输出映像寄存器
  ③ 输出刷新  把输出映像的值送到输出端子 → 驱动接触器、电磁阀、指示灯
```

三个阶段走一圈叫 1 个扫描周期。小型 PLC 的周期常在 10 ms 上下，程序越长越久；到几十毫秒，人按按钮就会觉得迟了。

关键在「映像」两个字。程序不直接读端子，也不直接写端子，读写的都是映像寄存器。输入的变化要等下一次采样才被看见，输出的变化要等刷新时刻才生效，响应延迟就是这么来的。

::: tip 扫描周期带来 2 个直接后果
1. 响应延迟：输入变化到输出响应，中间隔着 1~2 个**扫描周期**（例 2 会算）。周期短响应就快，可周期长短受程序长短限制，所以「程序写得简洁」是有工程意义的。
2. **双线圈**输出会互相覆盖：输出最终取映像寄存器里最后一次写入的值（例 3 会验）。
:::

扫描机制立住了，再看程序本身长什么样。先认五个符号。

## 梯形图符号

五个元素，各读成什么逻辑，认一遍就够。

| 元素 | 画法 | 含义 |
| --- | --- | --- |
| 常开触点 | `─| |─` | 该位为 1 时「导通」 |
| 常闭触点 | `─|/|─` | 该位为 0 时「导通」 |
| 线圈 | `─( )─` | 逻辑结果写入输出位 |
| 定时器 | `─[TON T0 100]─` | 延时接通 |
| 计数器 | `─[CTU C0 5]─` | 加计数 |

定时器那条 `─[TON T0 100]─` 里，T0 是定时器编号，100 是设定值，具体多少毫秒得结合时基算，例 4 会走一遍。

左母线是电源正，右母线是电源负，中间是触点组合和线圈。这两根竖线只是画法上的约定，不是真的电源轨，所以别在图上找电位高低。梯形图就是横着的一条条支路，每条支路一个逻辑等式。一条典型梯级长这样，两个触点串联驱动一个线圈：

<CircuitFig kind="ladder" title="PLC 梯形图：左母线 → 触点串联 → 线圈 → 右母线" />

::: tip 心智模型：梯形图 = 软继电器 + 扫描，不是实物接线
看梯形图先立一个模型：左右母线不是真的电源，支路里没有电流，只有逻辑，「能流」只是形象说法。它是被 CPU 从上到下、从左到右扫描执行的一段程序：触点读的是位的 0/1，线圈把运算结果写进位。所以读一条梯级，就当读一个布尔等式，别去追电流路径。双线圈为什么互相覆盖，根子也在这里。
:::

## 梯形图 ↔ 逻辑式

任何梯形图都能机械地翻成逻辑式，反过来也一样。这套互译是本页所有例题的共同工具。

| 梯形图结构 | 逻辑式 |
| --- | --- |
| 两个触点串联 | $Q = A \cdot B$ |
| 两个触点并联 | $Q = A + B$ |
| 常闭触点 $A$ | $\bar{A}$ |
| 启保停 | $Q = (A + Q)\cdot \bar{B}$（$A$ 起动、$B$ 停止） |
| 正反转（带互锁） | $Q_0 = (A_0 + Q_0)\cdot\bar B\cdot \bar{Q_1}$ |

转换规则一句话：从左母线开始，遇串联就乘，遇并联就加，遇常闭就取反，一直推到线圈。练三五遍就能条件反射。

互译规则在手，上一章的继电器电路就能直接搬进 PLC。搬的时候每个器件对应 PLC 里什么东西，往下看。

## 从继电器电路改造

[第 20 章 · 继电接触器控制](relay.md)那张继电控制图，改造成 PLC 只要重画控制电路那半边：

| 继电器电路里的 | PLC 里的 |
| --- | --- |
| 按钮、行程开关、传感器 | 输入点 I |
| 接触器线圈、电磁阀、指示灯 | 输出点 Q |
| 中间继电器的触点逻辑 | 内部位 M |
| 时间继电器 | 定时器 T |
| 热继电器常闭触点 | 输入点（或保留在硬件回路做后备保护） |
| 自锁/互锁触点 | 输出位的常开/常闭触点（软触点，可无限次使用） |

::: warning 停止按钮接常开还是常闭
硬件接常闭，程序里当条件用（梯形图里画成常开触点 `─| |─`，逻辑式里直接串联 $I0.1$）。

这叫**故障导向安全**，接线方式是：按下按钮，回路断开，$I0.1 = 0$，程序停机。要是电线断了呢？$I0.1$ 同样变 0，电机同样停机，这就是故障导向安全。反过来接常开，断线时程序以为没人按停止，电机会一直转，那才危险。
:::

还有一件事表里没写：输出点本身分 3 种形态。继电器输出能带交流也能带直流，动作慢，带接触器最稳；晶体管输出只带直流，动作快，能打脉冲；双向可控硅输出专带交流负载。选型时先看你后面挂的是什么，别只数点数。

器件映射完了，安全规则也立住了。看例题之前扫一眼指令表，知道手上有哪些积木。

## 常用指令

速查表，不用背。例题里用到 TON 时回来瞄一眼即可。

| 类别 | 指令 | 说明 |
| --- | --- | --- |
| 位逻辑 | LD / LDN / A / AN / O / ON / = | 取、与、或、输出 |
| 定时 | TON（接通延时）、TOF（断开延时）、TP（脉冲） | PT 是设定值 |
| 计数 | CTU / CTD / CTUD | 计到设定值置位 |
| 数据处理 | 传送 MOV、比较、运算、移位 | — |
| 边沿检测 | EU / ED | 只在状态变化的那一个周期动作一次 |

这张表不用背，但得知道每一类的存在：位逻辑负责搭骨架，定时和计数负责管时间，数据处理和边沿检测负责批量信号。写程序时想不起某个功能，先翻表看有没有现成的，比硬凑触点快。

指令认全，开始做题。四道题从互译到组合，把要点挨个过一遍。

## 例题

四道题按「翻译 → 计时 → 辨析 → 组合」排，每题先看先想什么。

::: tip 例 1 · 梯形图转逻辑式
写出下图梯形图的逻辑表达式，并说明它实现什么功能。

<CircuitFig kind="ladder" title="例 1 的梯形图：I0.0 与自锁触点 Q0.0 并联，串常闭 I0.1，驱动 Q0.0" note="先找线圈，再倒推它的触点组合：两条并联支路（I0.0 与 Q0.0 常开）共同串联一个常闭触点 I0.1。" />

先想什么：读梯形图别追电流，按固定动作走。先找到线圈，再从左母线倒推它的触点组合：并联是 +、串联是 $\cdot$、常闭取反。翻完再看这个式子像谁。

```
  I0.0   Q0.0
──| |──┬──| |──┬──|/|────( )──
       │       │   I0.1  Q0.0
       └───────┘
```

解：两条并联支路（I0.0 与 Q0.0 常开）串联 I0.1 常闭，驱动 Q0.0 线圈：

$$
Q0.0 = (I0.0 + Q0.0)\cdot \overline{I0.1}
$$

这正是启保停：I0.0 是起动按钮，按一下即松开，靠 Q0.0 自己的常开触点续上；I0.1 是停止按钮，接的是常闭，程序里取反后串联。式子和[第 20 章 · 继电接触器控制](relay.md)的继电器电路完全同构，只是这里的 Q0.0 触点不占物理端子，可以随意使用。

验算：代入两个边界状态。按住 I0.0、未按 I0.1，$Q=(1+0)\cdot 1=1$ ✓ 起动；松开 I0.0，$Q=(0+1)\cdot 1=1$ ✓ 保持；按 I0.1，$Q=(0+1)\cdot 0=0$ ✓ 停止。自锁、停止全部吻合。
:::

::: tip 例 2 · 扫描周期与响应延迟
某 PLC 扫描周期 $T = 100$ ms，其中输入采样占前 5 ms，输出刷新在第 90~95 ms。输入 I0.0 在执行程序阶段中途（第 6 ms）发生变化，输出 Q0.0 什么时候响应？

先想什么：这是把扫描三阶段当时间轴用的题。关键动作只有两步，先找下一次采样时刻（输入映像何时更新），再找那之后的下一次刷新时刻（输出何时生效），两者一减就是延迟。

1. 采样时机：变化发生在第 6 ms，本周期的采样（0~5 ms）已经过去了。所以要等下一个周期的采样，第 100 ms 时 I0.0 的新状态才进入输入映像寄存器。等待时间 $= 100 - 6 = 94$ ms。*（为什么不在本周期补采：扫描纪律是「程序执行期间输入映像冻结」，中途改读会让同一段程序前后看到两个不一样的世界。）*
2. 刷新时机：下一周期执行程序、刷新输出发生在第 90~95 ms（即第 190 ms 时刻），Q0.0 此刻才真正改变。从输入变化算起共延迟 $190 - 6 = 184$ ms $\approx 1.84\,T$。*（为什么不按刷新点 90 ms 算：执行程序读的还是刷新前的输出映像，必须等刷新完成才送到端子。）*

另一种极端：输入在第 99 ms 变化（采样前 1 ms），第 100 ms 就被采入，输出在第 190 ms 刷新，延迟仅 $91$ ms $\approx 0.91\,T$。

验算：延迟 $=$ 采样等待 $+$ 执行等待 $\approx 94 + 90 = 184$ ms，与直接相减 $190-6$ 一致 ✓；两个极端（0.91 T 与 1.84 T）都落在「1~2 个周期」这个区间里 ✓。

所以工程上按一个周期估算延迟就够了。对响应速度有要求的场合，比如限位急停，要么缩短扫描周期，要么把最关键的信号接进高速输入或中断，不能指望主循环。
:::

::: tip 例 3 · 双线圈为什么是禁忌
程序中同一个输出线圈 Q0.0 在两个地方各出现一次：

```
支路1：I0.0 ──| |──────────(Q0.0)──
支路2：I0.1 ──| |──────────(Q0.0)──
```

I0.0 = 1、I0.1 = 0 时，Q0.0 是什么？

先想什么：直觉答案是「两条支路并联，Q0.0 = 1」，那是继电器思维。这道题考的正是这个模型失效的地方。PLC 是串行执行的，同一个线圈被写了两次，后一次必然覆盖前一次，问题于是变成「最后写的是哪条支路」。

解：Q0.0 = 0。

因为扫描是从上到下顺序执行的。支路 1 执行时算得 Q0.0 = 1 写进输出映像；执行到支路 2 时又算得 Q0.0 = 0，把前面的结果覆盖掉。刷新时送到端子的是最后写入的值，支路 1 的逻辑等于白写。

验算：把执行顺序逐步列出来。扫描到支路 1，输出映像 Q0.0 ← 1；扫描到支路 2，输出映像 Q0.0 ← 0；刷新，端子得到 0 ✓，与串行覆盖的推理一致。

这和继电器电路有本质区别。继电器电路里那 2 条支路是真正的并联，物理上同时存在；PLC 是串行执行。结论：1 个线圈在程序里只允许写 1 次。想要「或」逻辑，就把两个条件并联到同一条支路里，或者用内部位 M 中转。

触点则相反，常开常闭触点可以无限次引用，因为它们只读位状态，不产生写入冲突。
:::

::: tip 例 4 · 定时器延时起动
要求：按下 I0.0 后延时 10 s 才接通 Q0.0；松开 I0.0 立即停止。设 TON 定时器时基为 100 ms，写出梯形图结构和 PT 值。

先想什么：拆需求。「延时接通」正是 TON（接通延时定时器，条件满足后开始计时、计满才闭合触点）的定义，选型不用犹豫。剩下两件事：定时器挂在哪个条件上，以及 PT 怎么从 10 s 换算成计数个数。松开要立即停，所以挂在 I0.0 上，条件一消失计时就中断，触点也就断开。

解：TON 是接通延时定时器，条件一满足就开始计时，计到 PT 才把触点闭合。所以：

```
I0.0 ──| |────[TON  T0  PT=100]──
                    T0 常开 ──| |────────( Q0.0 )──
```

PT 的换算：时基 100 ms × 100 = 10 000 ms = 10 s，所以 PT = 100。

两个容易错的地方：

- TON 计时期间触点还没闭合，Q0.0 不会动作；计时中断（条件消失）时定时器当前值清零，下次重新从 0 计
- 若要「延时断开」，得用 TOF，或者用「停止后启动另一个定时器」的写法，TON 本身做不到

验算：PT 换算倒推，$100\times100\ \text{ms}=10\ \text{s}$ ✓；行为核对，按住 I0.0 满足 10 s 后 Q0.0 = 1，第 9.9 s 松开则计时清零、Q0.0 保持 0，与「松开立即停止」的要求一致 ✓。
:::

## 工程实例：用 PLC 改造一台老机床

老设备是继电接触器控制，改造分五步。

1. 清点 I/O：数输入（起动、停止、正转、反转、限位 ×3、热继电器、急停 ≈ 8 点）和输出（正转线圈、反转线圈、指示灯 ×4 ≈ 6 点），选 16 点输入 / 16 点输出的小型 PLC，点数留 30% 裕量。
2. 分配地址：把每个器件写成 I/O 分配表，这张表就是程序的图纸。
3. 翻译控制电路：主电路几乎不动，接触器、热继电器、电机原样保留，只把控制电路的硬接线换成梯形图。热继电器仍接在硬件回路里做后备保护，程序不能是唯一的安全屏障。
4. 急停必须硬接线：急停按钮直接串在接触器线圈的电源回路里，不经过 PLC 程序。程序会死机，硬件不会。
5. 调试：先单独调每个支路，也就是点动，再联调；用「强制」功能模拟输入，省得反复按按钮。
6. 留档：梯形图、I/O 分配表、参数设置各存一份，贴在柜门内侧。老机床改造最怕的就是三年后没人知道某个中间位 M 是干什么的。

改造的收益不只是省电线。改工艺只需改程序，加一个定时、计数或联锁只是几行梯形图，这是硬接线做不到的。

程序再可靠也有死机的时候，安全底线还得靠接地、漏电与急救那些知识兜住。那是下一章的事。

## 易错清单

按踩坑频率排序，格式是「错误做法 → 会得到什么 → 正确做法」。

1. 一个线圈在程序里出现两次 → 后执行的覆盖先执行的，前面支路白写 → 线圈只出现一次，「或」逻辑并进同一条支路或用 M 中转。
2. 把梯形图当电路追电流 → 分析串行覆盖现象时必然出错 → 它是逻辑运算，读成布尔等式。
3. 停止按钮硬件接常开 → 断线时程序不知道，电机停不下来 → 硬件接常闭，程序里当条件串联，也就是故障导向安全。
4. 急停只写进程序 → 程序死机时急停失效 → 急停直接串在接触器线圈电源回路，不经过 PLC。
5. TON 计时中断以为能续算 → 定时值清零，动作时间对不上 → 条件断开当前值清零重来；要「断开保持」得另搭回路。
6. 响应延迟按 0 估 → 高速场合（限位、急停）出错 → 按 1~2 个扫描周期估；关键信号走硬件或中断。
7. 输出类型不看 → 继电器输出接高频脉冲失灵、晶体管输出接交流烧毁 → 继电器输出（交直流、慢）与晶体管输出（直流、快、可脉冲）分开选。

# 20 · PLC 与梯形图

<Meta time="25 min" level="了解" note="重点：扫描周期、梯形图与逻辑式的互换、双线圈禁忌" />

## 结论先行

1. PLC 是工业控制计算机，**循环扫描**工作：输入采样 → 执行程序 → 输出刷新，周而复始
2. 梯形图长得像继电器电路，但**里面没有电流**，只有逻辑运算——"能流"只是形象说法
3. 梯形图与逻辑式一一对应：**串联 = 与，并联 = 或，常闭 = 取反**；这是考试的基本功
4. 启保停的梯形图和继电器电路**长得完全一样**，但"自锁"的含义变了：继电器里是触点闭合，PLC 里是输出位为 1
5. **同一线圈在一个程序里只能出现一次**（双线圈禁忌），而触点可以无限次引用
6. 停止按钮要**故障导向安全**：硬件接常闭，程序里当"条件"串联

## 工作原理：循环扫描

PLC 加电后不停重复三件事：

```
每个扫描周期：
  ① 输入采样  读所有输入端子 → 输入映像寄存器
  ② 执行程序  按梯形图从上到下、从左到右做逻辑运算 → 输出映像寄存器
  ③ 输出刷新  把输出映像的值送到输出端子 → 驱动接触器、电磁阀、指示灯
```

关键在"映像"两个字：**程序不直接读端子，也不直接写端子**，读写的都是映像寄存器。输入的变化要等下一次采样才被看见，输出的变化要等刷新时刻才生效——这就是响应延迟的来源。

::: tip 扫描周期带来两个直接后果
1. **响应延迟**：输入变化到输出响应的延迟在 1~2 个扫描周期之间（见例 2）。周期越短响应越快，但周期受程序长短限制——这就是为什么"程序写得简洁"有工程意义。
2. **双线圈输出会互相覆盖**：因为输出最终由映像寄存器里最后一次写入的值决定（见例 3）。
:::

## 梯形图符号

| 元素 | 画法 | 含义 |
| --- | --- | --- |
| 常开触点 | `─| |─` | 该位为 1 时"导通" |
| 常闭触点 | `─|/|─` | 该位为 0 时"导通" |
| 线圈 | `─( )─` | 逻辑结果写入输出位 |
| 定时器 | `─[TON T0 100]─` | 延时接通 |
| 计数器 | `─[CTU C0 5]─` | 加计数 |

左母线（电源正）→ 触点组合 → 线圈 → 右母线（电源负）。梯形图是"横着的一条条支路"，每条支路是一个逻辑等式。

::: tip 心智模型：梯形图 = 软继电器 + 扫描，不是实物接线
看梯形图先立一个模型：左右母线不是真的电源，支路里没有电流，只有**逻辑**——「能流」只是形象说法。它是被 CPU **从上到下、从左到右扫描执行**的一段程序：触点读的是「位」的 0/1，线圈是把运算结果写进「位」。所以读一条梯级，就当读一个布尔等式，别去追电流路径——这也是为什么「双线圈」会互相覆盖（见例 3）。
:::

## 梯形图 ↔ 逻辑式（考试基本功）

| 梯形图结构 | 逻辑式 |
| --- | --- |
| 两个触点串联 | $Q = A \cdot B$ |
| 两个触点并联 | $Q = A + B$ |
| 常闭触点 $A$ | $\bar{A}$ |
| 启保停 | $Q = (A + Q)\cdot \bar{B}$（$A$ 起动、$B$ 停止） |
| 正反转（带互锁） | $Q_0 = (A_0 + Q_0)\cdot\bar B\cdot \bar{Q_1}$ |

**转换规则**：从左母线开始，遇到串联就"乘"，遇到并联就"加"，遇到常闭就"取反"，一直推到线圈。练三五遍就能条件反射。

## 从继电器电路改造

第 19 章那张继电控制图，改造成 PLC 只要重画控制电路那半边：

| 继电器电路里的 | PLC 里的 |
| --- | --- |
| 按钮、行程开关、传感器 | 输入点 I |
| 接触器线圈、电磁阀、指示灯 | 输出点 Q |
| 中间继电器的触点逻辑 | 内部位 M |
| 时间继电器 | 定时器 T |
| 热继电器常闭触点 | 输入点（或保留在硬件回路做后备保护） |
| 自锁/互锁触点 | 输出位的常开/常闭触点（**软触点，可无限次使用**） |

::: warning 停止按钮接常开还是常闭
**硬件接常闭，程序里当"条件"用**（梯形图里画成常开触点 `─| |─`，逻辑式里直接串联 $I0.1$）。

原因：这样接线时，按钮按下 → 回路断开 → $I0.1 = 0$ → 程序停机。而如果**电线断线**（故障），$I0.1$ 同样变 0，电机同样停机——这就是"故障导向安全"。反过来若接常开，断线时程序以为"没按停止"，电机会继续转，很危险。
:::

## 常用指令

| 类别 | 指令 | 说明 |
| --- | --- | --- |
| 位逻辑 | LD / LDN / A / AN / O / ON / = | 取、与、或、输出 |
| 定时 | TON（接通延时）、TOF（断开延时）、TP（脉冲） | PT 是设定值 |
| 计数 | CTU / CTD / CTUD | 计到设定值置位 |
| 数据处理 | 传送 MOV、比较、运算、移位 | — |
| 边沿检测 | EU / ED | 只在状态变化的那一个周期动作一次 |

## 例题

::: tip 例 1 · 梯形图转逻辑式
写出下图梯形图的逻辑表达式，并说明它实现什么功能。

```
  I0.0   Q0.0
──| |──┬──| |──┬──|/|────( )──
       │       │   I0.1  Q0.0
       └───────┘
```

**解**：两条并联支路（I0.0 与 Q0.0 常开）串联 I0.1 常闭，驱动 Q0.0 线圈：

$$
Q0.0 = (I0.0 + Q0.0)\cdot \overline{I0.1}
$$

这正是**启保停**：I0.0 是起动按钮（按一下即松开，靠 Q0.0 自己的常开触点续上），I0.1 是停止按钮（常闭，程序里取反后串联）。与第 19 章的继电器电路完全同构——只是这里的 Q0.0 触点不占物理端子，可以随意使用。
:::

::: tip 例 2 · 扫描周期与响应延迟
某 PLC 扫描周期 $T = 100$ ms，其中输入采样占前 5 ms，输出刷新在第 90~95 ms。输入 I0.0 在**执行程序阶段中途**（第 6 ms）发生变化，输出 Q0.0 什么时候响应？

**解**：分两步推。

1. **采样时机**：变化发生在第 6 ms，本周期的采样（0~5 ms）已经过去了。所以要等**下一个周期**的采样，即第 100 ms 时 I0.0 的新状态才进入输入映像寄存器。等待时间 $= 100 - 6 = 94$ ms。
2. **刷新时机**：下一周期执行程序、刷新输出发生在第 90~95 ms（即第 190 ms 时刻），Q0.0 此刻才真正改变。从输入变化算起共延迟 $190 - 6 = 184$ ms $\approx 1.84\,T$。

另一种极端：若输入在第 99 ms 变化（采样前 1 ms），则第 100 ms 就被采入，输出在第 190 ms 刷新，延迟仅 $91$ ms $\approx 0.91\,T$。

**结论**：响应延迟在 **1~2 个扫描周期**之间。工程上按"一个周期"估算；对响应速度有要求的场合（如限位急停），要么缩短扫描周期，要么把最关键的信号接进**高速输入/中断**，不能指望主循环。
:::

::: tip 例 3 · 双线圈为什么是禁忌
程序中同一个输出线圈 Q0.0 在两个地方各出现一次：

```
支路1：I0.0 ──| |──────────(Q0.0)──
支路2：I0.1 ──| |──────────(Q0.0)──
```

I0.0 = 1、I0.1 = 0 时，Q0.0 是什么？

**解**：**Q0.0 = 0**。

因为扫描是"从上到下"顺序执行的：支路 1 执行时算得 Q0.0 = 1 写进输出映像；执行到支路 2 时又算得 Q0.0 = 0，**把前面的结果覆盖掉**。刷新时送到端子的是最后写入的值——支路 1 的逻辑等于白写。

这与继电器电路有本质区别：继电器电路里两个支路是真正的并联（物理上同时存在），而 PLC 是串行执行。**结论：一个线圈在程序里只允许出现一次**；想实现"或"逻辑，就把两个条件并联到同一支路里，或者用内部位 M 中转。

触点则相反：**常开/常闭触点可以无限次引用**，因为它们只是"读"位状态，不产生写入冲突。
:::

::: tip 例 4 · 定时器延时起动
要求：按下 I0.0 后**延时 10 s** 才接通 Q0.0；松开 I0.0 立即停止。设 TON 定时器时基为 100 ms，写出梯形图结构和 PT 值。

**解**：TON 是"接通延时"定时器——条件一满足就开始计时，计到 PT 才把触点闭合。所以：

```
I0.0 ──| |────[TON  T0  PT=100]──
                    T0 常开 ──| |────────( Q0.0 )──
```

PT 的换算：时基 100 ms × 100 = 10 000 ms = **10 s**，所以 **PT = 100**。

两个容易错的地方：

- **TON 计时期间触点还没闭合**，Q0.0 不会动作；计时中断（条件消失）时定时器**当前值清零**，下次重新从 0 计
- 若要"延时断开"，得用 TOF 或用"停止后启动另一个定时器"的写法——TON 本身做不到
:::

## 工程实例：用 PLC 改造一台老机床

老设备是继电接触器控制，改造步骤：

1. **清点 I/O**：数输入（起动、停止、正转、反转、限位 ×3、热继电器、急停 ≈ 8 点）和输出（正转线圈、反转线圈、指示灯 ×4 ≈ 6 点），选 16 点输入 / 16 点输出的小型 PLC（点数留 30% 裕量）
2. **分配地址**：把每个器件写成 I/O 分配表，这是程序的"图纸"
3. **翻译控制电路**：主电路几乎不动（接触器、热继电器、电机原样保留），只把控制电路的硬接线换成梯形图；**热继电器仍接在硬件回路里**作后备保护——程序不能是唯一的安全屏障
4. **急停必须硬接线**：急停按钮直接串在接触器线圈的电源回路里，不经过 PLC 程序。**程序会死机，硬件不会**
5. **调试**：先单独调每个支路（点动），再联调；用"强制"功能模拟输入，避免反复按按钮

改造的收益不只是省电线：改工艺只需改程序，加一个定时/计数/联锁只是几行梯形图——这是硬接线做不到的。

## 易错清单

- PLC 是**串行扫描**，不是并行；同一个线圈**只能出现一次**
- 梯形图里"能流"是形象说法，本质是逻辑运算，不要真的去分析电流路径
- 停止按钮**硬件接常闭**，程序里当条件串联（故障导向安全）
- 急停**不要只靠程序**，必须串在硬件回路
- 双线圈：后执行的覆盖先执行的；触点则可以无限次引用
- TON 计时中条件断开，定时值**清零重来**
- 输出类型要分清：继电器输出（交直流、慢）、晶体管输出（直流、快、可脉冲）
- 响应延迟 1~2 个扫描周期，高速/安全信号走硬件或中断

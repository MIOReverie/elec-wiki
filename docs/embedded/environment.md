# 02 · 开发环境与第一个工程

<Meta time="35 min" level="了解" note="工具链怎么搭、CubeMX 生成了什么、点灯的三步到底在干什么" />

## 结论先行

1. **工具链只有三件事**：把 C 代码编译成芯片能跑的机器码（编译器）、把引脚和时钟配好（CubeMX）、把程序灌进芯片并调试（ST-Link）。IDE 只是把它们打包在一起。
2. **CubeMX 的价值是「用图形配时钟树和引脚复用，然后生成初始化代码」**，你只需要在生成的工程里写应用逻辑。
3. **点灯的固定三步**：开 GPIO 时钟 → 配置引脚为输出 → 写高低电平。**漏掉第一步是新手最常犯的错**，而且症状是「代码没错但灯就是不亮」。
4. **HAL 库是主流选择**：可读性和跨系列移植性好，代价是代码体积和效率；底层调优才用 LL 或直接写寄存器。
5. **下载用 SWD（两根线），调试靠断点**；串口下载（ISP）是救砖手段，不是常规方式。

## 一、工具链到底是什么

很多人装完 IDE 还是不知道自己装了什么。把嵌入式开发想象成「在 PC 上写代码，给 ARM 芯片运行」，中间需要三样东西：

| 环节 | 工具 | 作用 | 产物 |
| --- | --- | --- | --- |
| **配置** | STM32CubeMX | 图形化分配引脚、配时钟树、生成初始化代码 | `.ioc` 文件 + 初始化 C 代码 |
| **编译** | `arm-none-eabi-gcc`（交叉编译器） | 在 x86 PC 上编译出 ARM 指令 | `.o` → `.elf`（含调试信息）→ `.hex` / `.bin` |
| **下载调试** | ST-Link / J-Link + OpenOCD | 通过 SWD 把固件写进 Flash，支持断点单步 | — |

**为什么叫「交叉编译」**：编译器跑在 x86 的 PC 上，产出的却是 ARM 的机器码，两者架构不同。`arm-none-eabi` 这个名字就是「ARM 架构 / 无操作系统 / 嵌入式 ABI」。

**IDE 怎么选**：

- **STM32CubeIDE**（推荐入门）：ST 官方免费，CubeMX 直接集成在里面，装一个就能跑通全流程，省去配置烦恼。
- **VS Code + STM32 VS Code 扩展 + CMake + OpenOCD**：更轻、可定制，适合想理解构建过程或用 Git 管理工程的人；配置步骤多一些。
- **Keil MDK**：老牌商业软件，国内教程极多，但要注意授权；很多学校机房用的是它。

本课程的例子以 **HAL 库 + CubeMX** 为准（三种 IDE 生成的代码结构一致），不绑定某个具体 IDE。

## 二、CubeMX 生成了什么

CubeMX 做两件你手工做起来极易出错的事：**引脚复用分配**和**时钟树计算**。它把结果写进 `.ioc` 文件，并生成一套初始化代码。

生成的工程结构（CubeIDE 典型布局）：

```
项目/
├─ Core/
│  ├─ Inc/           头文件：main.h、gpio.h、stm32f1xx_it.h…
│  └─ Src/           源文件：main.c、gpio.c、stm32f1xx_it.c…
├─ Drivers/
│  ├─ CMSIS/         内核相关（Cortex-M 的寄存器定义）
│  └─ STM32F1xx_HAL_Driver/   HAL 库源码
├─ Startup/          启动文件（startup_stm32f103xb.s）
├─ 项目.ioc          CubeMX 配置文件（双击可用 CubeMX 打开）
└─ STM32F103C8TX_FLASH.ld    链接脚本（决定代码放在 Flash 的哪里）
```

`main.c` 的骨架是这样的——**注意注释里的「用户代码」保护区**：

```c
int main(void) {
  HAL_Init();                  // 初始化 HAL 库（含 SysTick 时基）
  SystemClock_Config();        // 配置时钟树（CubeMX 生成）
  MX_GPIO_Init();              // 配置 GPIO（CubeMX 生成）

  while (1) {
    /* USER CODE BEGIN 3 */     // ← 你的代码写在这里
    /* USER CODE END 3 */
  }
}
```

**关键约定**：只有写在 `USER CODE BEGIN` 和 `USER CODE END` 之间的代码，才会在你下次用 CubeMX 改配置重新生成时**被保留**；写在外面会被覆盖。这是新手丢代码的头号原因。

## 三、第一个工程：点亮一颗 LED

### 硬件

LED 不能直接接在 IO 上——它是电流驱动器件，必须串**限流电阻**。电阻值由欧姆定律决定：

$$R = \frac{V_{CC} - V_F}{I_F}$$

其中 $V_F$ 是 LED 的正向压降（红光约 1.8~2.0 V，蓝/白光约 3.0~3.3 V），$I_F$ 是想要的工作电流（普通指示 LED 取 5~10 mA 即可）。

::: tip 例 1 · 算 LED 的限流电阻
用 3.3 V 供电、红色 LED（$V_F = 2.0$ V），想让它工作在 10 mA：

$$R = \frac{3.3 - 2.0}{0.01} = 130\ \Omega$$

取标称值 **130 Ω**（或最接近的 150 Ω）。此时实际电流：

$$I = \frac{3.3 - 2.0}{130} = 10\ \text{mA}$$

换 5 V 供电同样算：$R = (5 - 2)/0.01 = 300\ \Omega$。

**注意灌电流限制**：STM32 单个 IO 的吸收/输出电流一般不超过 20~25 mA，整片总电流也有上限（F103 约 150 mA）。驱动大功率 LED、继电器、电机**必须**用三极管或 MOS 管，不能直接挂 IO。
:::

### 软件三步

```c
// ① 开时钟（最容易漏！）
__HAL_RCC_GPIOC_CLK_ENABLE();

// ② 配置引脚为推挽输出
GPIO_InitTypeDef g = {0};
g.Pin   = GPIO_PIN_13;
g.Mode  = GPIO_MODE_OUTPUT_PP;   // 推挽输出
g.Pull  = GPIO_NOPULL;
g.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOC, &g);

// ③ 写电平（PC13 低电平点亮，因为板子上 LED 是灌电流接法）
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);   // 亮
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);                  // 翻转
```

**为什么第一步不能漏**：STM32 上电后所有外设时钟默认是**关闭**的（为了省电）。不打开时钟，对应的寄存器根本不会被驱动，你对 GPIO 的任何写入都像打在棉花上——不报错，也没效果。

::: tip 例 2 · 同一个点灯，寄存器版 vs HAL 版
**HAL 版**（上面那段）可读性好，换芯片基本不用改。

**直接写寄存器版**（F103）：

```c
RCC->APB2ENR |= (1 << 4);        // ① 开 GPIOC 时钟（bit4 = IOPCEN）
GPIOC->CRH   &= ~(0xF << 20);    // ② 清掉 PC13 的配置位（CRH 管 Pin8~15，PC13 占 bit[23:20]）
GPIOC->CRH   |=  (0x1 << 20);    //    配成 通用推挽输出、10 MHz
GPIOC->BSRR   =  (1 << 13);      // ③ BRy：BSRR 低 16 位置位（输出高）
GPIOC->BRR    =  (1 << 13);      //    BRR（或 BSRR 高 16 位）清零（输出低）
```

对比结论：**HAL 用结构体描述意图，寄存器版直接操作地址**。寄存器版快、省空间，但要自己查手册确认每一位的位置（比如 PC13 为什么是 `CRH` 的 bit[23:20]——因为 CRH 管 8~15 号引脚，每个引脚占 4 位，$13 - 8 = 5$，$5 \times 4 = 20$）。

入门用 HAL，需要极致效率或排查硬件时再回到底层。
:::

## 四、HAL、LL、寄存器：三层怎么选

| 层次 | 特点 | 代码体积/效率 | 适合 |
| --- | --- | --- | --- |
| **HAL**（硬件抽象层） | 跨系列可移植，API 统一，CubeMX 直接生成 | 体积大、有函数调用开销 | 入门、快速开发、跨型号移植 |
| **LL**（底层库） | 接近寄存器，但用宏封装位定义 | 接近手写效率 | 需要效率又想少查手册 |
| **寄存器直写** | 完全手工，最快最小 | 最优 | 时序苛刻的场合（如软件模拟协议） |
| ~~SPL 标准库~~ | F1 时代的旧库，ST 已停止维护 | — | 仅在维护老项目时遇到 |

**实践建议**：用 HAL 跑通功能，遇到「时序差几个微秒」「中断响应不够快」再针对性换成 LL 或寄存器写法，不要一上来就全部手写。

## 五、下载、启动模式与调试

### SWD：只要两根线

**SWD**（Serial Wire Debug）是 ARM 的调试接口，只需 **SWDIO**（数据）和 **SWCLK**（时钟）两根信号线 + GND，比 JTAG 省引脚。ST-Link V2 就是最常见的 SWD 调试器（十几元）。

调试器能做的事：下载固件、设断点、单步、查看/修改变量和寄存器、看调用栈。**会用断点，就不需要靠点灯猜程序跑到哪了**。

### 三种启动/下载方式

| 方式 | 怎么进 | 用途 |
| --- | --- | --- |
| **SWD 下载**（常规） | BOOT0 = 0，接 ST-Link | 日常开发，可调试 |
| **串口 ISP** | BOOT0 = 1 上电，走 USART1 | 没有调试器时的救急；进的是芯片内部固化的 BootLoader |
| **DFU（USB）** | 部分型号支持，BOOT0 = 1 | 产品现场升级 |

::: tip 例 3 · 程序下载成功却不运行，怎么排查
按顺序查这四条，能覆盖绝大多数情况：

1. **BOOT0 引脚电平**：必须接地（低电平）才是从主 Flash 启动。若 BOOT0 被拉高，芯片上电进 BootLoader，等在那里不运行你的程序——**下载完全正常，只是不跑**。
2. **是否真的在跑**：在 `while(1)` 里放一个翻转 LED，或者用调试器看 PC 指针是否在 `main` 里。
3. **时钟配置失败**：若外部晶振没焊或不起振，`SystemClock_Config()` 会卡在等待 HSE 就绪的循环里（HAL 会返回错误或死等）。可先改用 HSI 验证。
4. **复位电路**：NRST 被意外拉低会让芯片一直处于复位状态。
:::

## 六、工程实例

**`printf` 重定向**：把 `printf` 的输出转到串口，是嵌入式最实用的调试手段。做法是重定向底层写函数（不同工具链函数名不同，GCC 下是 `_write`）：

```c
int _write(int fd, char *ptr, int len) {
  HAL_UART_Transmit(&huart1, (uint8_t *)ptr, len, 100);
  return len;
}
```

之后 `printf` 就能从串口打印变量。注意浮点格式化（`%f`）在新工具链里默认可能被裁剪以节省空间，需要显式开启。详细的串口配置见 [08 · 串口 UART](./uart.md)。

**软件延时为什么不准**：很多人入门时写 `for(i=0;i<72000;i++);` 当作 1 ms 延时。问题在于——编译器优化等级一变、循环体内容一改，每次循环的机器周期数就变了，延时会整体漂移。

::: tip 例 4 · 估算空循环延时，并看清它为什么不可靠
72 MHz 下，1 ms 对应 $72 \times 10^6 \times 0.001 = 72000$ 个时钟周期。若一次空循环约消耗 4 个周期，则大约需要

$$n = \frac{72000}{4} = 18000\ \text{次循环}$$

**但这个数字不可靠**，因为：

1. 编译器优化等级（`-O0` / `-O2` / `-Os`）会改变循环展开方式；
2. 循环体里只要多一条语句，每次迭代的周期数就变了；
3. 开启了指令 Cache（M7）或 Flash 预取后，取指时间还会变。

所以**精确定时一律用定时器**（见 [07 · 定时器与 PWM](./timer-pwm.md)），软件延时只适合「不关心精确时长」的消抖和简单闪灯。
:::

## 七、易错清单 + 自检

- [ ] **忘记开外设时钟**：GPIO/定时器/串口都要先 `__HAL_RCC_xxx_CLK_ENABLE()`，症状是「配置都对但没反应」
- [ ] **代码写在 USER CODE 保护区之外**：下次 CubeMX 重新生成就丢了
- [ ] **LED 没串限流电阻**，或电流超过 IO 承受（单脚 ≤ 20 mA 左右）
- [ ] **BOOT0 没接地**：下载成功却不运行
- [ ] **外部晶振不起振导致卡在 SystemClock_Config**：先切 HSI 定位问题
- [ ] **`printf` 的 `%f` 打不出来**：新工具链默认裁剪了浮点格式化支持
- [ ] **用软件延时做精确定时**：会被编译器优化和主频影响，要用定时器

**自检**：说出点灯的固定三步；说出 STM32 上电后外设时钟的默认状态；说出 BOOT0 = 1 时芯片会做什么。（答案：开时钟 → 配引脚 → 写电平；默认全部关闭以省电；进入系统 BootLoader，不运行用户程序）

# 09 · SPI 与 I²C

<Meta time="45 min" level="核心" note="两种最常用的板级总线：一个快而费线，一个省线而优雅；最容易错的是 CPOL/CPHA 配错位与 I²C 地址忘了左移" />

刚拿到一块 OLED 屏，例程里写着「SPI 模式 3」；旁边那颗温湿度传感器是 I²C 的，地址标着 `0x68`。屏幕接上，刷出来是错乱的条纹；传感器接上，搜不到设备。

两个失败原因完全不同。屏幕是主机和从机对「什么时候采样」的理解没对齐，也就是 SPI 模式；传感器是你发出的地址和手册给的不是同一个数，也就是 I²C 地址忘了左移。

SPI（Serial Peripheral Interface，串行外设接口）四线全双工，由主机提供时钟；I²C（Inter-Integrated Circuit，集成电路互连总线）两线半双工，带地址和应答。两种总线各自用时间换引脚，代价不一样。

不用复数，不用微积分，上拉电阻那段只有乘除法。

## 一、为什么需要串行总线

并行总线（8/16 根数据线加若干控制线）速度快，可太费引脚。一颗 48 脚的 MCU 经不起这样的消耗。串行总线用少数几根线分时传数据，把「宽度」换成「时间」。

换的代价是协议复杂度：要时钟同步、要寻址、要应答。SPI 和 I²C 是两种不同的换法，SPI 用 4 根线换几十 MHz 的速度，I²C 只用 2 根线换一条线上挂一堆设备。

## 二、SPI：四根线与四种模式

四根线各干什么、数据在时钟的哪个瞬间有效、模式配错长什么样，这三件事说清楚，SPI 就通了。

### 四根线

| 线 | 方向 | 作用 |
| --- | --- | --- |
| SCK（Serial Clock） | 主 → 从 | 时钟，由主机产生 |
| MOSI（Master Out Slave In） | 主 → 从 | 主机发数据 |
| MISO（Master In Slave Out） | 从 → 主 | 从机回数据 |
| CS / NSS（Chip Select / Slave Select） | 主 → 从 | 片选，低电平选中某个从机（每个从机一根） |

全双工（full-duplex，两个方向同时传输）的意思是：主机在 MOSI 上发一位的同时，也在 MISO 上收一位。于是读操作也必须「发」，想读一个字节，就得先发一个字节来产生时钟，通常发 `0xFF` 这种无关值，称为 dummy 字节。

### 四种模式：CPOL 与 CPHA

时序由两个参数决定：

- CPOL（Clock Polarity，时钟极性）：时钟空闲时的电平，0 = 空闲为低，1 = 空闲为高；
- CPHA（Clock Phase，时钟相位）：在第几个边沿采样，0 = 第一个边沿，1 = 第二个边沿。

::: tip 例 1 · 配 SPI 时钟：别超器件上限
**题目**：F103 的 SPI1 挂在 APB2（PCLK2 = 72 MHz），SCK 由分频系数决定。分频该怎么选？

两边各卡着一个上限：外设自己的，和从机器件手册上的。算 SCK 不难，难的是取较小值。

步骤：

1. 列公式与可选分频：$\text{SCK} = f_{PCLK}/\text{分频}$，分频系数 $\in \{2,4,8,16,32,64,128,256\}$。

| 分频 | SCK | 是否可用 |
| --- | --- | --- |
| /2 | 36 MHz | ❌ 超过 F103 的 18 MHz 上限 |
| /4 | 18 MHz | ✅ 达到上限（最快） |
| /8 | 9 MHz | ✅ |
| /64 | 1.125 MHz | ✅ |

2. 核对两个上限：SPI 外设本身的上限（F103 是 18 MHz）与从机器件的上限（某款 SPI Flash 只支持 10 MHz、某款屏幕支持 20 MHz），取较小值。为什么取较小：任何一个超了都会出错，别只看 MCU 一侧。

回代验算：72/4 = 18 MHz，恰为外设上限且不超 18，可用 ✓；72/2 = 36 > 18，排除 ✓。

还有个易错点：SPI2/SPI3 挂在 APB1（36 MHz）而不是 APB2，同样的分频系数得到的 SCK 只有 SPI1 的一半。
:::

## 三、I²C：两根线、地址与应答

两根线为什么必须带上拉、一帧交互里地址和应答怎么排、手册上的地址和代码里写的为什么不一样，三个问题连在一起。

### 两根线与「线与」

I²C 只有 SCL（时钟）和 SDA（数据），两者都是开漏输出加上拉电阻（开漏，只能拉低、写 1 等于释放引脚）。由此有几条直接结论：

- 任何器件只能把线拉低，不能主动驱动为高；
- 只要有一个器件拉低，线就是低；所有器件都释放，线才被上拉变高。

这就是线与（wire-AND，多个开漏输出并在一起，等效于把它们的输出做逻辑与）。它带来三个好处：

- 天然支持多主机，谁拉低谁说话，冲突可以被检测；
- 不同电压的器件可以共存，上拉到各自电平，配电平转换；
- 从机可以通过拉低 SCL 来延长时钟（clock stretching，时钟延展，从机告诉主机「我还没准备好」的手段），主机检测到 SCL 被拉住就等着。

代价也来自同一个结构：上拉电阻和总线电容（bus capacitance $C_b$，所有器件引脚与 PCB 走线对地的寄生电容之和）构成一个 RC 充电回路，它限制了上升沿速度和最高通信速率。

### 时序与地址

一次「写寄存器」的完整时序如下，注意每 8 位之后都有一个第 9 位的应答：

```
START → 地址字节(写) → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP
```

- START（起始条件）：SCL 为高时，SDA 出现下降沿；
- STOP（停止条件）：SCL 为高时，SDA 出现上升沿；
- ACK（Acknowledge，应答）：每传完 8 位，接收方在第 9 个时钟把 SDA 拉低表示收到；没人拉低（读到高）就是 NACK，即「没收到」或「地址不存在」；
- 地址字节：7 位地址左移 1 位，最低位表示方向，0 = 写，1 = 读。地址有 7 位和 10 位两套编法，10 位模式要拿两个字节传地址，实际产品里少见。

::: tip 例 3 · 7 位地址和实际发出的字节不是一回事
**题目**：MPU6050 的手册写着「从机地址 `0x68`」，代码里该写什么？

看图上那个地址字节的框：线上走的是 8 位，手册给的是 7 位，两个数不是一回事，方向位补在最低位。

步骤：

1. 左移一位、补方向位：

$$\text{写} = \text{0x68} \ll 1 \;|\; 0 = \text{0xD0},\qquad \text{读} = \text{0x68} \ll 1 \;|\; 1 = \text{0xD1}$$

2. 推广到常见器件：

| 器件 | 7 位地址 | 写字节 | 读字节 |
| --- | --- | --- | --- |
| MPU6050 | `0x68` | `0xD0` | `0xD1` |
| SSD1306 OLED | `0x3C` | `0x78` | `0x79` |
| PCF8574 IO 扩展 | `0x27` | `0x4E` | `0x4F` |

回代验算：`0x68` = 0b1101000，左移一位 = 0b11010000 = 0xD0，加方向位 0 仍是 0xD0 ✓；0b1101000 | 1 = 0b11010001 = 0xD1 ✓。

这是最常见的困惑来源。手册给的是 7 位地址（不含方向位），而 HAL 的 `HAL_I2C_Master_Transmit(hi2c, DevAddress, ...)` 要求传的却是左移一位后的地址。用 HAL 时写成 `0x68` 会找不到器件，得写 `0xD0`，或者自己在调用前 `addr << 1`。

判断方法很简单：地址是偶数、且器件手册上的地址正好是它的一半，说明你传对了；两者相等，说明忘了左移。
:::

::: tip 例 4 · 上拉电阻取多大
**题目**：100 kHz 与 400 kHz 两种速率下，上拉电阻各取多少？

上拉电阻的上限由上升时间（rise time $t_r$，信号从低电平爬到高电平所花的时间）要求决定，I²C 规范要求 $t_r$ 不超过位周期的某个比例：

$$R_{p(max)} = \frac{t_r}{0.8473 \times C_b}$$

其中 $C_b$ 是总线总电容（器件引脚加 PCB 走线，一般估算 100~400 pF）。上下两个边界都要过：算完上限还要算下限。电阻太小、灌电流太大也不行，两边都合规才算数。

步骤：

| 模式 | 要求的 $t_r$ | 假设 $C_b$ = 200 pF | 计算 | 取值 |
| --- | --- | --- | --- | --- |
| 标准 100 kHz | 1000 ns | 200 pF | $1000/(0.8473 \times 200) = 5.90\ \text{k}\Omega$ | 4.7 kΩ |
| 快速 400 kHz | 300 ns | 200 pF | $300/(0.8473 \times 200) = 1.77\ \text{k}\Omega$ | 1.5 kΩ |
| 标准 100 kHz（长线 400 pF） | 1000 ns | 400 pF | $1000/(0.8473 \times 400) = 2.95\ \text{k}\Omega$ | 2.2 kΩ |

下限验算：电阻太小，器件拉低时需要吸收的电流过大（$I = V_{CC}/R_p$）。3.3 V、1 kΩ 时 $I = 3.3$ mA，尚在一般 ≥3 mA 的要求之内 ✓，再小就要超了。

实用取值可以直接抄：100 kHz、短距离用 4.7 kΩ，最常见；400 kHz 用 1.5~2.2 kΩ；多器件、长线先减小电阻，不行再降速率。

顺便算一下传输效率。100 kHz 下传一个字节需要 9 个位（8 数据 + 1 ACK）：

$$9 \times \frac{1}{100\ \text{kHz}} = 90\ \mu\text{s},\qquad \text{3 字节} = 270\ \mu\text{s}$$

400 kHz 下则是 22.5 µs/字节。I²C 传大量数据会很慢，这也是高速场合选 SPI 的原因。
:::

## 四、两者的对比与选型

| 维度 | SPI | I²C |
| --- | --- | --- |
| 线数 | 4 + 每从机 1 根 CS | 2（全部共享） |
| 速度 | 几 M ~ 几十 MHz | 100 kHz / 400 kHz / 1 MHz（高速模式 3.4 MHz） |
| 双工 | 全双工 | 半双工 |
| 寻址 | 无（靠 CS） | 7/10 位地址 |
| 应答 | 无 | 每字节 ACK |
| 多主机 | 不支持 | 支持（带仲裁 arbitration，多个主机同时开口时按「谁发的 0 谁赢」逐位裁决出唯一主机） |
| 距离 | 板内短距离 | 板内，可稍长 |
| 典型器件 | Flash、SD 卡、屏幕、高速 ADC | 传感器、EEPROM、RTC、IO 扩展 |

一句话的选型依据：要高速、点对点、大数据量（屏、Flash、高速 ADC）就上 SPI；引脚紧张、设备多、速度要求低（传感器、EEPROM、IO 扩展）就用 I²C。

## 五、工程实例

两种总线各有一个高频踩坑场景，都和「谁在什么时候松手」有关。

SPI 的片选管理：多个 SPI 从机时，CS 一般用普通 GPIO 软件控制，不走硬件 NSS。关键纪律是每次传输前拉低对应 CS，传完立刻拉高，而且 CS 有效期间不能被打断，否则从机会收到半个命令而状态错乱。多任务环境里还得给 SPI 总线加互斥。

I²C 死锁与恢复：主机在传输中途复位，或者从机拉住 SDA 不放，总线可能卡在 SDA 为低的状态，此后主机再也发不出 START。恢复办法是主机用 GPIO 模拟时钟，把 SCL 强行翻转 9 个周期，让从机释放 SDA，然后补发一个 STOP。很多产品的 I²C 驱动里都留着这段总线恢复代码。

## 六、易错清单 + 自检

按踩坑频率从高到低排：

1. SPI 主从模式（CPOL/CPHA）不一致 → 数据整体错位一位。
2. SPI 时钟超过器件或外设上限。
3. SPI2/3 挂在 APB1，同样分频下速度只有 SPI1 的一半。
4. 读操作忘了发 dummy 字节。SPI 全双工，不给时钟就收不到数据。
5. I²C 忘了接上拉电阻。开漏总线没有上拉，永远读不到高电平。
6. I²C 地址忘了左移一位，或者重复左移。
7. 没检查 ACK。地址错、器件没上电、总线被拉死时都会无 ACK，应检测并报错。
8. CS 在传输中途被释放，多任务下往往就是忘了加互斥。

自检：SPI 有哪四根线、CPOL 和 CPHA 各决定什么？I²C 的 7 位地址 0x68 在写操作时发出的字节是什么？100 kHz、200 pF 总线下上拉电阻取多大？

（答案：SCK/MOSI/MISO/CS；CPOL 决定时钟空闲电平、CPHA 决定第几个边沿采样；0xD0；约 4.7 kΩ）

# 13 · 舵机控制：从 PWM 脉宽到角度

<Meta time="45 min" level="核心" note="会算 CCR 只是及格线；舵机能不抖、不烧板，靠的是电源与地" />

这一章是 [07 · 定时器与 PWM](./timer-pwm.md) 的直接下游：07 章告诉你「PWM 是 CNT 与 CCR 比较出来的」，这一章告诉你**同一个外设怎么驱动一个真实的执行器**，以及为什么大量新手在「代码完全正确」的情况下把舵机调成抽风、把开发板调成复位。定时器时钟从哪来、为什么 APB1 上的定时器要 ×2，见 <Prereq id="clock-tree" />；`CCR`、`ARR` 这类寄存器「就是有地址的内存」，见 <Prereq id="register-map" />。

## 结论先行

1. **舵机要的不是占空比，是绝对脉宽**：固定 **50 Hz**（周期 20 ms），脉宽 **0.5–2.5 ms**，角度与脉宽**线性映射**——1.5 ms 是中位（0°），多 1 ms 转到 +90°，少 1 ms 转到 −90°。占空比只是 $t_{on}/T$ 的副产品，最低 2.5%、最高 12.5%，和「亮不亮」毫无关系。
2. **改频率 = 改角度**：脉宽不变、周期变了，角度其实不变；但绝大多数翻车现场是「按占空比写的代码」——`duty = 7.5%` 在 40 Hz 下算出来是 1.875 ms，角度直接偏 37.5°。**先锁频率，再算 CCR，最后才谈角度**。
3. **闭环在舵机里面，不在你这里**：舵机内部有电位器测量当前转角，与脉宽解码出的目标角比较，误差驱动直流电机直到落入**死区**。所以舵机不需要编码器、不需要 PID，你唯一要提供的是一个宽度准确的脉冲，外加**能扛住堵转电流的电源**。
4. **抖动九成来自供电与地**：舵机启动/堵转瞬间电流从几十 mA 跳到 1–2.5 A，若你的 5 V 来自开发板的 LDO 或一根细杜邦线，电压会瞬间跌到 4 V 以下，舵机内部逻辑复位、电机重新定位，看上去就是「抖」。**独立 5 V 供电 + 公共地 + 大电容**能解决绝大多数抖动，而不是去调代码。
5. **STM32 侧只需四行**：`HAL_TIM_PWM_Start` 启输出，`__HAL_TIM_SET_COMPARE` 写 CCR，上电先写 1500（中位）再启输出，其余交给硬件。多路用**同一个定时器的多个通道**（频率天然一致），或用 DMA 一次刷多个 CCR。

## 一、舵机里到底有什么

拆开一个 SG90，里面只有四样东西：**直流电机 + 减速齿轮组 + 电位器 + 一块小控制板**。

- **直流电机**转速高、扭矩小，经多级齿轮减速后输出到摇臂；
- **电位器**与输出轴同轴，输出电压与转角**成线性关系**——它就是「角度传感器」；
- **控制板**（常见是 8 位或 32 位小 MCU + H 桥驱动）做两件事：把输入脉冲的宽度解码成目标角，把电位器电压与目标角比较，得到误差；
- **H 桥**根据误差**正转或反转**电机，直到误差小于死区。

这就是一个**最朴素的位置随动系统**：被控量是角度，反馈来自电位器，控制器是「误差 → 驱动方向」的继电器式（bang-bang）策略。它不需要 PID 是因为齿轮组的阻尼与电机的反电动势已经提供了足够的阻尼，实际产品里顶多再做一个死区与「刹车」逻辑。

**「为什么不给电就不会保持」** 的答案是：舵机的保持力矩来自电机持续输出的小扭矩。控制板把误差控制在死区以内（典型 **5–10 µs 脉宽当量**，也就是 **0.5–1°**）时就让电机停转；一旦外力把轴推开、误差超出死区，控制板立刻再驱动一次。所以**脉宽必须连续不断地送**——脉冲停了，舵机就松手。这也是它与步进电机最根本的区别：舵机是**需要「hold」的主动系统**，步进电机则靠齿槽力矩被动保持。

**为什么不能像普通直流电机那样一直给电**：如果你用 MOSFET 或者 GPIO 直接把电机两端加 5 V，电流不经过限流，电机全力堵转，线圈在几秒内升到 100 °C 以上，绕组绝缘与齿轮塑料件都会受损。舵机的控制板之所以存在，一半是为了解码，另一半是为了**限流与方向控制**。

## 二、脉宽 ↔ 角度：把线性关系钉死

行业通用的映射（「标准舵机」）：

$$T_{pulse} = 1500\ \mu s + 10\ \mu s/\text{°} \times \theta,\qquad \theta \in [-90°,\ +90°]$$

反解：

$$\theta = \frac{T_{pulse} - 1500\ \mu s}{10\ \mu s/\text{°}}$$

| 脉宽 | 角度 | 占空比（50 Hz） |
| --- | --- | --- |
| 0.5 ms | −90° | 2.5% |
| 1.0 ms | −50° | 5.0% |
| **1.5 ms** | **0°（中位）** | **7.5%** |
| 2.0 ms | +50° | 10.0% |
| 2.5 ms | +90° | 12.5% |

三个必须记住的边界条件：

1. **两端不是硬限位**：多数 SG90/MG996R 机械行程约 180°，但实际可达角度因个体差异会有 ±5° 偏差。**程序里永远不要把脉宽写到 500 µs 以下或 2500 µs 以上**，更不要长期顶在端点上——堵转 + 持续电流是烧舵机的第一名原因。
2. **脉宽越界时舵机是「顶墙」不是「报错」**：控制板会一直驱动电机往那个方向推，直到机械限位阻止它，电流飙升。所以调试时先用 1500 µs 上电，再用 1000 µs / 2000 µs 试探，最后才放开到 ±90°。
3. **不同舵机型号的「全程脉宽」可能不同**：有些数字舵机支持 0.4–2.6 ms（即 ±100° 以上），有些只认 1.0–2.0 ms（±60°）。**以型号手册为准**，没有手册就用第三节的校准法自己测。

## 三、STM32 实现：PSC / ARR / CCR 一张表

舵机的需求是**先锁频率 50 Hz**，所以计算顺序与 07 章一样：先定 PSC 让计数频率好算 → 再定 ARR 得到 20 ms → 最后用 CCR 写脉宽。

$$
f_{cnt} = \frac{f_{TIM}}{PSC + 1},\qquad
ARR + 1 = \frac{f_{cnt}}{50\ \text{Hz}},\qquad
CCR = T_{pulse} \times f_{cnt}
$$

注意第三个式子里的 $f_{cnt}$ 单位是 Hz、$T_{pulse}$ 单位是秒；换算成「每个计数多少微秒」更好用：

$$CCR = \frac{T_{pulse}\ [\mu s]}{t_{cnt}\ [\mu s]},\qquad t_{cnt} = \frac{10^6}{f_{cnt}}$$

两种主流主频下的完整取值（均取 $t_{cnt}$ 为整数，避免浮点误差）：

| 主频 | PSC | $f_{cnt}$ | $t_{cnt}$ | ARR | CCR 中位 | CCR 下限 | CCR 上限 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **72 MHz**（F103，APB1 定时器 ×2 后） | **71** | 1 MHz | 1 µs | **19999** | **1500** | 500 | 2500 |
| **84 MHz**（F407，APB1 定时器 ×2 后） | **83** | 1 MHz | 1 µs | **19999** | **1500** | 500 | 2500 |

两行只差 PSC——这正是 <Prereq id="clock-tree" /> 里「定时器时钟是总线时钟的 2 倍」的直接后果：F103 的 APB1 是 36 MHz → 定时器 72 MHz → $PSC = 72/1 - 1 = 71$；F407 的 APB1 是 42 MHz → 定时器 84 MHz → $PSC = 84/1 - 1 = 83$。**如果只改芯片不改 PSC，频率会歪**（见例 1 的验算）。

再仔细看 ARR：12/16 位通用定时器的 ARR 上限是 **65535**，而 1 MHz 计数下 20 ms 只要 20000 个计数，**绰绰有余**。反过来说，如果贪图「直接用 84 MHz 计数」（PSC = 0），20 ms 需要 1680000 个计数，**根本装不下**——所以 PSC 不是可选项，是必须项。

想要更细的分辨率，可以把 $t_{cnt}$ 降到 0.5 µs（72 MHz 下 PSC = 35，84 MHz 下 PSC = 41），此时 ARR = 39999（仍在 16 位内），CCR 变成 1000 / 3000 / 5000。代价是精度提升只有一倍，收益远小于「把电源做好」，所以**默认建议 1 µs，够用**。

### HAL 代码：最小可用版

```c
/* ---- 初始化：CubeMX 生成的部分，这里只写关键参数 ---- */
hiTIM3.Instance           = TIM3;
hiTIM3.Init.Prescaler     = 71;        // 72 MHz → 1 MHz（84 MHz 主板改成 83）
hiTIM3.Init.CounterMode   = TIM_COUNTERMODE_UP;
hiTIM3.Init.Period        = 19999;     // ARR = 20000 - 1 → 50 Hz
hiTIM3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
HAL_TIM_PWM_Init(&hiTIM3);

sConfig.OCMode       = TIM_OCMODE_PWM1;
sConfig.OCPolarity   = TIM_OCPOLARITY_HIGH;   // 高有效：脉宽 = 高电平时间
sConfig.Pulse        = 1500;                  // 上电即中位，别让摇臂先撞一下
HAL_TIM_PWM_ConfigChannel(&hiTIM3, &sConfig, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&hiTIM3, TIM_CHANNEL_1);

/* ---- 对外接口：角度 → CCR ---- */
#define SERVO_CCR_MID   1500
#define SERVO_CCR_PER_DEG 10        /* 1 µs 计数下，10 µs/° */

/* 输入 ±90°，内部钳到 ±90° 防止机械限位堵转 */
void Servo_SetAngle(int8_t deg)
{
    int32_t ccr;
    if (deg >  90) deg =  90;
    if (deg < -90) deg = -90;
    ccr = SERVO_CCR_MID + (int32_t)deg * SERVO_CCR_PER_DEG;
    __HAL_TIM_SET_COMPARE(&hiTIM3, TIM_CHANNEL_1, (uint32_t)ccr);
}

/* ---- 平滑：别一步跳 90° ---- */
void Servo_Sweep(int8_t from, int8_t to, uint16_t step_ms)
{
    int8_t step = (to >= from) ? 1 : -1;
    for (int8_t a = from; a != to + step; a += step) {
        Servo_SetAngle(a);
        HAL_Delay(step_ms);          // 实际项目里换成定时器回调，别在主循环里 Delay
    }
}
```

几个要点：

- **`OCPolarity` 必须是 HIGH**，否则「脉宽」变成低电平的宽度，角度整反对；如果发现角度反了，优先查极性或 PWM 模式 1/2，而不是去改角度公式。
- **上电顺序**：`sConfig.Pulse = 1500` 写在启动之前，所以第一次输出就是中位。若先启动再写 CCR，会有一小段 0 脉宽的垃圾信号，有的舵机会猛撞到底。
- **`__HAL_TIM_SET_COMPARE` 只写 CCR，不产生更新事件**，可以在主循环、中断、甚至 DMA 回调里随时调用而不会打乱当前周期。
- `HAL_Delay` 只用于演示；正式代码里应把「每 20 ms 走 1°」放到定时器中断或 RTOS 任务里（见 [11 · FreeRTOS](./rtos.md)）。

### 中断 / DMA：多路方案怎么选

单个舵机独占一个定时器是浪费，多路舵机有四种做法：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **同定时器多通道** | TIM3_CH1/CH2/CH3/CH4 各接一个舵机，ARR 共用 | 零额外开销，四路完全同步，代码最短 | 频率被强制一致（对舵机恰好是要求），>4 路要换 32 位定时器 |
| **中断刷新 CCR** | 定时器配「每 20 ms 一次更新中断」，在 ISR 里更新一个通道的 CCR 并软件计数分配 | 一个定时器可驱动任意多路 | ISR 每条都要几十个周期，路数多时 CPU 占用上升 |
| **DMA 刷新 CCR** | 把「周期内依次翻转的时间和通道」预计算成数组，DMA 循环送进 CCR | CPU 零占用，适合 16 路以上 | 需要预计算与一块 RAM，调试时数组越界很难查 |
| **专用舵机驱动芯片** | PCA9685（I²C，16 路，内部自己产生 50 Hz） | 只占一根 I²C，路数扩展最容易，频率精度由芯片晶振决定 | 多一个器件、I²C 要配好（见 [09 章](./spi-i2c.md)） |

**实际选择**：≤4 路用同定时器多通道；5–8 路且路数固定用 DMA 法；>8 路或者要频繁改动目标位置，直接用 PCA9685——它本质上就是「把 STM32 要做的事硬编码进了专用芯片」，也符合嵌入式的一条经验：**能用专用外设解决的通用问题，不要用 CPU 解决**。

## 四、电源与接线：抖动与烧板的真正原因

### 电流账

| 舵机 | 空载电流 | 堵转电流 | 工作电压 | 扭矩（近似） |
| --- | --- | --- | --- | --- |
| **SG90**（9 g 塑料齿） | 约 100–220 mA | **约 650 mA**（4.8 V） | 4.8–6 V | 1.8 kg·cm（4.8 V） |
| **MG996R**（55 g 金属齿） | 约 100 mA | **约 2.5 A**（6 V，部分批次手册标 1.4 A） | 4.8–7.2 V | 9.4 kg·cm（4.8 V） |

**开发板上的 3.3 V / 5 V 引脚通常是 LDO 出来的，额定只有几百 mA**。把 SG90 直接插上去，控制器还没进主循环，堵转瞬间就把 LDO 拉进限流，输出电压掉到 3 V 以下 → STM32 复位、舵机控制板重启（表现为「舵机先猛跳一下再抖」）。**MG996R 更不用说，2.5 A 超过绝大多数开发板 LDO 的 10 倍。**

正确接法：

```
外部 5V 电源（≥3 A，MG996R 建议 5 A）─┬── 舵机 VCC
                                      ├── 470 µF 电解 + 0.1 µF 陶瓷（并联，靠近舵机）
                                      └── 地 ─┬── 舵机 GND
                                              └── STM32 的 GND（务必连上！）

STM32 的 PWM 引脚 ──────────────── 舵机信号线（不串电阻，长度尽量短）
```

**共地是硬性要求**：舵机控制板解码脉宽是「以自身 GND 为参考」比较阈值的。如果 STM32 的地和舵机的地由两个电源分别供给而**没有连在一起**，两者的地电位差可能有几百 mV 到几 V，脉宽判断就会错位——表现为「角度不准、偶发乱跳、串口一开就抖」。**所有 GND 必须连到同一点**（星形接地，动力地与信号地在电源出口处汇合）。去耦电容里的电解负责吸收 ms 级的大电流冲击、陶瓷负责 µs 级的高频尖峰，两者并联、**尽量靠近舵机本体**，而不是放在 STM32 旁边。

### 信号电平兼容性

STM32 的 IO 是 **3.3 V** 推挽输出，而舵机通常按 **5 V** 供电。这是最常见的一个疑问：

- SG90 / MG996R 内部控制板**实际工作在 3.3 V 逻辑**（各自带 LDO），输入高电平阈值通常只有 **2.0 V 左右（TTL 兼容）**，所以 **3.3 V 直接驱动完全可行**，这也是几乎所有 STM32 舵机教程的做法。
- 如果遇到某个舵机手册明确写 **$V_{IH} \ge 0.7 \times V_{DD}$**（纯 CMOS 输入，5 V 下需要 3.5 V），3.3 V 就**不够**，表现为「不动或随机动」。这时可以：① 用 74HCT 系列门电路做电平转换（TTL 输入，3.3 V 就能识别）；② 在 IO 与舵机信号线之间**加 1 kΩ 上拉到 5 V**（仅当舵机信号引脚容忍 3.3 V 输入、且你能确认灌电流不超标时）；③ 用专用电平转换芯片。
- **不要给 STM32 引脚接 5 V 上拉再去推舵机**，除非确认该引脚是 5 V 容忍（FT 引脚）且上拉电流可控——普通 IO 上挂 5 V 上拉会反灌电流。

### 常见烧板原因

1. **用开发板的 5 V 引脚给 MG996R 供电**：LDO 立即过流，运气好只是复位，运气差 LDO 或走线烧断。
2. **舵机电源与主控共地没连、但连了信号线**：信号线成了唯一的电流回路，几 mA 到几十 mA 从 IO 灌进去，**直接烧 IO 或 MCU**。
3. **把舵信号线接到了 5 V / 3.3 V 电源脚**：舵机控制板输入端没保护，上电即烧。
4. **舵机堵转时间过长**：程序让舵机顶在 ±90° 之外（如写 3000），电机持续堵转，电流 2.5 A 持续几秒，控制板 H 桥烧毁。
5. **热插拔**：上电状态下插拔舵机，插头相邻脚可能瞬时短路到信号脚。
6. **电池反接**。

## 五、例题

::: tip 例 1 · PSC / ARR 计算：72 MHz 与 84 MHz 两张表 {#ex-servo-1}
**题干**：用通用定时器输出 50 Hz 舵机信号，分别求 STM32F103（APB1 定时器时钟 72 MHz）与 STM32F407（APB1 定时器时钟 84 MHz）下的 PSC 与 ARR。

**第 1 步：定 PSC，让计数频率成为好算的整数**

统一取 $f_{cnt} = 1\ \text{MHz}$，即每微秒计一个数：

$$PSC = \frac{f_{TIM}}{f_{cnt}} - 1 \Rightarrow \begin{cases} 72\ \text{MHz}: & 72 - 1 = \mathbf{71} \\ 84\ \text{MHz}: & 84 - 1 = \mathbf{83} \end{cases}$$

**第 2 步：定 ARR，得到 20 ms**

$$ARR + 1 = \frac{1\ \text{MHz}}{50\ \text{Hz}} = 20000 \Rightarrow ARR = \mathbf{19999}\ (\text{两者相同})$$

**第 3 步：核对能不能装下**

1 MHz 下一次计数 1 µs，20 ms 共 20000 个计数，远小于 16 位 ARR 上限 65535 ✓。反例：若贪心取 PSC = 0（84 MHz 直数），20 ms 需要 $84 \times 10^6 \times 0.02 = 1\,680\,000$ 个计数，**超出 65535 的 25 倍**，装不下。

**第 4 步：核对「只改芯片不改 PSC」的后果**

| 配置 | 实际 $f_{cnt}$ | 实际 $f_{PWM}$ | 实际周期 |
| --- | --- | --- | --- |
| 72 MHz 主板误用 PSC = 83 | 857143 Hz | **42.857 Hz** | 23.33 ms |
| 84 MHz 主板误用 PSC = 71 | 1166667 Hz | **58.333 Hz** | 17.14 ms |

node 验算：`72e6/84 = 857142.857`，`857142.857/20000 = 42.857 Hz`；`84e6/72 = 1166666.667`，`/20000 = 58.333 Hz`。频率偏了 ±17%，虽然多数舵机对频率有容忍（典型 40–333 Hz），但这个误差会直接放大到「同样 CCR 下角度不一样」。

> **为什么这么想**
> 舵机的容差很大，但**代码里的常数容差为零**。把 PSC 和主频绑成一个宏（或在 CubeMX 里由图形配置计算），比在两个工程里各写一份常数安全得多。这也是为什么 07 章反复强调「先定频率、再定 ARR」：顺序错了，后面所有数字都是错的。
:::

::: tip 例 2 · 脉宽 ↔ 角度映射（正向与反向） {#ex-servo-2}
**题干**：某舵机按 $T = 1500 + 10\theta$（µs）标定。① 求 −50°、0°、+50° 的脉宽与 CCR（1 µs 计数）；② 若用 0.5 µs 计数（PSC = 35 或 41），CCR 变成多少？③ 若程序误按「占空比 7.5%」写，而周期被配成 25 ms，实际角度是多少？

**第 1 步：正算脉宽与 CCR**

$$\begin{aligned} \theta = -50° &: T = 1500 - 500 = 1000\ \mu s,\ CCR = 1000 \\ \theta = 0° &: T = 1500\ \mu s,\ CCR = 1500 \\ \theta = +50° &: T = 1500 + 500 = 2000\ \mu s,\ CCR = 2000 \end{aligned}$$

占空比分别为 $1000/20000 = 5.00\%$、$7.50\%$、$10.00\%$。

**第 2 步：换计数分辨率**（$t_{cnt} = 0.5\ \mu s$）

$$CCR = \frac{T[\mu s]}{0.5} \Rightarrow 2000 / 3000 / 4000$$

角度不变、脉宽不变，只有 CCR 数字变了——**CCR 不是角度，它只是脉宽的计数表示**。

**第 3 步：占空比陷阱**

程序写 `duty = 7.5%`，周期 25 ms：

$$T = 0.075 \times 25000\ \mu s = 1875\ \mu s \Rightarrow \theta = \frac{1875 - 1500}{10} = \mathbf{+37.5°}$$

本该是中位 0°，实际偏了 37.5°。node 验算：`0.075*25000 = 1875`，`(1875-1500)/10 = 37.5` ✓。

> **为什么这么想**
> 占空比是「相对量」，脉宽是「绝对量」。舵机只认脉宽，所以任何把参数存成占空比、百分数或「0–100 的等级」的代码，都会在你改频率的那一天悄悄失效。**接口函数的参数单位永远写成角度（或微秒），内部再乘系数**，而不是让调用方传百分比。
:::

::: tip 例 3 · 分辨率与死区：几微秒才换来 1° {#ex-servo-3}
**题干**：① 1 µs 计数下，一个 CCR 步进对应多少度？要分辨 0.1° 需要多高的计数频率？② 死区 5 µs 对应多少度？③ 1 µs 计数时，12 位 ARR 能产生的最低 PWM 频率是多少？

**第 1 步：角度分辨率**

全程 2000 µs 对应 180°，所以

$$\Delta\theta = \frac{180°}{2000\ \mu s} = 0.09°/\mu s$$

1 µs 计数 → 步进 **0.09°**，约 2000 级，肉眼完全看不出台阶。

**第 2 步：要 0.1° 需要多快**

$$t_{cnt} = \frac{0.1°}{0.09°/\mu s} = 1.111\ \mu s \Rightarrow f_{cnt} \ge \frac{1}{1.111\ \mu s} = 0.9\ \text{MHz}$$

也就是说 1 MHz 已经**满足甚至超出** 0.1° 的需求。把计数频率提到 2 MHz、10 MHz 对舵机毫无意义——**瓶颈根本不在定时器分辨率**。

**第 3 步：死区换算**

死区 5 µs → $5 \times 0.09° = \mathbf{0.45°}$；10 µs → 0.90°；20 µs → 1.80°。这就是舵机「静态误差」的来源：控制板内部的比较窗口有多大，静止时就可能偏多少。**你永远调不出比死区更准的手感**，只能靠外部编码器或视觉反馈做二次校正。

**第 4 步：12 位 ARR 的频率下限**

$$f_{min} = \frac{1\ \text{MHz}}{2^{16}} = 15.26\ \text{Hz}$$

50 Hz 只需 20000 个计数，**远远安全**。node 验算：`1e6/65536 = 15.259 Hz`。

> **为什么这么想**
> 很多教程花大量篇幅讲「怎么把分辨率从 1 µs 提到 0.5 µs」，但它改善的只是 0.09° 的台阶，而舵机的机械回差、齿隙、死区都在 0.5° 量级。**决定精度的永远是器件本身，不是寄存器**。同理，电源质量决定了抖动幅度，代码参数只能决定目标位置能不能被准确送达。
:::

::: tip 例 4 · 堵转电流与电源选型 {#ex-servo-4}
**题干**：四个 MG996R 装在机械臂上，$V = 6\ \text{V}$，堵转电流 2.5 A/台，空载 0.1 A/台。① 四台同时堵转多大电流？② 若用 0.5 Ω 回路的杜邦线供电，堵转时线损多少？③ 电源至少选多大？④ 470 µF 电容能在 1 A 阶跃下撑多久（允许压降 0.1 V）？

**第 1 步：峰值电流**

$$I_{peak} = 4 \times 2.5 = \mathbf{10\ A}$$

**第 2 步：线损**

$$V_{drop} = I \times R = 10 \times 0.5 = \mathbf{5\ V}$$

5 V 的压降意味着供电从 6 V 掉到 1 V——舵机控制板直接复位，STM32 也会跟着掉电。这条算式是「一给舵机供电，全部复位」现象最直接的定量解释。

**第 3 步：电源容量**

工程上按「最坏情况 × 1.5」选：

$$I_{supply} \ge 10 \times 1.5 = \mathbf{15\ A}$$

实际布置时，机械臂不会四轴同时堵转，所以常见做法是选 **5 V / 10 A 以上的开关电源**，并把线径从杜邦线换成 18 AWG 以上（0.02 Ω 级），把 0.5 Ω 的线损压到 0.2 V 以内。采用「20% 时间堵转、80% 空载」的占空比估算平均电流：

$$I_{avg} = 4 \times (0.2 \times 2.5 + 0.8 \times 0.1) = 4 \times 0.58 = \mathbf{2.32\ A}$$

平均只有 2.3 A，但电源必须按**峰值 10 A** 选——**平均电流决定发热，峰值电流决定电源能不能扛住**。

**第 4 步：电容能撑多久**

$$C \cdot \frac{\Delta V}{\Delta t} = \Delta I \Rightarrow \Delta t = \frac{C\ \Delta V}{\Delta I} = \frac{470\ \mu F \times 0.1\ V}{1\ A} = 47\ \mu s$$

470 µF 只能撑 47 µs——它**不是用来顶住堵转的**，而是给电源的反馈环路争取响应时间（典型几十到几百 µs）。想靠电容解决 ms 级的堵转是不现实的：要在 5 ms 内把 1 A 压降控制在 0.1 V，需要 $C = I\Delta t/\Delta V = 1 \times 0.005 / 0.1 = 50\ \text{mF} = 50000\ \mu F$。**结论：大电容是补充，不是替代，电源的额定电流才是根本。**

> **为什么这么想**
> 题目的每一问都在纠正一个典型直觉错误：以为「加个电容就好了」。电容的储能是 $\frac{1}{2}CV^2$，470 µF 在 6 V 下只有 8.5 mJ，而 MG996R 堵转 2.5 A×6 V 时每毫秒就要 15 mJ——**连 1 ms 都撑不住**。电容真正的作用是抑制高频尖峰与开关噪声，稳态大电流只能靠电源和线径。
:::

## 六、工程实例

**云台（两轴舵机云台）**：两个舵机一个管俯仰、一个管水平。要点有三：① **两个舵机必须共地且各自有足够电流余量**，云台转动时负载力矩会变化，堵转风险比单舵机大；② 机械上要让云台的**重心落在舵机轴的附近**，负载力矩越小，同样的堵转电流余量越宽裕；③ 软件上要做**限幅 + 软启动**（从上电位置以固定速度走到目标），直接跳到目标会让云台「甩镜头」，画面里全是运动模糊。

**机械臂（多自由度）**：3–6 个 MG996R 串联。典型问题是**远端舵机的电源线共用了近端的细线**，导致远端舵机动作时近端也跟着抖。正解是**星形电源布线**——每个舵机从电源出口单独拉一组线（或用粗母线 + 在每级并联去耦），而不是串联「接力」。另外要做**电流预算**：六轴同时启动的峰值是 $6 \times 2.5 = 15\ \text{A}$，必须按这个数选电源，或者软件上错开启动时间（每次只让一个舵机动作）。

**舵机测试仪 / 校准台**：一个电位器 + 一个 STM32 最小系统就能做——ADC 读电位器（见 [10 · ADC 与 DMA](./adc-dma.md)），映射到脉宽，直接输出给舵机，这样一边转电位器一边看舵机转。它的价值在于**测量每个舵机的真实 min/max 脉宽**：

```
校准流程：
1. 电位器上调出一个脉宽值 p，从 1000 µs 开始每次 +10 µs，直到舵机刚好处在机械左端点
2. 记录 p_min（此时再小的脉宽只会让舵机"顶墙"，电流飙升但不动）
3. 同理从中间往上加，找到 p_max
4. 把 p_min / p_max 作为该舵机的限幅写进 Flash，程序里所有目标角度都映射到 [p_min, p_max]
```

典型的 SG90 实测值是 p_min ≈ 520–560 µs、p_max ≈ 2440–2480 µs，两端不对称——**每台都不一样，这就是为什么「照抄教程写 500/2500」会出现个别舵机到了极限角度还在响的原因**：它在顶墙。

**抖动排查清单**（按概率排序）：

1. **供电**：换独立 5 V 电源，确认够电流（先量一下舵机供电脚上的电压，动作瞬间跌了多少）；
2. **共地**：STM32 的 GND 与舵机电源 GND 用同一根粗线连到电源出口；
3. **去耦**：舵机端并联 470 µF + 0.1 µF，尽量靠近舵机；
4. **线径与长度**：杜邦线换成 22 AWG 以下规格，长度 < 20 cm；
5. **信号线串扰**：信号线远离电机电源线，别和 PWM 大电流回路并行；
6. **脉宽是否连续**：`HAL_TIM_PWM_Stop` 之后舵机就会松手，检查是否在中途停了输出；
7. **是否在顶墙**：把 ±90° 临时改成 ±80° 看是否还抖，抖消失了就是限幅问题；
8. **机械负载**：齿轮有背隙、摇臂与支架干涉，也会表现为「抖动」；
9. **频率飘移**：用示波器或逻辑分析仪量一下真实周期是不是 20 ms；
10. **舵机本身**：廉价舵机的电位器接触噪声大，换个舵机对比一下就能排除。

## 七、易错清单

- [ ] **按占空比而不是脉宽写代码**——改频率时角度会静默漂移（例 2 第 3 步）
- [ ] **PSC 按主频硬编码**——72 MHz 与 84 MHz 的 PSC 不同（例 1）
- [ ] **上电不先写中位**——初始化瞬间输出 0 脉宽，摇臂猛撞端点
- [ ] **脉宽写到 500 µs 以下 / 2500 µs 以上**——舵机顶墙堵转，电流飙升
- [ ] **把舵机接开发板的 5 V 引脚**——LDO 过流，轻则复位重则烧板
- [ ] **忘记共地**——角度不准、偶发乱跳，严重时信号线灌电流烧 IO
- [ ] **用「加电容」代替正常的电源容量**——470 µF 只撑 47 µs（例 4）
- [ ] **`OCPolarity` 配反**——脉宽变成低电平宽度，角度整体反转
- [ ] **写完 CCR 立刻读角度**——舵机有 0.1–0.2 s/60° 的转速限制，读到的还是旧值
- [ ] **非 16 位的定时器（如 TIM2 是 32 位）与 16 位混用没检查接线**——部分型号定时器位宽不同，ARR 上限不一样
- [ ] **热插拔舵机**——上电状态插拔可能让电源脚与信号脚瞬时短路

## 八、考点速记

- **三个常数**：50 Hz、0.5–2.5 ms、1.5 ms = 中位；**1 ms ↔ 10 µs ↔ 1°**。
- **三个公式**：$PSC = f_{TIM}/f_{cnt} - 1$；$ARR = f_{cnt}/50 - 1$；$CCR = T_{pulse} \times f_{cnt}$。
- **两张参数表**：72 MHz → PSC = 71、ARR = 19999、CCR 500/1500/2500；84 MHz → PSC = 83，其余相同。
- **一句话原理**：电位器测角度 → 与脉宽解码出的目标角比较 → 误差驱动电机 → 落入死区停止。
- **一句话排障**：舵机抖先查电源与地，角度不准先查频率与限幅，完全不动先查极性与电平。
- **一个数量感**：SG90 堵转 0.65 A，MG996R 堵转 2.5 A，开发板 LDO 通常 0.5 A——**差一个数量级**。

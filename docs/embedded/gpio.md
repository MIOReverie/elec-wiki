# 05 · GPIO 与按键

<Meta time="35 min" level="核心" note="最基础的引脚：八种模式怎么选、上下拉为什么必须有、按键为什么要消抖" />

## 结论先行

1. **GPIO 有八种工作模式**：输入（浮空 / 上拉 / 下拉 / 模拟）、输出（推挽 / 开漏）、复用（推挽 / 开漏）。**模式选错，引脚就完全不按预期工作**。
2. **推挽能主动输出高低电平；开漏只能拉低，输出「高」其实是释放引脚**，必须外部上拉才有高电平——这是 I²C 总线的物理基础。
3. **输入引脚绝不允许悬空**：浮空输入 + 外部悬空 = 电平随机跳变。按键、拨码开关这类「可能断开」的输入必须配上拉或下拉。
4. **机械按键会抖动（5~20 ms），必须消抖**，否则一次按下会被读成好几次。
5. **IO 驱动能力有限**（单脚约 20 mA 量级），驱动继电器、电机、大功率 LED 必须用三极管或 MOS 管。

## 一、八种模式

STM32F1 用 `CRL`（管 Pin0~7）/ `CRH`（管 Pin8~15）里的 4 位配置每根引脚：2 位 `MODE`（方向+速度） + 2 位 `CNF`（具体模式）。组合出八种：

| 大类 | 模式 | 特点 | 典型用途 |
| --- | --- | --- | --- |
| **输入** | 浮空输入 | 不接上下拉，完全由外部决定 | 外部已有确定驱动的信号（如另一芯片的输出） |
| | 上拉输入 | 内部电阻拉到 VCC，默认 1 | **按键（按下接地）**、开漏总线的输入 |
| | 下拉输入 | 内部电阻拉到 GND，默认 0 | 高电平有效的按键 |
| | 模拟输入 | 断开数字输入缓冲，直连 ADC | ADC 采样、比较器输入 |
| **输出** | 推挽输出 | P 管拉高、N 管拉低，都能主动驱动 | 驱动 LED、控制普通数字器件 |
| | 开漏输出 | 只能拉低，写 1 = 释放 | I²C 总线、电平转换、线与 |
| **复用** | 复用推挽 | 由片上外设驱动（推挽） | UART 的 TX、SPI 的 MOSI/SCK、TIM 的 PWM |
| | 复用开漏 | 由片上外设驱动（开漏） | I²C 的 SDA/SCL |

> F4 及以后把这 4 位拆成了几个独立寄存器，更好理解：`MODER`（输入/输出/复用/模拟）+ `OTYPER`（推挽/开漏）+ `OSPEEDR`（速度）+ `PUPDR`（无/上拉/下拉）。**方向和上下拉变成正交的两个维度**，可以任意组合。

## 二、推挽 vs 开漏（最容易混淆的一对）

**推挽**：内部上下两个 MOS 管，一个负责拉到 VCC，一个负责拉到 GND。写 1 就真的输出高电平，写 0 就真的输出低电平，**两端都能主动驱动**。

**开漏**：只有下面那个 N 管（漏极开路，所以叫开漏）。

- 写 **0** → N 管导通 → 引脚被**主动拉低**；
- 写 **1** → N 管关断 → 引脚**悬空（高阻）**，电平由外部电路决定。

::: tip 例 1 · 按键电路的上拉电阻怎么取
按键一端接 MCU 引脚、另一端接地，引脚配置成**上拉输入**：按键松开时内部上拉把引脚拉成 1，按下时被外部短路到地读到 0。

若用外部上拉电阻，典型取 **4.7 kΩ ~ 10 kΩ**。以 3.3 V 供电计算按下时的电流：

$$R = 4.7\ \text{k}\Omega:\quad I = \frac{3.3}{4700} \approx 0.70\ \text{mA}$$
$$R = 10\ \text{k}\Omega:\quad I = \frac{3.3}{10000} \approx 0.33\ \text{mA}$$

**为什么不取更小**：电阻越小，按键按下时白白流过的电流越大（1 kΩ 就有 3.3 mA），电池供电的产品会因此缩短续航。
**为什么不取更大**：电阻越大，引脚越容易受空间耦合的干扰（引脚输入阻抗很高，微弱电流就能改变电平），50 kΩ 以上就明显不可靠了。4.7 k~10 k 是功耗与抗干扰的平衡点。

**优先用内部上拉**（`GPIO_PULLUP`）：省一个元件，且阻值由芯片保证（通常 30~50 kΩ，略大但够用）。
:::

## 三、按键为什么要消抖

机械按键在闭合/断开的瞬间，金属触点会**弹跳**数次才稳定，持续时间通常 **5~20 ms**。对运行在 MHz 级别的 MCU 来说，这段时间足够读成几十次「按下—松开」。

**硬件消抖**：在按键两端并联一个 100 nF 电容（配合上拉电阻构成 RC 滤波），把抖动的毛刺滤平。代价是每个按键多一个电容。

**软件消抖**（更常用）：读到电平变化后，**延时 10~20 ms 再读一次**，若仍保持才认为有效。但不要用死等延时（`HAL_Delay` 会阻塞整个 CPU），正确做法是**用定时器定时扫描**（如每 5~10 ms 扫一次按键），配合状态机：

```c
// 每 10 ms 由定时器中断调用一次
void Key_Scan(void) {
  static uint8_t last = 1;
  uint8_t now = HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin);
  if (now == 0 && last == 1) key_pressed = 1;   // 只在「从松开变按下」时触发一次
  last = now;
}
```

::: tip 例 2 · 消抖时间取多少
按键抖动一般 **5~20 ms**，所以消抖延时应**大于最大抖动时间**，取 **10~20 ms**。

- 取 5 ms：可能仍在抖动窗口内，偶尔会误触发两次；
- 取 20 ms：可靠，但按键响应变慢（人手能察觉的下限约 50~100 ms，20 ms 无感）；
- **定时扫描周期**取 10 ms 即可：既能滤掉抖动，又保证响应及时。

**注意「响应变慢」和「误触发」的权衡**：对音量加减这类需要长按连续触发的功能，还要加「首次触发后延时 500 ms 再进入连发」的逻辑。
:::

## 四、输出速度（翻转速率）是什么

配置 GPIO 时有个「输出速度」选项（F1 是 2/10/50 MHz，F4 是 Low/Medium/High/Very High）。它**不是输出频率的上限**，而是**驱动管翻转的快慢（压摆率）**。

- **选太高**：边沿陡峭 → 高频分量多 → EMI 辐射大，还可能引起信号过冲和串扰；
- **选太低**：边沿缓慢 → 高速通信（如 SPI 几十 MHz）时波形变形，接收端采样错误。

**经验**：点个 LED 选最低速；跑 UART 选低速或中速；跑 SPI 高速通信才选中/高速。原则是**够用即可**。

## 五、驱动能力：什么时候必须加三极管

STM32 单个 IO 的吸收/灌入电流一般限制在 **20~25 mA**，整片总电流也有上限（F103 约 150 mA）。几种典型负载：

| 负载 | 能否直接驱动 | 说明 |
| --- | --- | --- |
| 普通指示 LED（5~10 mA） | ✅ 可以 | 必须串限流电阻 |
| 蜂鸣器（有源，20 mA 以内） | ✅ 勉强 | 建议仍用三极管 |
| 继电器线圈（70 mA 以上） | ❌ 不行 | 必须用三极管/MOS |
| 直流电机 | ❌ 不行 | 用 MOS 管或专用驱动芯片 |
| 大功率 LED / 灯带 | ❌ 不行 | 用 MOS 管 |

::: tip 例 3 · 为什么开漏输出时 LED 不亮
有人把 LED（串电阻接 VCC，低电平点亮）接到配置成**开漏输出**的引脚上，写 1 期待 LED 灭、写 0 期待亮，结果**写 1 时 LED 也亮了或者状态诡异**。

原因是开漏写 1 = **释放引脚**，引脚变成高阻。此时：

- 若外部有上拉电阻（或 LED+电阻接到 VCC 构成的通路），引脚被拉成高电平 → LED 两端无压差 → 灭；
- 若**什么都没接**，引脚悬空，电平不确定，LED 的状态也就不确定。

**排查规则**：用开漏输出时，先问一句「我的上拉电阻在哪里？」。没有上拉的开漏输出，永远得不到确定的高电平。这也是 I²C 总线必须接上拉电阻的原因（见 [09 · SPI 与 I²C](./spi-i2c.md)）。
:::

::: tip 例 4 · 用三极管驱动继电器，算基极电阻
继电器线圈 5 V、吸合电流 70 mA，用 NPN 三极管（如 S8050，取 $h_{FE} \approx 100$）做低边开关，MCU 用 3.3 V IO 控制。

**第一步：算需要的基极电流**（要让三极管饱和，工程上取理论值的 2~5 倍）：

$$I_{B(min)} = \frac{I_C}{h_{FE}} = \frac{70}{100} = 0.7\ \text{mA},\qquad \text{取 3 倍} \approx 2.6\ \text{mA}$$

**第二步：算基极电阻**（$V_{BE} \approx 0.7$ V）：

$$R_B = \frac{3.3 - 0.7}{2.6\ \text{mA}} \approx 1000\ \Omega \quad \text{取标称 1 k}\Omega$$

**验算**：$R_B = 1\ \text{k}\Omega$ 时 $I_B = (3.3-0.7)/1000 = 2.6$ mA，可驱动的集电极电流达 $2.6 \times 100 = 260$ mA，远大于继电器所需的 70 mA → 三极管充分饱和。

**两个不能漏的元件**：

1. **续流二极管**（反向并联在线圈两端）：继电器是电感，关断瞬间会产生很高的反向电动势，没有续流二极管会直接击穿三极管。
2. **基极下拉电阻**（如 10 kΩ 到地）：保证 MCU 复位期间（IO 高阻）三极管不会误导通。
:::

## 六、复用功能与重映射

当引脚用作 UART、SPI、TIM 等外设功能时，必须配成**复用模式**，并且要**开启 AFIO 时钟**（F1 上重映射还需要操作 `AFIO->MAPR`）：

```c
__HAL_RCC_AFIO_CLK_ENABLE();          // F1 上复用/重映射必须先开 AFIO 时钟
// 然后把引脚配成 GPIO_Mode_AF_PP（复用推挽）
```

**忘了配复用是最常见的「外设没信号」原因**：定时器在跑、代码也在执行，但引脚仍然是普通 GPIO，所以示波器上什么都看不到。

## 七、工程实例

**矩阵键盘**：4×4 键盘只需要 8 根引脚（4 行 + 4 列），而不是 16 根。扫描方法是：把 4 行依次设为推挽输出低电平、其余高电平，同时读 4 列（配成上拉输入）；若某列读到 0，说明该行该列的按键被按下。用定时中断每 10 ms 扫一遍，顺便完成消抖。

**电平转换**：3.3 V 的 MCU 要控制 5 V 器件时，把引脚配成**开漏输出 + 外部上拉到 5 V** 即可——输出 0 时拉低，输出 1 时由上拉电阻拉到 5 V。注意只有标注 **FT**（5 V 容忍）的引脚才能这样用，否则会损坏芯片。

## 八、易错清单 + 自检

- [ ] **输入引脚悬空**：浮空输入 + 外部没接 = 读到随机值，必须配上拉或下拉
- [ ] **开漏输出没接上拉**：写 1 得不到高电平
- [ ] **把「输出速度」当成输出频率上限**：它其实是压摆率，选高了 EMI 大
- [ ] **用 IO 直接驱动继电器/电机**：超过 20 mA 会烧引脚，必须加驱动管
- [ ] **驱动感性负载忘了续流二极管**：关断时的反向电动势会击穿三极管
- [ ] **用外设却忘了配复用模式**（以及 F1 上忘了开 AFIO 时钟）
- [ ] **按键没消抖**：一次按下触发多次
- [ ] **用 `HAL_Delay` 做消抖**：会阻塞整个程序，改用定时扫描

**自检**：要让一个按键「按下接地、松开为高」，引脚该配成什么模式？按键抖动一般持续多久？开漏输出要得到高电平必须加什么？（答案：上拉输入（或外部上拉 + 浮空输入）；5~20 ms；上拉电阻）

# 建立时间与保持时间

<Meta time="4 min" level="卡片" note="保持时间违例不能靠降频解决，只能改设计" />

**触发器在时钟有效沿前后各需要一段数据稳定的时间（建立时间与保持时间），时钟周期必须容得下「建立 + 输出延迟 + 保持」这一整段。**

## 记住这几条

- 触发器在**时钟有效沿**采样输入。要采得准，输入必须在沿前后各留出一段「稳定时间」：
  - **建立时间 $t_{su}$**：时钟沿之前，数据必须已经稳定的最短时间；
  - **保持时间 $t_h$**：时钟沿之后，数据必须继续稳定的最短时间。
- 时钟周期必须满足 $T_{clk} > t_{su} + t_{CC} + t_h$，其中 $t_{CC}$ 是**时钟到输出延迟**（时钟沿到 Q 端翻转的时间）。
- **保持时间违例最危险**：它不能靠降频解决，只能靠设计（换器件、调整数据路径、加一级锁存）。
- 触发器进入**亚稳态**时，输出可能在阈值附近停留任意长的时间，随后随机落到 0 或 1——这就是数字设计里「偶发、不可复现」的一类故障。

**为什么它承重**：现代数字系统的主频瓶颈往往不是逻辑深度，而是**建立/保持时间余量**。不懂这一条，配再快的时钟也只会得到一片随机数据。

## 典型数值

| 器件 | $t_{su}$ | $t_h$ | $t_{CC}$ |
| --- | --- | --- | --- |
| 74HC74（D 触发器，5 V） | 约 5 ns | 约 0 ns | 约 14 ns |
| 74LS74 | 约 20 ns | 约 0 ns | 约 25 ns |
| 现代 FPGA 触发器 | 0.1 ~ 1 ns | 0 ~ 0.5 ns | 0.2 ~ 2 ns |

- 由 $T_{clk} > t_{su}+t_{CC}+t_h$ 反推最高频率：$t_{su}=5\,\text{ns}$、$t_{CC}=12\,\text{ns}$、$t_h=1\,\text{ns}$ 时，$T_{clk} > 18\,\text{ns}$，即**最高约 55 MHz**。
- 主频 100 MHz（$T=10\,\text{ns}$）的板子上，$t_{su}+t_h$ 必须小于 10 ns 减去走线延迟裕量——这是选型时的硬指标，不是「差不多就行」。

## 常见坑

- **只查建立时间、忘了保持时间**：数据路径上某个寄存器的 $t_h$ 较大时，降频反而可能改善建立时间却恶化保持时间的相对余量。
- 把 $t_{CC}$ 漏掉：数据必须在**上一个**沿就稳定，时序分析是「沿到沿」而不是「沿到沿加一段」。
- 组合逻辑延迟太短（没插延迟单元）反而让保持时间违例——因为下一个沿来得太快，前一个沿的旧数据还没走远。
- 跨时钟域时把「亚稳态」当作小概率事件：它持续时间可能到微秒级，恢复逻辑必须能处理。

::: tip 例 1 · 100 MHz 的时钟能跑吗 {#ex-setup-hold-1}

某触发器 $t_{su}=3\,\text{ns}$、$t_h=1\,\text{ns}$、$t_{CC}=12\,\text{ns}$，时钟周期 $T=10\,\text{ns}$（100 MHz）。

$$T_{clk} > t_{su}+t_{CC}+t_h = 3+12+1 = 16\,\text{ns}$$

而实际 $T=10\,\text{ns} < 16\,\text{ns}$，**违例**。最高可用频率：

$$f_{max} = \frac{1}{16\,\text{ns}} = 62.5\,\text{MHz}$$

若一定要跑 100 MHz，只能换 $t_{su}+t_{CC}+t_h \le 10\,\text{ns}$ 的更快器件，或在数据路径上插延迟把保持时间余量腾出来。

> **为什么这么想**
> 把时钟沿当成一个「采样瞬间」，数据要在这个瞬间前就位（建立）、之后还不许跑（保持）。而上一拍的数据要到 $t_{CC}$ 之后才从触发器里出来，所以两拍之间必须容得下「建立 + 输出延迟 + 保持」这一整段。

:::

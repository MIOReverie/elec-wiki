# DMA 与缓存一致性

## 结论先行

- **DMA** 是独立于 CPU 的搬运工：外设数据就绪后，DMA 自动把它搬进内存（或反向），**全程不占 CPU**。
- 典型收益：100 kHz 采样若每次转换完成都进中断，CPU 每秒被打断 10 万次；改用 DMA 循环模式，CPU 只在「一批收满」时才被打扰一次。
- 三种常见模式：**Normal**（搬完停）、**Circular**（循环，连续采样必备）、**双缓冲**（一半满触发一次，实现流水线）。
- **缓存一致性**是带 D-Cache 的芯片（如 STM32F7/H7、M7）上的核心坑：DMA 直接写内存，**CPU 的 Cache 里还是旧值**；反过来 CPU 写完的数据可能还滞留在 Cache 里，DMA 读不到。
- 解决办法是**显式维护 Cache**：DMA 写内存后 CPU 读之前要 **Invalidate**（失效）对应区域；CPU 写内存之后 DMA 读之前要 **Clean**（回写）。

**为什么它承重**：Cache 带来的性能与「读到的值是旧的」这两件事同时存在，只有一半人知道。F7/H7 上不处理 Cache，DMA 采回来的数据会是一段旧值，调试时几乎无法定位。

## 典型数值

- 100 kHz 采样、每点 12 位：中断方式每秒 10 万次进入；DMA 循环缓冲 1000 点，则每秒只进 100 次中断（降低 1000 倍）。
- STM32F7 的 D-Cache 行大小是 **32 字节**。做 Cache 操作时地址必须**按 32 字节对齐**、长度取 32 的整数倍，否则失效范围不完整。
- CPU 读 DMA 缓冲前调用 `SCB_InvalidateDCache_by_Addr(addr, size)`；CPU 写完缓冲、DMA 要读时调用 `SCB_CleanDCache_by_Addr(addr, size)`。
- M7 的 AXI 总线带宽远高于 DMA 请求速率——所以 DMA 的瓶颈通常不是总线，而是**数据量与内存布局**。

## 常见坑

- **在带 Cache 的芯片上用 DMA 但没做 Cache 维护**：读到的数据是「上一批的」。
- Cache 操作**地址没按 32 字节对齐**——失效只覆盖了半行，另外半行还是脏数据。
- 忘了 DMA 缓冲区**不能放在栈上**（函数返回后失效），要放在全局或静态区。
- 环形缓冲区写指针与读指针**不是原子操作**：多字节变量被中断读到一半的值，需要临界区保护。
- 在 F1/F4（无 Cache）上写这套代码是多余的，但无害；反过来在 F7 上漏掉就是故障——**移植时最容易被漏掉的一步**。

::: tip 例 1 · DMA 采回来的是旧数据，怎么办 {#ex-dma-cache-1}

现象：STM32H7 上用 DMA 循环采 ADC，示波器看到输入在变，但屏幕上数字几乎不动，偶尔跳一下。

**原因**：H7 的 D-Cache 是写回（write-back）的。DMA 把新数据直接写进 SRAM，**不经过 Cache**；CPU 读的时候命中的是 Cache 里的旧行——只要那个行还没被替换，CPU 就一直读到旧值。

**处理**（三步，缺一不可）：

1. DMA 缓冲区放在**全局数组**里，且起始地址按 32 字节对齐（用 `__attribute__((aligned(32)))`）；
2. DMA 一批搬完（回调里），先 **Clean** 不必要、**Invalidate** 该区域：
   `SCB_InvalidateDCache_by_Addr((uint32_t*)buf, sizeof(buf));`
3. 之后 CPU 才去读 `buf`。

> **为什么这么想**
> Cache 是一份「本地副本」，DMA 是「外来写入者」——它不知道 Cache 存在，也不通知 Cache。于是本地副本与真实内存分家。Invalidate 就是命令 CPU「别信你的副本了，下次去内存取」。

:::

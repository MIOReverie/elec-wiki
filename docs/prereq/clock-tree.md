# 时钟树

<Meta time="5 min" level="卡片" note="外设时钟上电默认关闭；APB 分频不为 1 时定时器时钟自动乘 2" />

参数配好了，寄存器也写了，外设毫无反应，而且不报错。八成是时钟没使能。

另一种症状更绕：外设跑起来了，可是延时和 PWM 频率整体差一倍，代码怎么查都对。那是踩到了定时器时钟自动乘二这条规则。

## 时钟从哪来

上电默认用内部 HSI（RC 振荡器，误差 1%~2%）。要跑到标称主频，必须手工配：外部晶振 HSE → PLL（锁相环，把频率成倍放大的电路）倍频 → SYSCLK。

每个外设都有独立的时钟开关，上电默认关着（省电），必须先使能。

时钟树是一条分频链：$\text{SYSCLK}\to\text{HCLK(AHB)}\to\text{PCLK1/PCLK2(APB)}\to$ 各外设，每级分频系数都受芯片上限约束。

还有一条容易漏的：**APB 预分频系数 $\ne1$ 时，挂在该总线上的定时器时钟自动 ×2**。忘了它，延时与 PWM 频率整体差一倍。

所有基于时间的计算都以时钟为基准：延时、波特率、PWM 频率、采样率。时钟算错，程序照样编译、照样跑、照样看起来在工作，只是时间全错，最难查。

## 典型数值

| 时钟源 | 频率 | 精度 | 用途 |
| --- | --- | --- | --- |
| HSI | 8 MHz（F1）/ 16 MHz（F4） | 差（±1%~2%，温漂） | 上电默认；HSE 失效时的备份 |
| HSE | 通常 4~25 MHz | 高（几十 ppm） | 主时钟源 |
| LSI | 约 40 kHz | 很差 | 独立看门狗 IWDG |
| LSE | 32.768 kHz | 高 | RTC 实时时钟 |

F103 经典配置（HSE 8 MHz、PLL ×9）：

$$\text{SYSCLK}=8\times9=72\,\text{MHz},\quad \text{HCLK}=72\,\text{MHz},\quad \text{PCLK1}=36\,\text{MHz},\quad \text{PCLK2}=72\,\text{MHz}$$

$$\text{TIM2\text{--}7 时钟}=36\times2=72\,\text{MHz}\quad（APB1 预分频为 2，\times2）$$

$$\text{TIM1 时钟}=72\,\text{MHz}\quad（APB2 预分频为 1，不 \times2）$$

- APB1 上限 36 MHz（F103），所以必须至少二分频。
- 不配时钟时 F103 跑 8 MHz，所有时间计算差 9 倍。这是「程序能跑但串口全乱码」的经典原因。

## 常见坑

- 忘了使能外设时钟：`RCC->APB2ENR |= (1 << 2)` 或 `__HAL_RCC_GPIOA_CLK_ENABLE()`。
- 算定时器时钟用了 PCLK，而不是 ×2 之后的值。
- 算 UART 波特率时也乘了 2。USART 不享受 ×2，只有定时器享受。
- PLL 倍频后不检查上限：SYSCLK 超过芯片最大值，芯片直接进不了正常状态，表现是「卡在时钟配置之后」。
- 上拉引脚与外设时钟混为一谈：GPIO 配成开漏后仍需时钟，只是需求少一个而已。

::: tip 例 1 · 为什么定时器算出来快了一倍 {#ex-clock-tree-1}

某 F103 工程：HSE 8 MHz、PLL ×9、AHB ÷1、APB1 ÷2。写代码时按 $T=\dfrac{\text{ARR}+1}{\text{PCLK1}}$ 计算定时周期，PCLK1 = 36 MHz。但实测周期只有设计值的一半。

原因：APB1 的预分频系数是 2（$\ne1$），此时挂在 APB1 上的定时器时钟 $=36\times2=72\,\text{MHz}$，而不是 36 MHz。

修正：$T=\dfrac{\text{ARR}+1}{72\,\text{MHz}}$，即同样的 ARR 得到两倍的频率。

还有一处别顺手带错：同一个 APB1 上的 USART2 用的仍是 PCLK1 = 36 MHz，不乘二。定时器与串口在同一条总线上，时钟却不一样，这是最容易算混的地方。

> **为什么这么想**
> ×2 的设计意图是：即使你为了省电把 APB1 降到 36 MHz，定时器仍能拿到 72 MHz 的计数分辨率，不至于牺牲定时精度。这条规则是「总线的频率」与「外设实际吃到的频率」故意脱钩的结果。

:::

09 · SPI 与 I²C ​

核心 约 45 min两种最常用的板级总线：一个快而费线，一个省线而优雅；最容易错的是 CPOL/CPHA 配错位与 I²C 地址忘了左移

这一页要解决什么：传感器、屏幕、Flash 芯片要往单片机上挂，引脚却只有几十个——串行总线就是「用时间换引脚」的答案。这一页讲最常用的两种：SPI（Serial Peripheral Interface，串行外设接口：四线全双工、由主机提供时钟）和 I²C（Inter-Integrated Circuit，集成电路互连总线：两线半双工、带地址应答）。读完你应该能：给一个器件算出最高可用 SPI 时钟、配对四种模式里的正确一种、算出 I²C 器件实际发出的地址字节、取一组合规的上拉电阻。

读这页之前

  • 需要会：GPIO 的推挽与开漏输出（GPIO 页第二节的结论：开漏只能拉低、写 1 = 释放，这是 I²C 的物理基础）、时钟树（，SPI 时钟由总线时钟分频而来）、中断与 DMA 的基本概念（06 章、10 章，工程实例一节会用到）。
  • 这一页用到的符号：0x（十六进制前缀）、<<（左移）、|（按位或）、µs（微秒）、kHz/MHz。记号约定见符号与约定 · 数字与嵌入式。
  • 不需要复数与微积分；上拉电阻计算只有乘除法。

你刚拿到一块 OLED 屏，例程里写着「SPI 模式 3」；旁边一颗温湿度传感器却是 I²C 的，地址标着 0x68。你把屏幕接上，刷出来的是错乱的条纹；把传感器接上，搜索不到设备。两个失败的原因不同：屏幕是主机和从机对「什么时候采样」的理解没对齐（SPI 模式），传感器是你发出的地址和手册给的不是同一个数（I²C 地址左移）。这一页就解决这两类问题，顺便讲清两种总线各自的代价。

结论先行 ​

  1. SPI 用 4 根线（SCK / MOSI / MISO / CS）全双工同步传输，速度可达几十 MHz，没有地址概念，靠片选 CS（Chip Select，低电平选中某个从机）选择从机。
  2. I²C 只用 2 根线（SCL / SDA）半双工，靠 7 位（或 10 位）地址在同一条总线上挂多个设备，代价是速度较慢（100 kHz / 400 kHz）。
  3. SPI 有四种模式：CPOL（Clock Polarity，时钟极性：时钟空闲时的电平）与 CPHA（Clock Phase，时钟相位：在第几个边沿采样数据），主从必须一致，否则数据会整体错位一位。
  4. I²C 是开漏 + 上拉（pull-up：把线通过电阻接电源，没人驱动时把线拉成高电平）的「线与」结构：任何器件都只能把线拉低——所以上拉电阻是必需的，不是可选。
  5. 选型依据：要高速、点对点、大数据量（屏、Flash、高速 ADC）→ SPI；引脚紧张、多设备、低速（传感器、EEPROM、IO 扩展）→ I²C。

一、为什么需要串行总线 ​

这一节只回答一个取舍问题：为什么放着并行的「快」不用。

并行总线（8/16 根数据线 + 若干控制线）速度快但太费引脚，一颗 48 脚的 MCU 根本经不起这样的消耗。串行总线用少数几根线分时传数据，把「宽度」换成「时间」。

代价是协议复杂度——需要时钟同步、需要寻址、需要应答。SPI 和 I²C 就是两种不同取舍的产物，下一节先看舍得花钱买速度的 SPI。

二、SPI：四根线与四种模式 ​

这一节回答三个问题：四根线各干什么、数据在时钟的哪个瞬间有效、模式配错长什么样。

四根线 ​

线方向作用
SCK（Serial Clock）主 → 从时钟，由主机产生
MOSI（Master Out Slave In）主 → 从主机发数据
MISO（Master In Slave Out）从 → 主从机回数据
CS / NSS（Chip Select / Slave Select）主 → 从片选，低电平选中某个从机（每个从机一根）

全双工（full-duplex：两个方向同时传输）：主机在 MOSI 上发一位的同时，也在 MISO 上收一位。所以读操作也必须「发」——想读一个字节，就得先发一个字节（通常发 0xFF 这种无关值，称为 dummy 字节）来产生时钟。

四种模式：CPOL 与 CPHA ​

两个参数决定时序：

  • CPOL（时钟极性）：时钟空闲时的电平（0 = 空闲为低，1 = 空闲为高）
  • CPHA（时钟相位）：在第几个边沿采样数据（0 = 第一个边沿采样，1 = 第二个边沿采样）

组合成模式 0~3。绝大多数器件用模式 0 或模式 3。下面把四种模式的时序一比一画出来，先看图再配寄存器：

F103 的 SPI1 挂在 APB2（PCLK2 = 72 MHz），SCK 由分频系数决定。先想什么：算 SCK 不难，难的是记住有两个上限——外设自己的上限和从机器件的上限，取较小值。

另一个易错点：SPI2/SPI3 挂在 **APB1（36 MHz）**而不是 APB2，同样的分频系数得到的 SCK 只有 SPI1 的一半。

例 2 · 主从模式不一致会怎样

某 OLED 屏的手册写着「支持 SPI 模式 3（CPOL=1, CPHA=1）」，而工程师把 MCU 配成了模式 0（CPOL=0, CPHA=0）。先想什么：模式配错不是「偶尔丢包」，而是每字节固定错位一位——现象有指纹，能直接反推原因。

现象：屏幕要么全黑，要么显示错乱。原因是采样边沿错位——从机在 SCK 的上升沿采样，而主机在下降沿才更新数据（或反过来），导致从机采到的永远是「上一位」或「正在变化中的位」。

排查顺序：① 查从机器件手册确认它支持的模式；② 主从配成同一模式；③ 优先试模式 0 和模式 3（这两者覆盖绝大多数器件）。

SPI 的速度快、但每挂一个从机就要多一根 CS。当设备多、引脚又紧张时，就该看 I²C 了。

三、I²C：两根线、地址与应答 ​

这一节回答三个问题：两根线为什么必须带上拉、一帧交互里地址和应答怎么排、手册上的地址和代码里写的为什么不一样。

两根线与「线与」 ​

I²C 只有 SCL（时钟）和 SDA（数据），两者都是开漏输出 + 上拉电阻（开漏：GPIO 页讲过的输出形态，只能拉低、写 1 = 释放引脚）。这意味着：

  • 任何器件只能把线拉低，不能主动驱动为高；
  • 只要有一个器件拉低，线就是低；所有器件都释放，线才被上拉变高。

这就是「线与」（wire-AND：多个开漏输出并在一起，等效于把它们的输出做逻辑与）逻辑，好处是：

  • 天然支持多主机（谁拉低谁说话，冲突可被检测）；
  • 不同电压的器件可以共存（上拉到各自电平，配电平转换）；
  • 从机可以通过拉低 SCL 来延长时钟（clock stretching，时钟延展：从机告诉主机「我还没准备好」的手段），主机检测到 SCL 被拉住就等待。

代价：上拉电阻 + 总线电容（bus capacitance CbC_bCb​：所有器件引脚与 PCB 走线对地的寄生电容之和）构成一个 RC 充电回路，限制了上升沿速度和最高通信速率。

时序与地址 ​

一次「写寄存器」的完整时序——注意每 8 位之后都有一个第 9 位的应答：

START → 地址字节(写) → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP
  • START（起始条件）：SCL 为高时，SDA 出现下降沿
  • STOP（停止条件）：SCL 为高时，SDA 出现上升沿
  • ACK（Acknowledge，应答）：每传完 8 位，接收方在第 9 个时钟把 SDA 拉低表示收到；没人拉低（读到高）就是 NACK，即「没收到 / 地址不存在」
  • 地址字节：7 位地址左移 1 位，最低位表示方向（0 = 写，1 = 读）

例 3 · 7 位地址和实际发出的字节不是一回事

MPU6050 的手册写着「从机地址 0x68」。先想什么：先分清手册的 7 位地址和线上实际发出的 8 位字节是两个数，方向位补在最低位。

步骤：

  1. 左移一位、补方向位：
写=0x68≪1  ∣  0=0xD0,读=0x68≪1  ∣  1=0xD1\text{写} = \text{0x68} \ll 1 \;|\; 0 = \text{0xD0},\qquad \text{读} = \text{0x68} \ll 1 \;|\; 1 = \text{0xD1} 写=0x68≪1∣0=0xD0,读=0x68≪1∣1=0xD1
  1. 推广到常见器件：
器件7 位地址写字节读字节
MPU60500x680xD00xD1
SSD1306 OLED0x3C0x780x79

验算：0x68 = 0b1101000，左移一位 = 0b11010000 = 0xD0，加方向位 0 仍是 0xD0 ✓；0b1101000 | 1 = 0b11010001 = 0xD1 ✓。

这是最常见的困惑来源：手册给的是 7 位地址（未含方向位），而 HAL 的 HAL_I2C_Master_Transmit(hi2c, DevAddress, ...) 要求传的却是左移一位后的地址。用 HAL 时写成 0x68 会找不到器件——得写 0xD0（或者自己 addr << 1）。

判断方法：若你的地址是偶数、且器件手册地址是它的一半，说明你传对了（已左移）；若两者相等，说明忘了左移。

例 4 · 上拉电阻取多大

上拉电阻的上限由上升时间（rise time trt_rtr​：信号从低电平爬到高电平所花的时间）要求决定，I²C 规范要求 trt_rtr​ 不超过位周期的某个比例：

Rp(max)=tr0.8473×CbR_{p(max)} = \frac{t_r}{0.8473 \times C_b} Rp(max)​=0.8473×Cb​tr​​

其中 CbC_bCb​ 是总线总电容（器件引脚 + PCB 走线，一般估算 100~400 pF）。先想什么：上限算完还要算下限——电阻太小、灌电流太大也不行，两边都过了才算合规。

实用结论：

  • 100 kHz、短距离：4.7 kΩ（最常见）
  • 400 kHz：1.5~2.2 kΩ
  • 多器件、长线：先减小电阻，若还不行就降低速率

顺便算一下传输效率：100 kHz 下传一个字节需要 9 个位（8 数据 + 1 ACK）：

五、工程实例 ​

两种总线各有一个高频踩坑场景，都和「谁在什么时候松手」有关。

SPI 的片选管理：多个 SPI 从机时，CS 一般用普通 GPIO 软件控制（不用硬件 NSS）。关键纪律：每次传输前拉低对应 CS、传输完立刻拉高；CS 期间不能被打断（否则从机会收到半个命令而状态错乱）。多任务环境里要给 SPI 总线加互斥。

I²C 死锁与恢复：若主机在传输中途复位（或从机拉住 SDA 不放），总线可能卡在 SDA 为低的状态，此后主机再也发不出 START。恢复方法：主机把 SCL 强行翻转 9 个周期（用 GPIO 模拟时钟），让从机释放 SDA，然后补发一个 STOP。很多产品的 I²C 驱动里都有这段「总线恢复」代码。

六、易错清单 + 自检 ​

  • [ ] SPI 主从模式（CPOL/CPHA）不一致：数据整体错位一位
  • [ ] SPI 时钟超过器件或外设上限
  • [ ] SPI2/3 挂在 APB1，同样分频下速度只有 SPI1 的一半
  • [ ] 读操作忘了发 dummy 字节：SPI 全双工，不给时钟就收不到数据
  • [ ] I²C 忘了接上拉电阻：开漏总线没有上拉就永远读不到高电平
  • [ ] I²C 地址忘了左移一位（或重复左移）
  • [ ] 没检查 ACK：地址错、器件没上电、总线被拉死时都会无 ACK，应检测并报错
  • [ ] CS 在传输中途被释放（多任务下未加互斥）

自检：SPI 有哪四根线、CPOL 和 CPHA 各决定什么？I²C 的 7 位地址 0x68 在写操作时发出的字节是什么？100 kHz、200 pF 总线下上拉电阻取多大？（答案：SCK/MOSI/MISO/CS；CPOL 决定时钟空闲电平、CPHA 决定第几个边沿采样；0xD0；约 4.7 kΩ）

08 · 串口 UART ​

核心 约 45 min嵌入式最常用的对外接口：帧结构、波特率误差、轮询/中断/DMA 三种收法；最容易错的是 LSB 先发与波特率误差累积

这一页要解决什么：你把单片机和电脑用三根线接起来，printf 打出来的却是一屏乱码——问题出在哪一环？这一页把 UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器：一种没有时钟线、靠双方事先约定节奏的串行通信方式）从帧结构到接收方式讲清楚。读完你应该能：算出一帧占多少位、传 1000 字节要多久、判断一个波特率误差是否安全、为你的应用选轮询/中断/DMA，并搭一个最小可用的帧协议。

读这页之前

  • 需要会：寄存器是什么（，串口的所有配置最终都是往寄存器写数）、时钟树（，波特率由总线时钟 PCLK 分频得到，不知道 PCLK 是多少就没法算误差）。
  • 这一页用到的符号：0x（十六进制前缀）、<<（左移）、bps（位/秒，bit per second）、µs/ms（微秒/毫秒）。记号约定见符号与约定 · 数字与嵌入式。
  • 不需要复数、微积分；本页的数学只有除法和乘法。

先看一个所有人都遇过的场景。你照着教程接好 TX、RX、地三根线，波特率两边都设了 115200，打开串口助手——屏幕上滚出 元元鈥君子坦荡荡 这样的乱码；偶尔一切正常，烧录温度一高又开始偶发出错。乱码只有两种根源：两边对「一位是多长」的理解不一致（波特率误差），或者对「哪里是一帧的开头」理解不一致（帧格式、电平标准、LSB 顺序）。这一页就是把这两种根源拆开讲透。

结论先行 ​

  1. UART 是异步串行通信：没有时钟线，收发双方事先约定波特率（baud rate，每秒传输的位数），靠起始位的下降沿同步每一帧。
  2. 一帧 = 起始位 + 数据位（通常 8 位）+ 可选校验位 + 停止位。线路空闲时是高电平，第一个下降沿就是起始位。
  3. 数据位是最低位先发（LSB first，Least Significant Bit：最低有效位），和书写顺序相反——用逻辑分析仪读波形时最容易在这里出错。
  4. 三种接收方式：轮询（polling：主循环里反复查询，阻塞）、中断（每字节进一次中断）、DMA（Direct Memory Access，直接存储器访问：独立于 CPU 的搬运工，推荐，收完一帧才打扰 CPU）。
  5. 波特率由 PCLK（外设总线时钟）分频得到，通常有误差，但只要一帧内累积误差在 ±2%~3% 以内通信就正常；出问题先查「这条 USART 挂在哪个总线、PCLK 是多少」。

一、为什么需要「约定波特率」 ​

这一节只回答一个问题：没有时钟线的两台机器，怎么知道对方每一位有多长。

同步通信（SPI、I²C，见下一章）有专门的时钟线，接收方照着时钟采样即可。UART 每个方向只有一根数据线，没有时钟，于是双方必须事先约定「每位持续多久」——这就是波特率（baud，单位 bps，位/秒）的含义。

发方按约定节奏把每一位放到线上，收方按同样的节奏采样。为了对齐每一帧的起点，UART 规定三件事：线路空闲时为高电平；发送时先拉低一位（起始位），这个下降沿就是收方的同步信号；收方检测到下降沿后，等待半个位时间再开始采样——跳过边沿本身、在位的中间采样最可靠，之后每隔一个位时间采一次。

例 1 · 算一帧的时间和吞吐

115200 bps、8 位数据、无校验、1 位停止位（最常见的 115200-8-N-1 格式）。先想什么：先把一帧的位数数清楚，再算位时间，最后才算吞吐——顺序反了容易把「8 位」当成一帧。

步骤：

  1. 数位数：一帧 = 起始 1 + 数据 8 + 校验 0 + 停止 1 = 10 位。（为什么从起始位开始数：波特率的「位」包含起始位和停止位，它们也要占线上的时间。）
  2. 位时间与帧时间：
位时间=1115200≈8.68 μs,一帧=10×8.68=86.8 μs\text{位时间} = \frac{1}{115200} \approx 8.68\ \mu\text{s},\qquad \text{一帧} = 10 \times 8.68 = 86.8\ \mu\text{s} 位时间=1152001​≈8.68 μs,一帧=10×8.68=86.8 μs
  1. 有效数据速率（10 位里只有 8 位是数据）：115200/10=11520115200/10 = 11520115200/10=11520 字节/秒；传 1000 字节要 1000×86.8 μs=86.81000\times86.8\ \mu\text{s} = 86.81000×86.8 μs=86.8 ms。（为什么用帧时间而不是位时间：字节之间还夹着起始位和停止位。）
  2. 对照 9600 bps：一帧 10/9600=1.0410/9600 = 1.0410/9600=1.04 ms，1000 字节要 1042 ms（超过 1 秒）。

验算：11520 字节/秒 × 86.8 µs/字节 = 11520 × 86.8 µs ≈ 1.0 s/11520 字节 → 每字节 86.8 µs ✓（速率与单帧时间互为倒数，两条路算出同一个数）。

结论：波特率里的「位」包含起始位和停止位，有效数据速率只有标称值的 80%（无校验时）。做传输时间预算必须按这个算，否则会低估耗时。

帧的骨架看到了，下一个自然的问题是：这些位传错了怎么办——这就是校验位和波特率误差两件事。

二、校验位与波特率误差 ​

这一节回答两个问题：校验位能挡住什么样的错误，以及波特率差一点点到底会不会出事。

校验位（parity bit：附加在数据位之后的一个错误检测位）只有一种最朴素的能力：奇校验保证「数据位 + 校验位」里 1 的个数是奇数，偶校验保证是偶数。于是任何奇数个位被干扰翻转都能被发现，偶数个同时翻错发现不了——所以它只能挡最简单的单比特错误，可靠的协议都要另加 CRC（Cyclic Redundancy Check，循环冗余校验：对整帧数据做多项式除法得到的校验码，见本章例 4）。

波特率误差从哪来：UART 用 16 倍过采样（oversampling：接收方用比波特率高 16 倍的内部时钟去数每一位，从而能在位的中间附近采样），分频系数为 DIV=fPCLK/(16×baud)\text{DIV} = f_{PCLK} / (16 \times \text{baud})DIV=fPCLK​/(16×baud)，硬件只能取「整数 + 4 位小数」（步长 1/16）。PCLK 除不尽的时候，实际波特率就和标称值差一点。

例 2 · 波特率误差多大算安全

以 USART2（挂在 APB1，PCLK1 = 36 MHz）为例。先想什么：这不是算「误差是多少」就完了，而是要算误差在一帧里累积成多少个位——采样点在位的中间，只要累积漂移不超过 ±0.5 位就不出错。

步骤：

  1. 算理论分频与硬件可取值：
波特率理论 DIV硬件可取实际波特率误差
9600234.375234 + 6/16 = 234.3759600.000%（.375 = 6/16 恰好精确）
11520019.531319 + 9/16 = 19.5625115015.97−0.16%
  1. 评估 −0.16%：一帧 10 位，累积漂移 = 10×0.0016=0.01610 \times 0.0016 = 0.01610×0.0016=0.016 位。接收方在每个位中点采样，容错约 ±0.5 位，0.016 位远在容限内。（为什么按一帧算而不是按一秒算：UART 每一帧的起始位下降沿都重新同步一次，误差不会跨帧累积。）

验算：115015.97 × (1 + 0.0016) ≈ 115200 ✓（误差方向自洽：分频取大了，实际波特率偏低，符号为负）。

什么时候会出问题：误差接近或超过 ±2%~3%（比如用了不标准的晶振频率、或波特率取到接近分频极限的值），采样点会滑到位的边界，表现为偶发乱码——而且常是温度变化时才偶发，极难排查。

到这里，一位怎么发、一帧怎么对齐、误差多大安全都清楚了。接下来是工程师真正天天要做的决定：收到的字节怎么交给程序——三种方式各有代价。

三、三种接收方式 ​

这一节只做一件事：把轮询、中断、DMA 的 CPU 代价算成数字，让你能按场景选。

例 3 · 中断方式 vs DMA 方式的 CPU 开销

假设每次中断（进出 + 处理）约消耗 2 µs。先想什么：把「每秒进多少次中断」乘出来，再除以 1 秒，就得到 CPU 被打断的时间占比——占比超过 10% 主循环就会明显变卡。

步骤：

  1. 115200、每字节一次中断：每秒 115200/10=11520115200/10 = 11520115200/10=11520 次中断，
11520×2 μs=23 ms⇒CPU 占用约 2.3%11520 \times 2\ \mu\text{s} = 23\ \text{ms} \Rightarrow \text{CPU 占用约 } 2.3\% 11520×2 μs=23 ms⇒CPU 占用约 2.3%
  1. 921600 时：每秒 92160 次中断 → 92160×2 μs=18492160 \times 2\ \mu\text{s} = 18492160×2 μs=184 ms，CPU 占用 18.4%。
  2. 改用 DMA：收满 1024 字节才中断一次，115200 下每秒约 11520/1024≈1111520/1024 \approx 1111520/1024≈11 次，CPU 占用降到千分之一量级。

验算：11520×2 μs=23040 μs=2311520 \times 2\ \mu\text{s} = 23040\ \mu\text{s} = 2311520×2 μs=23040 μs=23 ms，23/1000=2.3%23/1000 = 2.3\%23/1000=2.3% ✓（与上式一致）。

结论：低波特率、少量数据时中断够用；高波特率或大数据量必须用 DMA，否则 CPU 会被中断淹没，主循环几乎无法执行。

中断方式的一个坑：HAL_UART_Receive_IT 只接收指定长度，收完就停止。所以回调里必须重新调用一次才能继续接收，否则只能收到第一字节。

三种方式都会把字节送进某个缓冲区。缓冲区怎么设计、一帧到哪里才算结束，是下一节的事。

四、环形缓冲与不定长帧 ​

这一节给出一对生产者—消费者的标准结构，并解决「帧长不固定时怎么知道一帧结束」。

串口数据是流式的，一帧数据可能分多次到达。标准做法是 ISR（Interrupt Service Routine，中断服务程序）/DMA 只负责往环形缓冲里放数据，主循环负责解析。环形缓冲（ring buffer：一段首尾相接的数组，写指针追着读指针走，写满不覆盖未读数据）在这里的作用是：即使主循环正忙，数据也不会丢。

不定长帧怎么判断一帧结束：常用 IDLE 空闲中断——线路上超过一个字节时间没有新数据，就认为一帧结束（HAL 的 ReceiveToIdle 系列就是干这个的）。这是目前最实用的方案。

字节流已经能安全进程序了，但字节本身还没有语义——哪些是帧头、哪些是数据、错了怎么办，这要靠你自己定义协议。

五、电平标准：TTL / RS232 / RS485 ​

这一节解决「为什么接对了线还是烧了板」：UART 是协议，电平标准另有讲究。

六、工程实例 ​

协议设计是这一章所有知识的合体。下面的例 4 从帧格式讲到解析状态机，两样都需要先看图再写代码。

例 4 · 设计一个简单可靠的帧协议

裸的字节流无法区分「帧边界」和「数据内容」。先想什么：帧格式解决「一帧长什么样」，解析状态机解决「收到一半、收到错帧怎么办」——两个问题分开想，别在代码里混着解决。

第一步：定帧格式（最小可用版）：

字段长度值
帧头2 字节0xAA 0x55（固定，用于定位帧起始）
长度1 字节后续数据长度 N
数据N 字节有效载荷
校验2 字节CRC16

第二步：算开销（115200、10 位/帧）：

数据长度帧长协议开销传输耗时
8 字节13 字节38.5%1.13 ms
32 字节37 字节13.5%3.21 ms
128 字节133 字节3.8%11.55 ms

验算：13 字节里 5 字节是固定开销，5/13=38.5%5/13 = 38.5\%5/13=38.5% ✓；耗时按例 1 的帧时间外推，13×86.8 μs=1.1313 \times 86.8\ \mu\text{s} = 1.1313×86.8 μs=1.13 ms ✓。

结论：帧头 + 长度 + 校验共 5 字节固定开销，数据越短，协议开销占比越高。所以高频小数据（如传感器采样值）应尽量打包成较长的帧批量发送，而不是一字节一帧。

第三步：解析要点：

  1. 用状态机（state machine：程序在任何时刻只处于有限几个状态之一，收到什么字节决定跳到哪个状态）解析，不要假设一次就能收完整帧；
  2. 校验失败要能重新同步：丢弃当前帧并回到「找帧头」状态；
  3. 若数据里可能出现帧头字节（0xAA 0x55），要做转义（escaping：把特殊字节替换成约定序列，如 0xAA 在数据中发成 0xBB 0xAA，接收方再还原），否则会误判帧边界。

七、易错清单 + 自检 ​

  • [ ] TX/RX 接反：TX 接对方的 RX，交叉连接；接成 TX-TX 永远收不到
  • [ ] 波特率不一致：双方必须一致；注意波特率包含起始/停止位开销
  • [ ] 电平标准混接：RS232 的 ±12 V 直接进 MCU 会烧片
  • [ ] 忘了在中断回调里重新启动接收（HAL_UART_Receive_IT 只收一次）
  • [ ] 主循环里用轮询接收导致系统卡顿：改用中断或 DMA
  • [ ] 读波形时按正常顺序读：UART 是 LSB 先发，波形顺序与书写顺序相反
  • [ ] 没做帧同步：直接按「收到的第一字节是数据」解析，一旦丢一字节就永久错位
  • [ ] printf 的浮点格式化打不出来：新工具链默认裁剪了 %f 支持

自检：115200-8-N-1 下，一帧几位、有效速率多少字节/秒、传 1000 字节多久？USART2 在 36 MHz 下跑 115200 的误差是多少、是否安全？（答案：10 位 / 11520 字节每秒 / 86.8 ms；−0.16%，一帧累积 0.016 位，远小于 0.5 位容限，安全）

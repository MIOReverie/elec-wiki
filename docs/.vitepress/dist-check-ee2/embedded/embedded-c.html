03 · 嵌入式 C 与寄存器思维 ​

核心 约 45 min四个高频坑：清零忘了取反、读位先移位再屏蔽、volatile 与原子性是两件事、改字段分两步写会被中断撕开

这一页要解决什么：上一页你已经能用 HAL 点灯，但那些函数背后其实都是「往某个地址的某几位写数」。这一页要让你自己写得出这类代码，并且写得对：寄存器到底是什么、怎么只改其中一位而不伤到邻居、位带为什么能把一位变成一个地址、volatile 到底防住了什么、以及为什么「先清零再置位」在中断面前会失效。读完你应该能看懂手册里的寄存器表和任何一段 HAL 源码，也能自己写出点灯、置标志、配字段的寄存器代码。

读这页之前

  • 需要会：C 语言的指针与结构体（-> 访问成员、把整数强制转换成指针）；二进制与十六进制互转；按位与 &、按位或 |、按位异或 ^、按位取反 ~ 的真值规律。这些是这一页唯一的工具，没有它们会很痛苦。
  • 这一页用到的符号：|= 按位或赋值、&= 按位与赋值、^= 按位异或赋值、~ 按位取反、<< 左移、>> 右移、0x 十六进制、0b 二进制。读法与几个易混点见符号与约定 · 数字与嵌入式。
  • 术语速览（正文都会展开）：寄存器映射（register map）是手册里那张「基地址 + 偏移 = 某个功能寄存器」的表；偏移（offset）是寄存器相对基地址的字节距离；掩码（mask）是只保留或只改动某几位的那个数；位带（bit-band）是内核提供的一种地址翻译机制，让「某一位」也拥有独立地址；原子操作（atomic）指不会被中断撕成两半的操作。
  • 需要知道的前提：寄存器为什么能像内存一样访问，依赖 那张地址地图，这一页第一节会再讲一遍，可以直接跳过复习。

新手读 STM32 参考手册时经常卡在同一处：手册给一张表，写着 偏移 0x0C、名称 ODR、复位值 0x0000 0000，然后教程里出现 GPIOA->ODR |= (1 << 5)。这三个东西——偏移、结构体指针、或等号——各自都认识，连起来就不知道在干什么了。

更麻烦的是那些「看起来对、跑起来偶尔错」的写法：中断里改 GPIO 偶尔失灵、while(!flag); 在 Debug 版正常、Release 版死机、配置寄存器时别的引脚莫名其妙被改了。这些都不是玄学，而是三件很具体的事：地址怎么算、位怎么改、改动会不会被撕开。这一页按这个顺序讲。

结论先行 ​

这一页的结论集中放这里，每条一句话，后面每一节展开其中一条。

  1. 寄存器 = 占据固定地址的一小块内存；「配置外设」就是往这些地址写特定的数，C 里用结构体指针访问它们。
  2. 位操作只有四个动作：置位 |= (1<<n)、清零 &= ~(1<<n)、翻转 ^= (1<<n)、读位 (reg>>n)&1；清零必须取反。
  3. 位带把「一位」翻译成「一个字」：改一位就是往它专属的别名地址写 0 或 1，一条指令搞定，不用读—改—写。
  4. volatile 管「每次都真去内存读」，不管「读和写之间不被打断」；原子性要靠 BSRR 这类硬件机制或关中断。
  5. 嵌入式 C 的额外纪律：慎用 malloc、栈要算着用、结构体对齐要检查、const 常量放 Flash。

心智模型：寄存器是一排带门牌号的抽屉，位带是给每个格子再发一个门牌号

通常你只能敲开「地址 0x4001 080C 这个抽屉」，把里面 32 个格子整体倒出来、改一个、再整体放回去——这就是读—改—写。麻烦在于倒出来的瞬间，别人（中断）可能也往里塞了东西，你还回去时就把他的东西覆盖了。

位带相当于给每个格子单独装了一扇门：想改第 5 格，直接敲「0x4221 0194 这扇门」，写 1 就是 1、写 0 就是 0，从不碰邻居，也永远不会覆盖别人。代价是这种方法只对特定内存区有效，而且要会算那扇门的地址。

一、内存映射：寄存器是有地址的内存 ​

这一节只回答一个问题：手册上那个「偏移 0x0C」是怎么变成一个 C 表达式里的成员的。

Cortex-M 有 4 GB 的线性地址空间（32 位地址就是 2322^{32}232 个字节），厂商把它切成几块，每块放不同性质的东西：

地址区间放什么
0x0000 0000 ~代码区（Flash 的别名，实际从 0x0800 0000 开始）
0x0800 0000 ~Flash：程序代码和 const 常量
0x2000 0000 ~SRAM：全局变量、栈、堆
0x4000 0000 ~外设寄存器（APB1 / APB2 / AHB 各总线挂的外设）
0xE000 0000 ~Cortex-M 内核的系统控制块（NVIC、SysTick 等）

寄存器映射（register map）就是手册里那张把「基地址 + 偏移」对到功能名的表。以 F103 为例，GPIOA 的寄存器组从 0x4001 0800 开始：

偏移寄存器作用
0x00CRL配置 Pin0~7（每脚 4 位）
0x04CRH配置 Pin8~15（每脚 4 位）
0x08IDR输入数据（读引脚电平）
0x0CODR输出数据（写引脚电平）
0x10BSRR原子置位/清零
0x14BRR清零（等价于 BSRR 高 16 位）

CMSIS 库（Cortex-M 的官方寄存器定义包）把这些地址定义成一个结构体指针，于是你可以写：

c
#define GPIOA_BASE 0x40010800UL
typedef struct {
  volatile uint32_t CRL, CRH, IDR, ODR, BSRR, BRR, LCKR;
} GPIO_TypeDef;
#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)

GPIOA->ODR |= (1 << 5);   // 就是往 0x4001080C 这个地址写

这一点想通了，后面所有外设就都通了：UART 的 DR 寄存器、定时器的 CNT、ADC 的 DR，全都是「有名字的地址」，操作它们就是读写内存。

地址找到了，但一个 32 位寄存器里通常挤着十几个互不相关的字段。下一个问题是：怎么只改自己想要的那一位。下一节给出四个动作。

二、位操作的四个动作 ​

这一节只做一件事：把「改某一位」拆成四个可背诵的动作，并说明每个动作的掩码长什么样。

外设寄存器几乎从不「整个赋值」——因为一个 32 位寄存器里往往塞了十几个配置字段，你只想改其中一位，绝不能动其他位。于是有了四个标准动作：

动作写法含义
置位（把某位写成 1）reg |= (1 << n)OR 上「只有第 n 位为 1」的掩码，其余位不变
清零（把某位写成 0）reg &= ~(1 << n)AND 上「只有第 n 位为 0」的掩码
翻转（1↔0）reg ^= (1 << n)异或，同掩码翻转两次回到原值
读位(reg >> n) & 1右移到最低位再屏蔽其余位

为什么是这四个、为什么掩码长这样，看一张位级图最清楚。

例 1 · 置位：把寄存器第 3 位写成 1

题目：寄存器初值 0x0000 00A0（二进制 1010 0000，即 bit5 和 bit7 为 1）。要把 bit3 置 1。

先想什么：置位只用一个掩码，不需要先把旧值读出来看——OR 的性质决定「OR 0 保留、OR 1 置一」，所以哪怕不知道当前值也能安全置位。（这正是置位比清零省事的地方：清零必须知道哪些位要保住。）

步骤：

0x00A0  ∣  (1≪3)=0x00A0  ∣  0x0008=0x00A8\text{0x00A0} \;|\; (1 \ll 3) = \text{0x00A0} \;|\; \text{0x0008} = \text{0x00A8} 0x00A0∣(1≪3)=0x00A0∣0x0008=0x00A8

二进制：1010 0000 → 1010 1000，bit5、bit7 原封不动。

验算：读回三位的值——bit3 现在为 1 ✓、bit5 仍为 1 ✓、bit7 仍为 1 ✓，其余位为 0 ✓。三个都过，说明没有误伤。

例 2 · 清零：把第 5 位写成 0（最易错的一步）

题目：承接上一步的 0x00A8，要把 bit5 清 0。

先想什么：清零要保住其他位，所以掩码里除了目标位之外全都得是 1——而 (1<<5) 恰好相反（只有目标位是 1）。于是必须取反，得到「只有目标位是 0」的掩码。（这一步之所以是最高频错误：|= 和 &= 长得像，脑子自动套用了置位的掩码。）

正确做法——掩码取反：

0x00A8  &  ∼(1≪5)=0x00A8  &  0xFFFF FFDF=0x0088\text{0x00A8} \;\&\; \sim(1 \ll 5) = \text{0x00A8} \;\&\; \text{0xFFFF FFDF} = \text{0x0088} 0x00A8&∼(1≪5)=0x00A8&0xFFFF FFDF=0x0088

错误做法（初学者高频）——忘了取反：

0x00A8  &  (1≪5)=0x00A8  &  0x20=0x0020\text{0x00A8} \;\&\; (1 \ll 5) = \text{0x00A8} \;\&\; \text{0x20} = \text{0x0020} 0x00A8&(1≪5)=0x00A8&0x20=0x0020

结果是除了 bit5 之外所有位都被清掉了，整个寄存器被毁。口诀：置位用原掩码，清零用反掩码。

验算：用十进制复核。0xA8 = 168，bit5 = 32，168−32=136=0x88168-32=136=\text{0x88}168−32=136=0x88 ✓；错误写法得到 0x20 = 32，而 168 与 32 的共同位只有 32，说明确实只剩一位 ✓（这也正是「全毁」的样子）。

例 3 · 翻转与读位

题目：承接 0x0088，翻转 bit7；再读出当前 bit5 的值。

先想什么：翻转用异或——异或 1 取反、异或 0 保持，所以同一个表达式能做「切换」。读位则要先右移把目标位挪到最低位，再与 1 相与，顺序反过来会得到一个 0 或 2n2^n2n 的数，不是干净的 0/1。（为什么要移位而不直接与：直接与得到的是「第 n 位仍在原位」的数，判断真假时容易把 0x20 当 0 以外的一切当真。）

步骤：

0x0088  ⊕  (1≪7)=0x0088  ⊕  0x80=0x0008\text{0x0088} \;\oplus\; (1 \ll 7) = \text{0x0088} \;\oplus\; \text{0x80} = \text{0x0008} 0x0088⊕(1≪7)=0x0088⊕0x80=0x0008

bit7 从 1 变成 0。翻转的性质是可逆：再执行一次 ^= (1<<7) 又会变回 0x0088，所以 LED_Toggle 这类操作用异或最自然。

读位：读 0x0008 的 bit5：

(0x0008≫5)  &  1=0  &  1=0(0\text{x}0008 \gg 5) \;\&\; 1 = 0 \;\&\; 1 = 0 (0x0008≫5)&1=0&1=0

即 bit5 当前是 0。注意读位时先移位再屏蔽的顺序不能颠倒——若写成 reg & (1<<5)，得到的会是 0x00 或 0x20，而不是干净的 0/1。

验算：把翻转后的 0x0008 逐位核对：bit3 = 1（因为 8=238=2^38=23）、bit7 = 0、其余为 0 ✓，与两次异或的预期一致。

例 4 · 写多位的配置字段（位域写入）

题目：配置 GPIO 时每个引脚占 4 位（2 位模式 + 2 位速度）。要把 0x00A0 的 bit[3:2] 这个两位字段改写成 01。

先想什么：这不是「置几位」而是「写一个几位宽的字段」。字段写入的动作固定为两步：先用字段掩码把整段清零，再把新值或进去——顺序不能颠倒，也不能省掉清空。（为什么不能只做第二步：或运算只写 1，旧值里的 1 会留下，字段最终是什么取决于上一个值，这叫「不幂等」。）

步骤：

c
uint32_t mask = 0b11 << 2;              // 字段掩码：bit[3:2]
reg = (reg & ~mask) | (0b01 << 2);      // 先清空字段，再写入值

代入验证：

0x00A0  &  ∼0x0C=0x00A0  &  0xFFFF FFF3=0x00A0\text{0x00A0} \;\&\; \sim 0\text{x0C} = \text{0x00A0} \;\&\; \text{0xFFFF FFF3} = \text{0x00A0} 0x00A0&∼0x0C=0x00A0&0xFFFF FFF3=0x00A00x00A0  ∣  (1≪2)=0x00A4\text{0x00A0} \;|\; (1 \ll 2) = \text{0x00A4} 0x00A0∣(1≪2)=0x00A4

结果 0x00A4，其中 bit[3:2] = 01（因为 0xA4 = 1010 0100，bit3=0、bit2=1）。

为什么不能分两步（先 |= (1<<2) 再 &= ~(1<<3)）？在单线程里结果相同，但如果中间被中断打断，硬件会短暂看到一个中间态（字段先变成 11 之类），对配置敏感的寄存器（如时钟分频）可能引发故障。所以配字段要一次算好一次写入。

验算：0xA4=1640\text{xA}4 = 1640xA4=164；字段值 =⌊(164  &  0x0C)/4⌋=⌊(4)/4⌋=1=\lfloor(164 \;\&\; 0\text{x0C})/4\rfloor = \lfloor(4)/4\rfloor = 1=⌊(164&0x0C)/4⌋=⌊(4)/4⌋=1，即 01 ✓；再看字段外的位：164  &  ∼0x0C=160=0xA0164 \;\&\; \sim 0\text{x0C} = 160 = 0\text{xA0}164&∼0x0C=160=0xA0，与初始值完全一致，说明没有误伤 ✓。

四个动作都会了。但「改一位」这件事还有一个更隐蔽的敌人：编译器。下一节处理它。

三、volatile：别让编译器把你的代码优化没了 ​

这一节只回答一个问题：为什么一段在 Debug 版能跑的代码，换成 Release 就死循环。

编译器会做一件很聪明的事：如果一个变量在某段代码里没被写过，它就认为这个值不会变，把重复读取优化掉。在 PC 上这没问题（单线程、内存只由本线程改），但在嵌入式里，有些变量会被编译器看不见的东西改变——硬件、中断、另一个任务。

三种必须加 volatile 的场景：

c
// ① 硬件寄存器（CMSIS 的结构体成员全部带 volatile）
while ((USART1->SR & (1 << 5)) == 0) { }   // 等待发送完成标志

// ② 中断服务程序里修改的标志
volatile uint8_t flag = 0;
void HAL_GPIO_EXTI_Callback(uint16_t pin) { flag = 1; }
int main(void) { while (!flag) { } /* ... */ }

// ③ RTOS / 多线程共享的变量
volatile uint32_t tick_count;

不加 volatile 会发生什么：while(!flag); 里，编译器发现循环体不修改 flag，就把它优化成「读一次到寄存器，然后死循环」——中断明明把 flag 置 1 了，主循环却永远看不到。这类 bug 极其隐蔽：开优化（-O2）才出现，关优化（-O0）一切正常。

volatile 不保证什么：它只保证「每次都真的去内存读写」，不保证原子性，也不能替代互斥锁。多字节变量的跨任务保护要靠关中断或 RTOS 的同步机制——这一点是下一节的主题。

四、原子性：为什么需要 BSRR，以及位带是什么 ​

这一节回答两个问题：为什么「看起来只改一位」的 |= 其实不安全，以及硬件给了哪两条出路。

看这行很常见的代码：

c
GPIOA->ODR |= (1 << 5);   // 看起来是「只改 bit5」

它编译后其实是三步机器操作：读 ODR → 或运算 → 写回 ODR。如果在这三步之间来了个中断，中断里也改了 ODR 的其他位，那么中断返回后，主程序写回的旧值会把中断的修改覆盖掉。

STM32 为此提供了第一条出路——BSRR（Bit Set/Reset Register，位置位/复位寄存器）：

c
GPIOA->BSRR = (1 << 5);          // 低 16 位：置位 → bit5 = 1
GPIOA->BSRR = (1 << (5 + 16));   // 高 16 位：清零 → bit5 = 0

写入 BSRR 是一次写操作，硬件内部完成置位/清零，不存在「读—改—写」的窗口，因此是原子的——中断里改 GPIO 可以放心用。

第二条出路更狠：干脆让「一位」自己拥有一个地址。这就是位带（bit-band，Cortex-M3/M4 内核的一项地址翻译机制：把某个内存区里每一位，映射成另一个区里的一整个 32 位字）。

位带的规矩只有三条：

  1. 只有两块源区能用：SRAM 的 0x2000 0000 起 1 MB、外设区的 0x4000 0000 起 1 MB。别的地址没有别名。
  2. 别名区基址固定：SRAM 对应 0x2200 0000，外设对应 0x4200 0000。
  3. 换算公式：别名地址 = 别名基址 + (源地址 − 源区基址) × 32 + 位号 × 4。乘 32 是因为「源区 1 字节」要摊成「别名区 32 字节」，每个位占 4 字节（一个 32 位字）。

用一次就明白它好在哪：*(volatile uint32_t *)0x42210194 = 1; 这一句就完成了「把 ODR 的 bit5 置 1」，没有读、没有回写、也不会碰到邻居。

例 5 · 算一个位的别名地址

题目：要原子地把 GPIOA 的 ODR 第 5 位置 1，别名地址是多少？若改的是 SRAM 里地址 0x2000 0000 的第 7 位呢？

先想什么：先判断源地址属于哪块源区（SRAM 还是外设），因为它决定别名基址；再算偏移，最后套公式。三步顺序错了，地址会落在完全无关的地方——写进去不会报错，只是改了一个没人看的内存。（为什么强调先判区：两块别名区基址不同，用错基址算出来的地址依然「可写」，这类错误最难查。）

步骤：

  1. GPIOA->ODR 的字节地址是 0x4001 080C，落在外设区（0x4000 0000 起），别名基址取 0x4200 0000。
  2. 偏移：0x4001080C−0x40000000=0x1080C0\text{x}4001080C - 0\text{x}40000000 = 0\text{x}1080C0x4001080C−0x40000000=0x1080C。
  3. 套公式：0x42000000+0x1080C×32+5×4=0x42000000+0x210180+0x14=0x4221 01940\text{x}42000000 + 0\text{x}1080C\times32 + 5\times4 = 0\text{x}42000000 + 0\text{x}210180 + 0\text{x}14 = \text{0x4221 0194}0x42000000+0x1080C×32+5×4=0x42000000+0x210180+0x14=0x4221 0194。
  4. SRAM 那个：源地址就是区首，偏移 0，别名基址 0x2200 0000，位 7 → 0x22000000+0+28=0x2200 001C0\text{x}22000000 + 0 + 28 = \text{0x2200 001C}0x22000000+0+28=0x2200 001C。

验算：用「每字 4 字节、每字节 32 字节」的数量关系反推。bit5 的别名应在该字节别名区起点之后 5×4=205\times4=205×4=20 字节处，即 0x4221 0180 + 0x14 = 0x4221 0194 ✓；SRAM 的 bit7 应在区首之后 7×4=287\times4=287×4=28 字节处，0x1C ✓。两个结果与独立算的偏移一致。

先确认你的芯片有没有位带：F1（Cortex-M3）有；多数 F4 及更新的型号并不实现这个功能，写别名地址会直接触发总线错误。用之前查手册的「Bit banding」一节，别照抄。

位带这条捷径只在部分芯片上存在，而「volatile 不保证原子」这个问题在每颗芯片上都存在。再往外放宽一层，还有一批「在 PC 上不算毛病、在单片机上会要命」的 C 语言习惯。

五、嵌入式 C 的额外纪律 ​

这一节给一张清单：在只有几 KB RAM 的机器上写 C，哪些平时的习惯要改。

主题纪律原因
动态内存尽量不用 malloc / free内存碎片；失败时难以恢复；确定性差（实时系统最怕这个）
栈大数组不要放函数内；递归要谨慎栈溢出会静默破坏内存，且默认栈可能只有几 KB
结构体对齐与硬件/协议对应的结构体要检查对齐编译器会插填充字节，导致结构体大小和成员偏移与预期不符
const常量表加 const会被放进 Flash 而不是占用宝贵的 RAM
static限制作用域，避免全局污染也便于编译器优化
浮点M0/M3 无 FPU，float 运算是软件模拟，很慢需要浮点运算选 M4，或改用定点数

结构体对齐的例子：

c
typedef struct {
  uint8_t  a;   // 偏移 0
  uint32_t b;   // 偏移 4（编译器插了 3 字节填充）
  uint8_t  c;   // 偏移 8
} Bad;          // sizeof = 12，不是 6

按成员从大到小排列，或用 __attribute__((packed))（但会带来非对齐访问的性能损失甚至硬件错误）来消除填充。

这些纪律在你写第一个驱动时就会撞上：栈溢出、对齐错位、常量占满 RAM，通常一起出现。下一节用两个真实案例把它们串起来。

六、工程实例 ​

为什么 HAL 库的 handle 里到处是 volatile：打开 stm32f1xx_hal_uart.h，你会看到 UART_HandleTypeDef 里的状态成员带 __IO（就是 volatile 的宏）。因为 UART 的收发状态会被中断服务程序修改，主程序轮询它时必须每次真正读内存。

一个真实的隐蔽 bug：某项目用 while(!tx_done); 等待 DMA 发送完成，tx_done 在 DMA 中断里置位。Debug 版本（-O0）正常，Release（-O2）死机。原因就是 tx_done 没加 volatile，被优化成了只读一次。加上 volatile 后两个版本都正常——这类问题只在优化后才暴露，所以要尽早用 Release 配置编译验证。

为什么寄存器地址要用结构体而不是一堆宏：GPIOA->ODR 让编译器替你算偏移，还能靠类型检查发现「写错寄存器」。代价是结构体成员顺序必须与手册严格一致——这也是为什么 CMSIS 头文件里那些成员不能随手重排。

易错清单（按踩坑频率排序） ​

  1. 清零忘了取反（写成 &= (1<<n)） → 除目标位外全部清零，整个寄存器被毁，现象是「配置完外设彻底不动」 → &= ~(1<<n) 才是清零，记「置位用原掩码、清零用反掩码」。
  2. 读位顺序写反（写成 reg & (1<<n)） → 得到 0x20 这类值，if 判断永远为真 → 先移位再屏蔽：(reg >> n) & 1。
  3. 改多位字段不分两步（直接 |= value） → 旧字段里的 1 残留，得到 11 之类的非法组合 → 先 & ~mask 清空整段，再 | value 一次写入。
  4. 共享变量忘加 volatile → -O0 正常、-O2 死等，且断点调试时看不出来 → 硬件寄存器、中断修改的全局变量、RTOS 共享变量三者必加。
  5. 把 volatile 当原子 → 多字节变量在中断与主循环之间被撕裂，偶发错值 → 原子性要靠关中断、BSRR、或 RTOS 同步机制。
  6. 中断里用 ODR |= 改 GPIO → 整字读—改—写，覆盖中断里刚改的其它位 → 改用 BSRR（或位带，前提是芯片支持）。
  7. 函数里开大数组 → 几 KB 的默认栈瞬间溢出，破坏相邻内存，症状随机 → 改成 static 或全局，并核算栈深。
  8. 结构体直接映射到硬件或协议 → 填充字节让偏移与预期差几位，读到错的数据 → 检查对齐，必要时 packed 但要接受非对齐访问的代价。

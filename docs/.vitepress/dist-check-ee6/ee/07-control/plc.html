20 · PLC 与梯形图 ​

了解 约 25 min重点：扫描周期、梯形图与逻辑式的互换、双线圈禁忌

这一页要解决什么：上一章的自锁、互锁靠硬接线，改一个逻辑就得重新拉线。这一页把同一套逻辑搬进 PLC（Programmable Logic Controller，可编程逻辑控制器：面向工业开关量控制的专用计算机）。读完你应该能：说清 PLC 一个扫描周期里发生什么、把梯形图和逻辑式互相翻译、解释双线圈为什么被禁止、并按「故障导向安全」的规则接停止按钮。

读这页之前

  • 需要会：第 19 章 · 继电接触器控制 的自锁与互锁（）、基本逻辑运算（与、或、非，）。
  • 这一页用到的记号：I（输入位）、Q（输出位）、M（内部中间位）、T（定时器）、C（计数器）——PLC 里的「位」就是一个 0/1 变量，触点是读位，线圈是写位。
  • 符号与约定：逻辑式记号（⋅\cdot⋅ 与、+++ 或、上划线非）见符号与约定。
  • 一个词先给一句话：梯形图（ladder diagram：把触点画成横档、母线画成两根竖轨的编程语言）长得像继电器电路图，是 PLC 最常用的编程方式。

上一章的自锁电路一旦要加一个延时、改一个联锁，就得拆线重接。工厂里这类「改逻辑」每个月都有，于是一台机器代替了整面继电器屏：PLC 用程序实现同样的触点逻辑，梯形图写起来还像继电器图，改起来却只需改几行代码。但「像继电器」只是长相——PLC 里面没有电流，只有被一遍遍重复执行的计算。这一页就讲这个「像而不一样」到底差在哪。

结论先行 ​

  1. PLC 是工业控制计算机，循环扫描工作：输入采样 → 执行程序 → 输出刷新，周而复始
  2. 梯形图长得像继电器电路，但里面没有电流，只有逻辑运算——「能流」只是形象说法
  3. 梯形图与逻辑式一一对应：串联 = 与，并联 = 或，常闭 = 取反；这是考试的基本功
  4. 启保停的梯形图和继电器电路长得完全一样，但「自锁」的含义变了：继电器里是触点闭合，PLC 里是输出位为 1
  5. 同一线圈在一个程序里只能出现一次（双线圈禁忌），而触点可以无限次引用
  6. 停止按钮要故障导向安全：硬件接常闭，程序里当「条件」串联

工作原理：循环扫描 ​

这一节回答一个问题：PLC 把程序从头到尾跑一遍，中间到底发生了什么——理解了它，响应延迟和双线圈两个坑就都推得出来。

PLC 加电后不停重复三件事：

每个扫描周期：
  ① 输入采样  读所有输入端子 → 输入映像寄存器
  ② 执行程序  按梯形图从上到下、从左到右做逻辑运算 → 输出映像寄存器
  ③ 输出刷新  把输出映像的值送到输出端子 → 驱动接触器、电磁阀、指示灯

关键在「映像」两个字：程序不直接读端子，也不直接写端子，读写的都是映像寄存器。输入的变化要等下一次采样才被看见，输出的变化要等刷新时刻才生效——这就是响应延迟的来源。

扫描周期带来两个直接后果

  1. 响应延迟：输入变化到输出响应的延迟在 1~2 个扫描周期之间（见例 2）。周期越短响应越快，但周期受程序长短限制——这就是为什么「程序写得简洁」有工程意义。
  2. 双线圈输出会互相覆盖：因为输出最终由映像寄存器里最后一次写入的值决定（见例 3）。

扫描机制立住了，接下来看程序本身长什么样——先认梯形图的五个符号。

看梯形图先立一个模型：左右母线不是真的电源，支路里没有电流，只有逻辑——「能流」只是形象说法。它是被 CPU 从上到下、从左到右扫描执行的一段程序：触点读的是「位」的 0/1，线圈是把运算结果写进「位」。所以读一条梯级，就当读一个布尔等式，别去追电流路径——这也是为什么「双线圈」会互相覆盖（见例 3）。

停止按钮接常开还是常闭

硬件接常闭，程序里当「条件」用（梯形图里画成常开触点 ─| |─，逻辑式里直接串联 I0.1I0.1I0.1）。

原因：这样接线时，按钮按下 → 回路断开 → I0.1=0I0.1 = 0I0.1=0 → 程序停机。而如果电线断线（故障），I0.1I0.1I0.1 同样变 0，电机同样停机——这就是「故障导向安全」。反过来若接常开，断线时程序以为「没按停止」，电机会继续转，很危险。

例 1 · 梯形图转逻辑式

写出下图梯形图的逻辑表达式，并说明它实现什么功能。

先想什么：读梯形图别追「电流」，按固定动作走——先找到线圈，再从左母线倒推线圈的触点组合：并联是 +、串联是 ⋅\cdot⋅、常闭取反。翻译完再看这个式子像谁。

  I0.0   Q0.0
──| |──┬──| |──┬──|/|────( )──
       │       │   I0.1  Q0.0
       └───────┘

解：两条并联支路（I0.0 与 Q0.0 常开）串联 I0.1 常闭，驱动 Q0.0 线圈：

Q0.0=(I0.0+Q0.0)⋅I0.1‾Q0.0 = (I0.0 + Q0.0)\cdot \overline{I0.1} Q0.0=(I0.0+Q0.0)⋅I0.1

这正是启保停：I0.0 是起动按钮（按一下即松开，靠 Q0.0 自己的常开触点续上），I0.1 是停止按钮（常闭，程序里取反后串联）。与第 19 章 · 继电接触器控制的继电器电路完全同构——只是这里的 Q0.0 触点不占物理端子，可以随意使用。

验算：代入两个边界状态——按住 I0.0、未按 I0.1：Q=(1+0)⋅1=1Q=(1+0)\cdot 1=1Q=(1+0)⋅1=1 ✓ 起动；松开 I0.0：Q=(0+1)⋅1=1Q=(0+1)\cdot 1=1Q=(0+1)⋅1=1 ✓ 保持；按 I0.1：Q=(0+1)⋅0=0Q=(0+1)\cdot 0=0Q=(0+1)⋅0=0 ✓ 停止。自锁、停止全部吻合。

例 2 · 扫描周期与响应延迟

某 PLC 扫描周期 T=100T = 100T=100 ms，其中输入采样占前 5 ms，输出刷新在第 90~95 ms。输入 I0.0 在执行程序阶段中途（第 6 ms）发生变化，输出 Q0.0 什么时候响应？

先想什么：这是把扫描三阶段当时间轴用的题。关键动作只有两步：找下一次采样时刻（输入映像何时更新），再找那之后的下一次刷新时刻（输出何时生效），两者相减就是延迟。

  1. 采样时机：变化发生在第 6 ms，本周期的采样（0~5 ms）已经过去了。所以要等下一个周期的采样，即第 100 ms 时 I0.0 的新状态才进入输入映像寄存器。等待时间 =100−6=94= 100 - 6 = 94=100−6=94 ms。（为什么不在本周期补采：扫描纪律是「程序执行期间输入映像冻结」，中途改读会让同一段程序前后看到不一致的世界。）
  2. 刷新时机：下一周期执行程序、刷新输出发生在第 90~95 ms（即第 190 ms 时刻），Q0.0 此刻才真正改变。从输入变化算起共延迟 190−6=184190 - 6 = 184190−6=184 ms ≈1.84 T\approx 1.84\,T≈1.84T。（为什么不是刷新点 90 ms：执行程序读的还是刷新前的输出映像，必须等刷新完成才送到端子。）

另一种极端：若输入在第 99 ms 变化（采样前 1 ms），则第 100 ms 就被采入，输出在第 190 ms 刷新，延迟仅 919191 ms ≈0.91 T\approx 0.91\,T≈0.91T。

验算：延迟 === 采样等待 +++ 执行等待 ≈94+90=184\approx 94 + 90 = 184≈94+90=184 ms，与直接相减 190−6190-6190−6 一致 ✓；两个极端（0.91 T 与 1.84 T）都落在「1~2 个周期」的结论区间内 ✓。

结论：响应延迟在 1~2 个扫描周期之间。工程上按「一个周期」估算；对响应速度有要求的场合（如限位急停），要么缩短扫描周期，要么把最关键的信号接进高速输入/中断，不能指望主循环。

例 3 · 双线圈为什么是禁忌

程序中同一个输出线圈 Q0.0 在两个地方各出现一次：

支路1：I0.0 ──| |──────────(Q0.0)──
支路2：I0.1 ──| |──────────(Q0.0)──

I0.0 = 1、I0.1 = 0 时，Q0.0 是什么？

先想什么：直觉答案「两条支路并联，Q0.0 = 1」来自继电器思维。这题考的正是那个模型的失效——PLC 是串行执行的，同一个线圈被写了两次，后一次必然覆盖前一次，问题变成「最后写的是哪条支路」。

解：Q0.0 = 0。

因为扫描是「从上到下」顺序执行的：支路 1 执行时算得 Q0.0 = 1 写进输出映像；执行到支路 2 时又算得 Q0.0 = 0，把前面的结果覆盖掉。刷新时送到端子的是最后写入的值——支路 1 的逻辑等于白写。

验算：把执行顺序逐步列表——扫描到支路 1：输出映像 Q0.0 ← 1；扫描到支路 2：输出映像 Q0.0 ← 0；刷新：端子得到 0 ✓（与串行覆盖推理一致）。

这与继电器电路有本质区别：继电器电路里两个支路是真正的并联（物理上同时存在），而 PLC 是串行执行。结论：一个线圈在程序里只允许出现一次；想实现「或」逻辑，就把两个条件并联到同一支路里，或者用内部位 M 中转。

触点则相反：常开/常闭触点可以无限次引用，因为它们只是「读」位状态，不产生写入冲突。

例 4 · 定时器延时起动

要求：按下 I0.0 后延时 10 s 才接通 Q0.0；松开 I0.0 立即停止。设 TON 定时器时基为 100 ms，写出梯形图结构和 PT 值。

先想什么：拆需求——「延时接通」正是 TON（接通延时定时器，条件满足后开始计时、计满才闭合触点）的定义，所以选型不用犹豫；剩下两件事：定时器挂在哪个条件上（I0.0，因为松开要立即停 → 计时中断 → 触点断开），以及 PT 怎么从 10 s 换算成计数个数。

解：TON 是「接通延时」定时器——条件一满足就开始计时，计到 PT 才把触点闭合。所以：

I0.0 ──| |────[TON  T0  PT=100]──
                    T0 常开 ──| |────────( Q0.0 )──

PT 的换算：时基 100 ms × 100 = 10 000 ms = 10 s，所以 PT = 100。

两个容易错的地方：

  • TON 计时期间触点还没闭合，Q0.0 不会动作；计时中断（条件消失）时定时器当前值清零，下次重新从 0 计
  • 若要「延时断开」，得用 TOF 或用「停止后启动另一个定时器」的写法——TON 本身做不到

验算：PT 换算倒推：100×100 ms=10 s100\times100\ \text{ms}=10\ \text{s}100×100 ms=10 s ✓；行为核对——按住 I0.0 满足 10 s 后 Q0.0 = 1，第 9.9 s 松开则计时清零、Q0.0 保持 0，与「松开立即停止」的要求一致 ✓。

例题做完，最后看一台真实的老机床怎么从继电器柜改成 PLC 控制——把本页所有概念串起来。

工程实例：用 PLC 改造一台老机床 ​

这一节是操作清单式的收尾：看改造五步里分别用了本页的哪个知识点。

老设备是继电接触器控制，改造步骤：

  1. 清点 I/O：数输入（起动、停止、正转、反转、限位 ×3、热继电器、急停 ≈ 8 点）和输出（正转线圈、反转线圈、指示灯 ×4 ≈ 6 点），选 16 点输入 / 16 点输出的小型 PLC（点数留 30% 裕量）
  2. 分配地址：把每个器件写成 I/O 分配表，这是程序的「图纸」
  3. 翻译控制电路：主电路几乎不动（接触器、热继电器、电机原样保留），只把控制电路的硬接线换成梯形图；热继电器仍接在硬件回路里作后备保护——程序不能是唯一的安全屏障
  4. 急停必须硬接线：急停按钮直接串在接触器线圈的电源回路里，不经过 PLC 程序。程序会死机，硬件不会
  5. 调试：先单独调每个支路（点动），再联调；用「强制」功能模拟输入，避免反复按按钮

改造的收益不只是省电线：改工艺只需改程序，加一个定时/计数/联锁只是几行梯形图——这是硬接线做不到的。

程序再可靠也有死机的时候，安全底线还得靠最后一章的接地、漏电与急救知识兜住。

易错清单 ​

按踩坑频率排序，格式是「错误做法 → 会得到什么 → 正确做法」。

  1. 一个线圈在程序里出现两次 → 后执行的覆盖先执行的，前面支路白写 → 线圈只出现一次，「或」逻辑并进同一条支路或用 M 中转。
  2. 把梯形图当电路追电流 → 分析串行覆盖现象时必然出错 → 它是逻辑运算，读成布尔等式。
  3. 停止按钮硬件接常开 → 断线时程序不知道，电机停不下来 → 硬件接常闭，程序里当条件串联（故障导向安全）。
  4. 急停只写进程序 → 程序死机时急停失效 → 急停直接串在接触器线圈电源回路，不经过 PLC。
  5. TON 计时中断以为能续算 → 定时值清零、动作时间对不上 → 条件断开当前值清零重来；要「断开保持」得另搭回路。
  6. 响应延迟按 0 估 → 高速场合（限位、急停）出错 → 按 1~2 个扫描周期估；关键信号走硬件或中断。
  7. 输出类型不看 → 继电器输出接高频脉冲失灵、晶体管输出接交流烧毁 → 继电器输出（交直流、慢）、晶体管输出（直流、快、可脉冲）分开选。

自检 ​

  1. 为什么「输入变化后输出至少要等半个周期、至多两个周期」？用采样、执行、刷新三阶段各说一句话。
  2. 把第 19 章的正反转互锁电路翻译成两个逻辑式——自锁触点和互锁常闭触点各对应式子里哪一项？
  3. 停止按钮接常闭、程序里写常开触点，这两件事为什么合起来才是「故障导向安全」？

04 · 时钟系统（RCC 与时钟树） ​

核心 约 45 min所有外设的心跳都从这里来；忘了开时钟 = 外设不工作，算错分频 = 时间全错

时钟源、总线分频链与定时器 ×2 规则的完整说明见 。

结论先行 ​

  1. 时钟是 MCU 的心跳，每个外设都有独立的时钟开关。上电后外设时钟默认是关的（省电），必须先使能再用——这是「代码没错但外设没反应」的第一大原因。
  2. 芯片上电默认用内部 HSI（RC 振荡器，精度差），要达到标称主频必须手工配置时钟树：外部晶振 HSE → PLL 倍频 → SYSCLK。
  3. 时钟树是一条分频链：SYSCLK → AHB(HCLK) → APB1/APB2(PCLK1/PCLK2) → 各外设。每个环节的分频系数都受芯片上限约束，超了就会跑飞。
  4. APB 预分频系数 ≠ 1 时，挂在该总线上的定时器时钟会自动 ×2。忘了这条，你算出的延时和波特率会整体差一倍。
  5. 时钟配错的典型症状：延时不准、串口乱码、USB 不枚举、程序卡在等待晶振就绪——都不是逻辑错误，是频率错了。

一、为什么需要一棵「树」 ​

如果所有外设都跑同一个频率，那一个时钟源就够了。但现实是：

  • 性能需求不同：CPU 和 DMA 要最快；UART 只需要几十 kHz 到几 MHz 的时钟来产生波特率；看门狗只需要几十 kHz。
  • 省电是第一约束：不用的外设把时钟关掉，它就几乎不耗电。这是嵌入式低功耗设计最基础的一招。
  • 精度需求不同：USB 和串口通信要求时钟精度在千分之几以内，内部 RC 振荡器（误差 1%~2%）做不到，必须用外部晶振。

于是芯片设计成：一个（或几个）时钟源 → PLL 倍频 → 多路分频器 → 分发给各外设，中间每个节点都有开关。这棵树由 RCC（Reset and Clock Control，复位与时钟控制）模块管理。

二、五个时钟源 ​

时钟源频率精度用途
HSI 高速内部8 MHz（F1）/ 16 MHz（F4）差（±1%~2%，受温漂影响）上电默认时钟；HSE 失效时的备份
HSE 高速外部通常 4~25 MHz（板载晶振）高（几十 ppm）主时钟源，经 PLL 倍频到系统主频
LSI 低速内部约 40 kHz很差独立看门狗 IWDG
LSE 低速外部32.768 kHz高RTC 实时时钟（钟表晶振）
PLL 锁相环—跟随输入倍频器，把 8 MHz 变成 72 MHz / 168 MHz

PLL 不是独立的振荡器，它必须以 HSI 或 HSE 为输入做倍频。所以「用 PLL」永远要先有一个输入源。

上电后的默认状态 ​

芯片复位后跑在 HSI（F103 上就是 8 MHz 直接当 SYSCLK，不分频不倍频）。这意味着你不配时钟，程序照样能跑，只是主频是 8 MHz 而不是 72 MHz——于是所有基于时间的计算（延时、波特率、PWM 频率）都会差 9 倍。这是新手「程序跑了但串口全是乱码」的经典原因。

三、F103 的时钟树路径 ​

时钟树的整体结构与 ×2 规则见 。以最经典的 F103 + 8 MHz 晶振配置为例，整条链路是这样：

HSE 8 MHz ──[PLL ×9]──→ SYSCLK 72 MHz ──[AHB ÷1]──→ HCLK 72 MHz ──┬──[APB1 ÷2]──→ PCLK1 36 MHz ──(TIM×2)──→ TIM2~7 实际 72 MHz
                                                                   └──[APB2 ÷1]──→ PCLK2 72 MHz ──(不×2)──→ TIM1 实际 72 MHz

各总线上挂什么（F103）：

总线最高频率典型外设
AHB（HCLK）72 MHz内核、内存、DMA、CRC
APB2（PCLK2）72 MHz（高速）GPIO、AFIO、ADC、USART1、SPI1、TIM1、TIM8
APB1（PCLK1）36 MHz（低速）TIM2~7、USART2/3、SPI2/3、I²C、CAN、USB、DAC、看门狗

注意 APB1 的上限只有 36 MHz（F103），所以它必须至少二分频。这就是为什么挂在 APB1 上的外设（USART2、TIM2~7）时钟比 APB2 上的慢一半——选串口、选定时器时要先看它挂在哪条总线上。

例 1 · 把 F103 配到 72 MHz，算出各路时钟

已知：外部晶振 HSE = 8 MHz，PLL 倍频 ×9，AHB 不分频，APB1 二分频，APB2 不分频。

SYSCLK=8 MHz×9=72 MHz\text{SYSCLK} = 8\ \text{MHz} \times 9 = 72\ \text{MHz} SYSCLK=8 MHz×9=72 MHzHCLK=72÷1=72 MHz\text{HCLK} = 72 \div 1 = 72\ \text{MHz} HCLK=72÷1=72 MHzPCLK1=72÷2=36 MHz（未超过36 MHz上限）\text{PCLK1} = 72 \div 2 = 36\ \text{MHz}\quad（未超过 36\ \text{MHz} 上限） PCLK1=72÷2=36 MHz（未超过36 MHz上限）PCLK2=72÷1=72 MHz\text{PCLK2} = 72 \div 1 = 72\ \text{MHz} PCLK2=72÷1=72 MHz

定时器时钟（关键一步）：APB1 的预分频是 2（≠1），所以挂在 APB1 上的定时器时钟要 ×2：

TIM2 7 时钟=36×2=72 MHz\text{TIM2~7 时钟} = 36 \times 2 = 72\ \text{MHz} TIM2 7 时钟=36×2=72 MHz

APB2 预分频是 1，不 ×2，所以 TIM1 时钟 = 72 MHz。

结论：虽然 APB1 总线本身只有 36 MHz，但 TIM2~7 仍能以 72 MHz 计数——算定时周期时用的是 72 MHz 而不是 36 MHz。

四、外设时钟使能（最容易漏的一步） ​

时钟树配好了只是「时钟到达了总线」，每个外设还有自己的最后一级开关，在 RCC 的使能寄存器里：

c
// F103：APB2 外设使能寄存器 RCC->APB2ENR
RCC->APB2ENR |= (1 << 2);    // IOPAEN：GPIOA 时钟
RCC->APB2ENR |= (1 << 4);    // IOPCEN：GPIOC 时钟
RCC->APB2ENR |= (1 << 14);   // USART1EN：USART1 时钟

// HAL 写法（推荐，可读性好）
__HAL_RCC_GPIOA_CLK_ENABLE();
__HAL_RCC_USART1_CLK_ENABLE();
__HAL_RCC_TIM2_CLK_ENABLE();

忘了使能的症状：配置代码全部正确、寄存器也写了，但外设毫无反应，而且不报错。因为对未使能时钟的外设寄存器写入，硬件根本不响应。

五、定时器时钟为什么会自动 ×2 ​

这是 F1/F4 系列一个反直觉的硬件设计：当 APB 预分频系数为 1 时，定时器时钟 = PCLK；否则定时器时钟 = PCLK × 2。

用意是：即使你把 APB1 分频降到 36 MHz 来省电，定时器仍能拿到 72 MHz 的高分辨率，不至于因为省电而牺牲定时精度。

这条规则的实战影响：

  • 算定时周期、PWM 频率时，用的时钟是**×2 之后的值**；
  • 算 UART 波特率时，用的却是**×2 之前的 PCLK**（USART 不在 ×2 之列，只有定时器享受这个待遇）——同一个 APB1 上，定时器和串口用的时钟不一样，这是最容易算混的地方。

六、F4 系列的时钟树差异 ​

F4（如 F407）把 PLL 拆得更细，多了两级分频：

HSE 8 MHz ──[÷M]──→ 1 MHz ──[×N]──→ VCO 336 MHz ──[÷P]──→ SYSCLK 168 MHz
                                        └──[÷Q]──→ USB/SDIO 所需 48 MHz
参数约束
M 输入分频使 PLL 输入落在 1~2 MHz（推荐 2 MHz 以内）
N 倍频使 VCO 输出落在 100~432 MHz
P 输出分频取 2 / 4 / 6 / 8，决定 SYSCLK（F407 上限 168 MHz）
Q 分频给 USB OTG、SDIO 用，需得到 48 MHz

例 2 · 把 F407 配到 168 MHz

HSE = 8 MHz，取 M = 8，N = 336，P = 2：

PLL 输入=8÷8=1 MHz(在 1\sim2 MHz 内✓)\text{PLL 输入} = 8 \div 8 = 1\ \text{MHz}\quad(\text{在 1\sim2 MHz 内} \checkmark) PLL 输入=8÷8=1 MHz(在 1\sim2 MHz 内✓)VCO=1×336=336 MHz(在 100\sim432 MHz 内✓)\text{VCO} = 1 \times 336 = 336\ \text{MHz}\quad(\text{在 100\sim432 MHz 内} \checkmark) VCO=1×336=336 MHz(在 100\sim432 MHz 内✓)SYSCLK=336÷2=168 MHz(等于上限✓)\text{SYSCLK} = 336 \div 2 = 168\ \text{MHz}\quad(\text{等于上限} \checkmark) SYSCLK=336÷2=168 MHz(等于上限✓)

再配 AHB 不分频、APB1 四分频、APB2 二分频：

HCLK=168 MHz,PCLK1=168÷4=42 MHz (≤42✓),PCLK2=168÷2=84 MHz (≤84✓)\text{HCLK} = 168\ \text{MHz},\quad \text{PCLK1} = 168 \div 4 = 42\ \text{MHz}\ (\leq 42 \checkmark),\quad \text{PCLK2} = 168 \div 2 = 84\ \text{MHz}\ (\leq 84 \checkmark) HCLK=168 MHz,PCLK1=168÷4=42 MHz (≤42✓),PCLK2=168÷2=84 MHz (≤84✓)

此时 APB1 分频 = 4（≠1），所以 TIM2~7 时钟 = 42 × 2 = 84 MHz；APB2 分频 = 2（≠1），TIM1 时钟 = 84 × 2 = 168 MHz。

检查约束是必须的：VCO 超 432 MHz 或 PLL 输入不在 1~2 MHz，芯片可能根本起不来，且症状是「程序不跑」而非报错。

七、从时钟到定时与 PWM ​

定时器时钟确定后，定时周期和 PWM 频率就由两个寄存器决定：

  • PSC（预分频）：把定时器时钟再分一次，得到计数频率 fcnt=fTIM/(PSC+1)f_{cnt} = f_{TIM} / (PSC + 1)fcnt​=fTIM​/(PSC+1)
  • ARR（自动重装载）：计数器数到 ARR 就溢出/重装，周期 T=(ARR+1)/fcntT = (ARR + 1) / f_{cnt}T=(ARR+1)/fcnt​

例 3 · 用 72 MHz 定时器做 1 ms 定时

取 PSC = 71、ARR = 999：

fcnt=72 MHz71+1=1 MHzf_{cnt} = \frac{72\ \text{MHz}}{71 + 1} = 1\ \text{MHz} fcnt​=71+172 MHz​=1 MHzT=999+11 MHz=1 msT = \frac{999 + 1}{1\ \text{MHz}} = 1\ \text{ms} T=1 MHz999+1​=1 ms

注意所有公式里的 +1：分频器和计数器都是「数到设定值再加一」，写成 PSCPSCPSC 而不是 PSC+1PSC+1PSC+1 是高频错误。

顺带得到 PWM：同一定时器下，PWM 频率 = fcnt/(ARR+1)=1 MHz/1000=1 kHzf_{cnt} / (ARR+1) = 1\ \text{MHz} / 1000 = 1\ \text{kHz}fcnt​/(ARR+1)=1 MHz/1000=1 kHz。要让占空比为 30%，比较寄存器取：

CCR=(ARR+1)×30%=1000×0.3=300\text{CCR} = (ARR + 1) \times 30\% = 1000 \times 0.3 = 300 CCR=(ARR+1)×30%=1000×0.3=300

对应高电平时间 300/1 MHz=300 μs300 / 1\ \text{MHz} = 300\ \mu\text{s}300/1 MHz=300 μs。

八、工程实例：波特率误差是怎么来的 ​

串口的波特率由 PCLK 分频得到（16 倍过采样）：DIV=fPCLK/(16×baud)\text{DIV} = f_{PCLK} / (16 \times \text{baud})DIV=fPCLK​/(16×baud)。DIV 通常不是整数，硬件只能取「整数部分 + 4 位小数部分」，于是产生误差。

例 4 · 算两个串口在 115200 下的实际误差

USART1（挂 APB2，PCLK2 = 72 MHz）：

DIV=72×10616×115200=39.0625\text{DIV} = \frac{72 \times 10^6}{16 \times 115200} = 39.0625 DIV=16×11520072×106​=39.0625

整数 39、小数 0.0625 = 1/161/161/16，硬件恰好可以精确表示，所以实际波特率就是 115200，误差 0%。

USART2（挂 APB1，PCLK1 = 36 MHz）：

DIV=36×10616×115200=19.53125\text{DIV} = \frac{36 \times 10^6}{16 \times 115200} = 19.53125 DIV=16×11520036×106​=19.53125

小数部分 0.53125 无法用 4 位小数（1/16 = 0.0625 的步长）精确表示，最接近的是 9/16=0.56259/16 = 0.56259/16=0.5625，于是实际分频为 19.5625：

实际波特率=36×10616×19.5625≈115016 bps\text{实际波特率} = \frac{36 \times 10^6}{16 \times 19.5625} \approx 115016\ \text{bps} 实际波特率=16×19.562536×106​≈115016 bps

误差约 −0.16%。这个值远小于串口允许的 ±2%~3% 容差，通信完全正常——但它说明了为什么有些「奇怪的波特率」在某些主频下会乱码：当误差累积超过容差（尤其是长帧、高波特率时），采样点就会滑到错误的位置。

实用结论：串口通信出问题，先确认「这条 USART 挂在哪条总线、当前 PCLK 是多少」，再算误差，而不是先怀疑代码。

九、易错清单 + 自检 ​

  • [ ] 忘记开外设时钟：__HAL_RCC_xxx_CLK_ENABLE()，症状是配置全对但外设不动
  • [ ] 以为不配时钟就是 72 MHz：上电默认是 HSI（8 MHz），必须手工配置时钟树
  • [ ] 定时器时钟忘了 ×2：APB 分频 ≠ 1 时要乘 2，导致延时/频率差一倍
  • [ ] 把定时器的 ×2 规则套到串口上：USART 用的是 PCLK 本身，不 ×2
  • [ ] PSC / ARR 公式忘了 +1
  • [ ] 超过总线频率上限：F103 的 APB1 ≤ 36 MHz、APB2 ≤ 72 MHz；F407 的 APB1 ≤ 42 MHz、APB2 ≤ 84 MHz
  • [ ] F4 的 VCO 不在 100~432 MHz、PLL 输入不在 1~2 MHz：芯片可能直接起不来
  • [ ] HSE 晶振不起振：SystemClock_Config() 死等在等待就绪的循环里，先切 HSI 定位

自检：F103 用 8 MHz 晶振配到 72 MHz 时，PCLK1 是多少？TIM3 的实际计数时钟是多少？USART2 配置波特率时用的时钟又是多少？（答案：36 MHz；72 MHz（×2）；36 MHz（不 ×2））

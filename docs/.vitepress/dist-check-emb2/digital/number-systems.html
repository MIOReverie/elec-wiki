01 · 数制与编码 ​

核心 约 25 min二进制、补码、BCD——数字电路的『字母表』

这一页要解决什么：数字芯片里一切信息最终都是 0/1，但人类写的是十进制、算的是加减乘除。这一页解决「同一串 0/1 到底表示什么」——是数字、是负数、还是「某位十进制数字」。读完你应该能：在二进制 / 十进制 / 十六进制之间互转、用补码把减法变成加法、并分清 BCD 和二进制这两种长得像却完全不同的编码。

读这页之前

  • 需要会：十进制加减与「除 2 取余」这类基础算术（小学水平），本页不依赖任何电路前置。
  • 这一页用到的符号与约定：0b 表二进制、0x 表十六进制（如 0b1010=10、0xFF=255）；上划线 A‾\overline{A}A 表示逻辑非；位权、基数等术语见正文定义，其余统一约定见符号与约定。

你按下计算器算 0.1 + 0.2，屏幕却显示 0.30000000000000004；你在 C 语言里写 unsigned char x = 255; x++;，x 却莫名其妙变回 0。两件看似无关的小事，根子都在同一处：计算机只用 0/1 工作，而「一串 0/1 怎么翻译成你能懂的数」有一整套约定。这一页就把这套约定讲清楚。

结论先行 ​

  1. 数字电路只用 0/1：不是因为「数只能这么表示」，而是电子开关天然只有通/断两态，且二值系统抗干扰最强。
  2. 三种互转是基本功：二进制 ↔ 十进制（按权展开 / 除 2 取余）；二进制 ↔ 十六进制（每 4 位一组，因为 16=2416 = 2^416=24）。
  3. 负数用补码（一种让「减法变加法」的编码）：补码让「减法变加法、0 只有一种写法」，CPU 因此只需一套加法器。
  4. BCD（Binary-Coded Decimal，用 4 位二进制表示 1 位十进制数字）不是二进制：(182)10(182)_{10}(182)10​ 的 BCD 是 0001 1000 0010，而它的二进制是 10110110——两者完全不同。
  5. 格雷码 / 奇偶校验解决的是「传输和采样时少出错」，不是算术问题。

一、为什么是二进制 ​

这一节先回答「为什么电路不用十进制而用二进制」——根子不在数学，在物理实现。

十进制 (357)10(357)_{10}(357)10​ 的意思是：

(357)10=3×102+5×101+7×100(357)_{10} = 3\times 10^2 + 5\times 10^1 + 7\times 10^0 (357)10​=3×102+5×101+7×100

这里 101010 叫基数（radix，即「每位满几进一」的底数），10k10^k10k 叫第 kkk 位的位权（这一位上的 1 实际代表多大的数）。换成任意基数 RRR 都同理：

(anan−1⋯a0)R=∑k=0nakRk(a_n a_{n-1}\cdots a_0)_R = \sum_{k=0}^{n} a_k R^k (an​an−1​⋯a0​)R​=k=0∑n​ak​Rk

数字电路偏要用 R=2R=2R=2，根本原因是物理实现：三极管导通≈1、截止≈0；两个电平之间再容得下噪声，比区分十个电平稳得多。所以一切数据进芯片前都要先变成 0/1 串。

到这里我们接受了「电路用二进制」这件事；但二进制和人类习惯的十进制之间怎么对上号，就是下一节要解决的问题。

二、进制互转 ​

这一节只做一件事：在二进制、十进制、十六进制之间来回转换，并讲清为什么「每 4 位二进制恰好对应 1 位十六进制」。

二进制 ↔ 十进制 ​

  • 二转十：按权展开。(10110110)2=1⋅27+0+1⋅25+1⋅24+0+1⋅22+1⋅21=128+32+16+4+2=182(10110110)_2 = 1{\cdot}2^7 + 0 + 1{\cdot}2^5 + 1{\cdot}2^4 + 0 + 1{\cdot}2^2 + 1{\cdot}2^1 = 128+32+16+4+2 = 182(10110110)2​=1⋅27+0+1⋅25+1⋅24+0+1⋅22+1⋅21=128+32+16+4+2=182。
  • 十转二：除 2 取余，倒序排列。

二进制 ↔ 十六进制 ​

因为 16=2416 = 2^416=24，所以二进制每 4 位恰好对应十六进制 1 位，直接查表替换，不用经过十进制：

例 1 · 把 (3F8)16(3\text{F}8)_{16}(3F8)16​ 转成十进制和二进制

十六进制转十进制按权展开：

(3F8)16=3×162+15×161+8×160=768+240+8=1016(3\text{F}8)_{16} = 3\times 16^2 + 15\times 16^1 + 8\times 16^0 = 768 + 240 + 8 = 1016 (3F8)16​=3×162+15×161+8×160=768+240+8=1016

转二进制只需把每位拆成 4 位：3→00113→00113→0011、F→1111\text{F}→1111F→1111、8→10008→10008→1000，得 (0011 1111 1000)2(0011\,1111\,1000)_2(001111111000)2​。 记住「十六进制 ↔ 二进制是一一对应的，十六进制 ↔ 十进制才需要算」。

转完数，真正的麻烦是「负数」——下一节就用补码把这件事收拾干净。

三、带符号数：原码、反码、补码 ​

这一节解决「负数怎么用 0/1 表示」。最直白的三套写法是：原码（符号位 + 绝对值）、反码（原码的数值位逐位取反）、补码（反码 + 1）。下面先把 −5-5−5 的三种 8 位写法摆在一起对比。

用 8 位表示 −5-5−5，有几种写法：

表示法最高位数值位−5-5−5 的 8 位写法问题
原码符号（1=负）绝对值1000 01010 有两种：0000 0000 / 1000 0000
反码符号绝对值按位取反1111 10100 仍有两种
补码符号反码 + 11111 10110 唯一，减法可化加法

补码的核心思想是「模运算」：在 8 位里模是 28=2562^8=25628=256。一个负数 −x-x−x 的补码 = 256−x256 - x256−x。于是 a−b=a+(256−b)a - b = a + (256 - b)a−b=a+(256−b)，减法消失了，只剩加法。

例 2 · 用 8 位补码算 75−3875 - 3875−38

先把两数写成补码：75=0100 101175 = \texttt{0100 1011}75=0100 1011，38=0010 011038 = \texttt{0010 0110}38=0010 0110。 −38-38−38 的补码 = 38 取反加 1 = 1101 1010\texttt{1101 1010}1101 1010。 相加：

  0100 1011   (75)
+ 1101 1010   (−38 的补码)
------------
1 0010 0101   (9 位，最高位溢出丢弃)

取低 8 位 0010 0101=37\texttt{0010 0101} = 370010 0101=37。结果正是 75−38=3775-38=3775−38=37，且过程中没有任何「减法器」参与。

补码的两个坑

  • 符号位也是数值的一部分：1111 1111 在 8 位补码里是 −1-1−1，不是 255。同一个二进制串，「当作无符号」和「当作有符号」结果可能差很远（试在下面的转换器输入 255 看 8 位补码解读）。
  • 溢出：两个同号数相加可能超出表示范围（如 127+1127+1127+1 在 8 位里变成 −128-128−128）。判断溢出要看「符号位进位」与「最高数值位进位」是否相同，不能只看结果。

补码把减法变成了加法，这正是下一节那个实时转换器「一个输入框算尽所有表示」的底气。

看清了补码和 BCD 的区别，下一节看它们之外还有哪些「0/1 表示法」。

五、编码（不是数制，是「怎么用 0/1 表示别的东西」） ​

这一节讲几类「不是数制、却是 0/1 表示法」的编码：BCD、格雷码、奇偶校验。它们解决的不是「怎么算」，而是「怎么存、怎么传才不易错」。

BCD 码（8421 码） ​

用 4 位二进制表示 1 位十进制数字（0∼90\sim90∼9），常用于数码管显示。

例 3 · BCD 与二进制的区别

(182)10(182)_{10}(182)10​ 的 BCD 是 0001 1000 0010（每位十进制单独编 4 位）。 但同样是这串 1001 0110，如果按二进制读，它是 128+16+4+2=150128+16+4+2 = 150128+16+4+2=150。 所以「一串 0/1 是什么」完全取决于你怎么解读它——这正是数字系统里「约定」的重要性。

格雷码（Gray code） ​

相邻两个十进制数对应的格雷码只有一位不同。用途：光电编码器、状态机跳转时减少「同时变两位导致瞬间误读」的概率。

十进制01234567
二进制000001010011100101110111
格雷码000001011010110111101100

例 4 · 二进制转格雷码，再转回来

把二进制 (1011)2(1011)_2(1011)2​ 转格雷码，规则是最高位照抄，其余每位与左边一位异或：

得格雷码 (1110)2(1110)_2(1110)2​。反过来（格雷码→二进制）是最高位照抄，其余每位用已算出的二进制高位与格雷码位异或：b3=1b_3 = 1b3​=1，b2=1⊕1=0b_2 = 1\oplus1 = 0b2​=1⊕1=0，b1=0⊕1=1b_1 = 0\oplus1 = 1b1​=0⊕1=1，b0=1⊕0=1b_0 = 1\oplus0 = 1b0​=1⊕0=1，正好回到 (1011)2(1011)_2(1011)2​。

对照上表检查：十进制 11 不在 0~7 表内，但把 (1110)2(1110)_2(1110)2​ 按上表规律外推，相邻数之间确实只差 1 位——这个性质在编码器里比「算得对」更重要。

奇偶校验 ​

在数据中加 1 位，使「1 的总个数」为奇数（奇校验）或偶数（偶校验）。只能发现奇数个比特出错，不能纠正——纠错要靠更复杂的码（如汉明码）。

六、工程实例 ​

为什么 0.1 加不到 10？ 十进制 0.10.10.1 在二进制里是无限循环小数，存进 64 位浮点时只能近似。于是 0.1 + 0.2 !== 0.3 是 IEEE 754 的必然结果，不是 bug。理解数制，才能理解这类「浮点误差」从何而来。

为什么 CPU 只需要加法器？ 因为补码把减法、甚至乘法（移位加）都统一到加法上。一条 sub 指令在硬件里其实是「取补 + 加法」。

七、易错清单 + 自检 ​

  • [ ] 二进制转十六进制必须从右往左 4 位一组，左边不足 4 位补 0，不是从左分组
  • [ ] BCD 码的每一位上限是 9（1010 在 BCD 里非法），它不是该数的二进制
  • [ ] 补码的最高位参与运算；看一个二进制串的值前先确认「有符号还是无符号」
  • [ ] 原码 / 反码的 0 都有两种写法，补码没有——这是补码胜出的关键
  • [ ] 八进制（232^323）现在较少用，主要出现在老式权限位（如 Linux 755）

建立时间与保持时间 ​

结论先行 ​

  • 触发器在时钟有效沿采样输入。要采得准，输入必须在沿前后各留出一段「稳定时间」：
    • 建立时间 tsut_{su}tsu​：时钟沿之前，数据必须已经稳定的最短时间；
    • 保持时间 tht_hth​：时钟沿之后，数据必须继续稳定的最短时间。
  • 时钟周期必须满足 Tclk>tsu+tCC+thT_{clk} > t_{su} + t_{CC} + t_hTclk​>tsu​+tCC​+th​，其中 tCCt_{CC}tCC​ 是时钟到输出延迟（时钟沿到 Q 端翻转的时间）。
  • 保持时间违例最危险：它不能靠降频解决，只能靠设计（换器件、调整数据路径、加一级锁存）。
  • 触发器进入亚稳态时，输出可能在阈值附近停留 arbitrarily 久，随后随机落到 0 或 1——这就是数字设计里「偶发、不可复现」的一类故障。

为什么它承重：现代数字系统的主频瓶颈往往不是逻辑深度，而是建立/保持时间余量。不懂这一条，配再快的时钟也只会得到一片随机数据。

常见坑 ​

  • 只查建立时间、忘了保持时间：数据路径上某个寄存器的 tht_hth​ 较大时，降频反而可能改善建立时间却恶化保持时间的相对余量。
  • 把 tCCt_{CC}tCC​ 漏掉：数据必须在上一个沿就稳定，时序分析是「沿到沿」而不是「沿到沿加一段」。
  • 组合逻辑延迟太短（没插延迟单元）反而让保持时间违例——因为下一个沿来得太快，前一个沿的旧数据还没走远。
  • 跨时钟域时把「亚稳态」当作小概率事件：它持续时间可能到微秒级，恢复逻辑必须能处理。

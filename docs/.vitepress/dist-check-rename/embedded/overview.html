01 · 嵌入式与 STM32 概览 ​

了解 约 25 min先搞清楚「什么是嵌入式、为什么选 STM32、型号怎么读」，再动手

结论先行 ​

  1. 嵌入式系统 = 藏在设备里、专做一件事的计算机系统。它和 PC 的根本区别不是「小」，而是专用 + 资源受限 + 常常要求实时。
  2. MCU（单片机）和 MPU（应用处理器）是两条路：MCU 一片芯片自带 CPU、内存、Flash 和外设，裸机或 RTOS 直接跑；MPU 需要外挂 DDR 和 Flash，跑 Linux。STM32 属于 MCU。
  3. STM32 = ARM 的 Cortex-M 内核 + 意法半导体（ST）的外设。内核决定算力和指令集，外设决定能接什么。同一个 HAL 库代码在 F1/F4/H7 之间大部分可移植。
  4. 型号命名是有规律的：STM32F103C8T6 每一位都有含义，读懂它就读懂了大半选型信息。
  5. 最小系统四要素：电源、复位、时钟、调试下载口。任何一块能跑的板子都少不了这四样。

一、什么是嵌入式系统 ​

一个系统只要满足「以计算机为核心、但用户并不知道里面有个计算机」，就是嵌入式。洗衣机、电表、遥控器、汽车 ECU 都是；手机、PC 不是——后者的计算机本身就是产品。

这个定位带来四条硬约束，它们决定了后面所有设计取舍：

约束具体表现导致的工程习惯
专用只做固定的几件事不需要通用 OS，裸机或轻量 RTOS 即可
资源受限Flash 几十 KB、RAM 几 KB 到几百 KB不能随便 malloc，栈要算着用，避免递归
实时性必须在确定时间内响应中断要快进快出，不能随便关中断
低功耗/成本电池供电、百万量产出货睡眠模式、关不用的外设时钟、抠每一分钱 BOM

这四条不是「特点」，而是约束条件——后面每一章的配置（为什么开时钟、为什么用 DMA、为什么要睡眠）都能追溯到这四条之一。

二、MCU、MPU 与 SoC ​

这三个词经常被混用，区分标准很实际：看内存是不是在芯片里面。

类型内存典型主频跑什么例子
MCU 微控制器片内 Flash + SRAM，上电就能跑几十 ~ 几百 MHz裸机循环 / RTOS（FreeRTOS、RT-Thread）STM32F103、GD32、ESP32（MCU 部分）
MPU 微处理器需外挂 DDR、eMMC，上电要先跑 U-Boot几百 MHz ~ 几 GHzLinux / Android树莓派（博通）、全志、瑞芯微、NXP i.MX
SoC 片上系统看情况—强调「把整个系统集成进一颗芯片」手机芯片、STM32MP1（Cortex-A + Cortex-M 双核）

本课程在 MCU 这条线上。判断该用哪条的实用标准：需要跑 Linux、需要网络协议栈/文件系统/复杂 UI → MPU；只需要定时、采集、控制、简单通信 → MCU。

三、ARM Cortex-M 内核 ​

ARM 自己不造芯片，它卖内核设计（IP），ST、NXP、GD、TI 买过去加上自己的外设做成芯片。所以「STM32」和「Cortex-M」是两个层次的东西：

  • Cortex-M 内核：CPU 本身——寄存器、指令集（Thumb-2）、中断控制器 NVIC、调试接口。
  • 外设：GPIO、定时器、ADC、UART、SPI、I²C、DMA……这些是 ST 自己设计的，不同系列差异很大。

常见 M 系列内核：

内核定位关键特性代表
M0 / M0+超低成本、低功耗最简单，无除法指令优化F0、L0、G0
M3经典主力性能与成本平衡，生态最老F1（F103）
M4带 DSP 与浮点单精度 FPU，适合电机控制、音频、滤波F4（F407）、F3
M7高性能双精度 FPU、Cache、更高主频F7、H7

和经典 8 位单片机（如 8051、AVR）的本质差别是位宽与地址空间：32 位数据通路、32 位地址（4 GB 线性地址空间，实际只用了其中一小段放 Flash/SRAM/外设）。这意味着算一个数不用再拆成多次 8 位运算，指针可以直接访问整个空间。

四、读懂 STM32 的型号 ​

型号不是随机字符串，每一位都有含义。以最经典的 STM32F103C8T6 为例：

STM32  F   103   C    8    T    6
 │     │    │    │    │    │    └─ 温度范围：6 = −40~85℃
 │     │    │    │    │    └────── 封装：T = LQFP，H = BGA，U = VFQFPN
 │     │    │    │    └─────────── Flash 容量：8 = 64 KB，B = 128 KB，Z = 384 KB…
 │     │    │    └──────────────── 引脚数：C = 48 脚，R = 64 脚，V = 100 脚，Z = 144 脚
 │     │    └───────────────────── 子系列：103 = 基础型，407 = 高性能，411…
 │     └────────────────────────── 产品类别：F = 基础/通用，L = 低功耗，H = 高性能，W = 无线
 └──────────────────────────────── 家族：STM32

主流系列怎么选：

系列内核主频特点适合
F1（F103）M372 MHz最老牌、资料最多、最便宜入门学习、成本敏感的量产
F4（F407）M4168 MHz带 FPU、外设更全需要浮点运算/电机/音频
L4 / L0M4 / M0+80 MHz低功耗为设计目标电池供电
H7M7400 MHz+高性能、带 Cache复杂 UI、高速采集
G0 / G4M0+ / M464 / 170 MHz新架构，性价比替代 F1新设计选型
WB / WLM4 + 无线—片内蓝牙 / LoRa物联网节点

例 1 · 读型号，说出它是什么芯片

型号 STM32F103C8T6：F = 通用基础型，103 = 基础型子系列（Cortex-M3，最高 72 MHz），C = 48 个引脚，8 = 64 KB Flash，T = LQFP 封装，6 = 工业级温度（−40~85℃）。

这就是俗称「蓝色药丸」的最小系统板上那颗芯片：48 脚、64 KB Flash、20 KB SRAM。它之所以成为入门首选，不是因为性能强，而是因为资料最多、最便宜、坏了不心疼。

再看 STM32F407VET6：F4 = 高性能带 FPU，V = 100 脚，E = 512 KB Flash，T = LQFP。 cortex-M4 内核、168 MHz，是本课程讲时钟树和 DMA 时的另一个参照。

五、选型时到底看什么 ​

选型不是比参数表，而是回答四个问题：

  1. 算力够不够：要跑浮点滤波/电机 FOC → 必须有 M4 的 FPU；只是采数据发串口 → M0 都够。
  2. 存储够不够：Flash 放代码和常量，RAM 放全局变量、栈、堆和 RTOS 任务栈。按最坏情况估，并留 30% 以上余量。
  3. 外设对不对得上：需要几路 UART？要 CAN 吗？ADC 要几通道、多少位？USB 是 Device 还是 Host？
  4. 供货与成本：量产项目里，供货稳定性和价格往往比性能更重要——这也是 F103 至今仍在大量出货的原因。

例 2 · 估算一个项目的资源够不够

某项目需求：采集 4 路传感器（ADC）、驱动一块 OLED（I²C）、串口上报（UART）、跑 FreeRTOS 管理 3 个任务。选 STM32F103C8T6（64 KB Flash / 20 KB SRAM）够吗？

估 RAM（最容易先爆的）：

用途估算
3 个 RTOS 任务栈，每个 512 字节1.5 KB
FreeRTOS 内核与堆约 4 KB
串口收发缓冲 + OLED 显存（128×64/8 = 1 KB）约 2 KB
全局变量、ADC 缓冲约 1 KB
小计约 8.5 KB

20 KB 装 8.5 KB，余量约 57%，够。但如果把任务栈加到 1 KB、再开一路 DMA 双缓冲，就会逼近 15 KB，此时应换 CBT6（128 KB Flash）或 RCT6（64 脚 / 256 KB Flash）同级更大容量的型号。

估 Flash：带 HAL 库 + FreeRTOS 的工程中等规模约 40~60 KB，64 KB 会比较紧张，建议上 128 KB。结论：这个需求选 STM32F103CBT6（128 KB）更稳妥。

六、最小系统：让一颗裸片跑起来需要什么 ​

一颗 STM32 芯片焊到板上，还必须有这四部分才能工作：

  1. 电源：VDD/VSS 多组引脚都要接，每组旁边放 100 nF 去耦电容（靠近引脚），再并一个 10 µF 的储能电容。
  2. 复位：NRST 引脚，通常 10 kΩ 上拉 + 100 nF 到地构成上电复位（很多芯片内部已有上拉，外部可简化）。
  3. 时钟：8 MHz 晶振（HSE）+ 两个负载电容（通常 20 pF 量级，具体看晶振要求）；RTC 另配 32.768 kHz。不用外部晶振也能跑（用内部 HSI），但精度差、波特率容易出问题。
  4. 调试下载口：SWD 只需两根线（SWDIO、SWCLK）+ GND，比 JTAG 省引脚，是 ST-Link 的标准接法。再引出 VCC 即可给目标板供电（或由目标板自供电）。

另外还有 BOOT0/BOOT1 引脚决定上电从哪里启动：BOOT0 = 0 从主 Flash 启动（正常工作），BOOT0 = 1 进入系统 BootLoader（可用串口下载程序，即 ISP）。

例 3 · 拿到一块新板子，先确认什么

一块陌生的 STM32 板子，按这个顺序确认，能避开 80% 的「下载不进去」：

  1. BOOT0 是否为低电平（从 Flash 启动）——如果 BOOT0 被意外拉高，程序下载成功也不会运行。
  2. SWD 四根线是否连通：SWDIO、SWCLK、GND，以及 VCC（用于电平参考，不一定要供电）。
  3. 供电电压是 3.3 V 还是 5 V：STM32 的 IO 多数是 3.3 V 电平、5 V 容忍（标 FT 的引脚才容忍 5 V），接错会烧。
  4. 外部晶振是否焊接——很多最小系统板的 8 MHz 晶振是贴片焊死的，但便宜板子可能用的是精度较差的晶振，导致串口通信误码。

七、工程实例 ​

为什么 2026 年了还有大量产品在用 2007 年发布的 F103？ 因为它已经不是「一款芯片」，而是一个生态：十几年的中文教程、成熟的原理图、大量已验证的代码、极低的单价和极稳的供货。工程选型里，「能被稳定复现」往往比「参数漂亮」更有价值。反过来，全新项目如果不需要兼容老代码，G0/G4 系列在价格和功耗上都更划算。

为什么很多产品一颗芯片里既有 M4 又有 M0？（如 STM32WB、STM32MP1）因为两类任务的需求是冲突的：无线协议栈要求实时响应，应用逻辑要求算力。用一个小核专门跑协议栈、一个大核跑应用，比在一个核上硬挤要可靠得多——这和后面讲 RTOS 的「任务分离」是同一个思路。

八、易错清单 + 自检 ​

  • [ ] MCU 和 MPU 的区别是「内存是否在片内」，不是主频高低
  • [ ] Cortex-M 是内核，不是芯片：同样是 M4，ST 和 NXP 的外设完全不同，外设代码不能直接搬
  • [ ] STM32 的 IO 是 3.3 V 电平，只有标注 FT 的引脚才容忍 5 V；接 5 V 器件要做电平转换
  • [ ] 型号里的 Flash 容量码不是乘数：8 = 64 KB、B = 128 KB、C = 256 KB、E = 512 KB，需要查表，不能猜
  • [ ] BOOT0 拉高会进 BootLoader，此时下载成功也不会运行用户程序（非常常见的「程序没跑」原因）
  • [ ] 选型时先看 RAM 再看 Flash：带 RTOS 和协议栈的项目，RAM 往往先不够

自检：不看上表，说出 STM32F103C8T6 的内核、主频、引脚数、Flash 容量；并说明一个 MCU 最小系统必须包含哪四部分。（答案：Cortex-M3 / 72 MHz / 48 脚 / 64 KB；电源、复位、时钟、调试下载口）

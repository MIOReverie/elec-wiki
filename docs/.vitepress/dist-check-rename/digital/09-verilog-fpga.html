09 · 从逻辑到芯片：Verilog 与 FPGA 入门 ​

了解 约 40 min从纸面逻辑到并行硬件：Verilog 是在写电路，不是在写程序

前八章的所有结论都在纸面上：卡诺图化简出一个与或式，触发器画一个特性方程，计数器数出模值。这一章只解决一个衔接问题——把这些纸面结论变成一块真芯片里同时运转的硬件。不涉及 PCB 与电源，只讲「写成什么样」「为什么会跑不起来」「为什么偶尔出错一次」。

结论先行 ​

  1. Verilog 描述的是电路，不是执行流程。一段 always 块综合出来是一堆同时工作的触发器与门电路，而不是 CPU 一条条跑的指令。单片机（MCU）按程序计数器顺序执行，一次一条；FPGA 里每条数据通路同一时刻都在各自干活。
  2. always @(posedge clk) 里的赋值用非阻塞 <=，组合逻辑里用阻塞 =。这一条如果踩错，仿真和综合结果对不上，是新手最常见的「玄学 bug」。
  3. 时序逻辑一定带复位，异步复位 posedge rst_n 或同步复位，二选一但全项目统一；复位了就一定能从确定的初态启动。
  4. 跨时钟域的单个信号，必须先过两级触发器同步器；多比特数据用 FIFO 或握手，绝不用两级同步器硬搬。亚稳态不可消除，只能把它的影响概率压到工程可接受。
  5. FPGA 流程是 综合 → 布局布线 → 时序约束 → 下载，其中时序约束决定工具是不是真的按 100 MHz 去努力；没有约束的 100 MHz 只是「时钟发生器输出了 100 MHz」。
  6. 跑不到目标频率，九成是组合逻辑太长或时钟扇出太大；先看时序报告的关键路径，再决定插流水级、改用 DSP 乘法器，还是把大计数器拆开。频率不是靠改约束堆上去的。

一、为什么数电学完还要学这个 ​

前八章的结论都是「在纸上算出来」的：卡诺图圈格子得到化简式，触发器代特性方程得到次态，计数器排时序图数出模值。这些都对，但它们只告诉你「逻辑关系是什么」，没有回答「这个逻辑怎么变成一块能同时跑几十、几百路的硬件」。

真正的差别：并行与顺序

  • 单片机是「一个人按清单干活」：取指 → 译码 → 执行，一条指令占一个或几个机器周期，顺序推进。想看 8 路 ADC 同时采样？它其实是轮流切通道，靠 ADC 采样保持电容顶一下。
  • FPGA 是「一排工人同时干活」：你写的每一条数据通路都是独立的门电路与触发器，只要时钟一响，它们全部同时更新；8 路 ADC 接 8 个不同的引脚，就是真的 8 路并行。

这个差别带来三个具体后果，决定了「为什么卡诺图不够用」：

维度单片机（STM32 一类）FPGA
执行模型顺序执行，一次一条空间并行，所有通路同时工作
时间精度微秒级，受中断与 RTOS 调度抖动纳秒级，由时钟周期直接决定
灵活性改硬件要换芯片、改电路板改逻辑只需改代码、重新下载
功耗与成本小系统极便宜入门板卡门槛高，大芯片很贵
适合做什么控制流程、人机交互、串口与网络协议栈高速采样、视频处理、电机 FOC、并行 IO

一句话概括：单片机擅长「按顺序处理事件」，FPGA 擅长「同时处理很多路」。一个完整的工程里，两者常常同时出现：FPGA 负责并行采样与预处理，单片机负责通信与人机界面。

学 Verilog ≠ 学编程语言

C 语言里 for (i=0;i<16;i++) y = y + x[i]; 是循环 16 次。Verilog 里写同样一句，综合工具会展开成 16 个加法器串起来——它等价于 16 级组合逻辑，而不是 16 个时钟周期。Verilog 的 for 是「复制电路」的缩写，不是循环。

二、最小 Verilog：三个东西就够了 ​

Verilog 入门其实只需要三块积木：module 包接口、assign 写组合逻辑、always @(posedge clk) 写时序逻辑。

2.1 module 与端口 ​

verilog
// 名字叫 mux2，接口写在括号里
module mux2 (
    input  wire a,      // 输入 A
    input  wire b,      // 输入 B
    input  wire sel,    // 选择：0 选 a，1 选 b
    output wire y       // 输出
);
    assign y = sel ? b : a;   // 组合逻辑：一行就是一层二选一
endmodule

module 是电路块，括号里是它的引脚（端口）。input/output 表示方向，wire 是「连线」——组合逻辑的输出必须用 wire（或 logic + assign）。这里的端口就是一个物理引脚，综合后它会对应到芯片上某个焊盘。

2.2 组合逻辑完整例子：3-8 译码器 ​

前八章组合逻辑讲过 74LS138：3 个输入译成 8 个输出，输出低电平有效。写成 Verilog 是这样：

verilog
module dec3to8 (
    input  wire [2:0] a,     // A2 A1 A0
    input  wire       en_n,  // 使能，低有效
    output reg  [7:0] y_n    // Y7..Y0，低有效
);
    integer i;
    always @(*) begin                    // * 表示「敏感列表自动推断」
        for (i = 0; i < 8; i = i + 1) begin
            // 下标匹配且使能有效时输出 0，否则全 1
            y_n[i] = ~(en_n == 1'b0 && a == i);
        end
    end
endmodule

为什么 always @(*) 里的 for 能行：这不是循环执行，而是生成 8 份电路——综合工具把 i 展开成 8 个常数，得到 8 条「a 等于某个常数」的比较器加一个使能与门。8 个门同时工作，所以一个 3-8 译码器只占几层门延迟。

对照前八章的式子：真值表里「a 等于 5 时只有那一根输出为低」，在代码里就是 a == 5。

2.3 时序逻辑完整例子：带分频的计数器 ​

计数器那一章的结论是「每个时钟沿加 1，计到 N 归零」。Verilog 里写：

verilog
module cnt_div (
    input  wire        clk,     // 50 MHz 系统时钟
    input  wire        rst_n,   // 异步复位，低有效
    output reg  [15:0] cnt,     // 16 位计数器
    output reg         tick     // 每 N 拍出一个时钟周期的脉冲
);
    localparam N = 50000;       // 50 MHz / 50000 = 1 kHz

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin            // 复位：二选一优先级最高
            cnt  <= 16'd0;
            tick <= 1'b0;
        end else if (cnt == N - 1) begin
            cnt  <= 16'd0;
            tick <= 1'b1;
        end else begin
            cnt  <= cnt + 16'd1;
            tick <= 1'b0;
        end
    end
endmodule

这里有三处必须看懂：

  • <= 是非阻塞赋值：右边读的是时钟沿之前的旧值，所有寄存器在本拍末尾同时更新。这正好对应硬件事实——触发器同时被时钟沿触发。
  • posedge clk or negedge rst_n：异步复位，rst_n 一拉低立刻清零，不等时钟。同步复位则写成 always @(posedge clk) + if (!rst_n)，对时钟要求低、但对复位脉冲宽度有要求。
  • N - 1 而不是 N：计数值是 0,1,…,N−1，共 N 个状态，所以 cnt == N-1 是第 N 拍。写成 cnt == N 会多出 N 这一个状态。

2.4 阻塞 vs 非阻塞：一句话原则 ​

组合逻辑用 =，时序逻辑用 <=。原因不是风格，而是它们描述的对象不同：

写法何时生效用例综合结果
阻塞 =语句顺序执行，立刻生效always @(*) 内组合逻辑（门电路）
非阻塞 <=块结束时统一更新always @(posedge clk) 内触发器（时序逻辑）

用 node 手算一遍差别。两段代码都是三个寄存器首尾相接成环，只有赋值方式不同：

下面用 node 把两种写法各推三拍，初值 a=1、b=2、c=0：

text
非阻塞  always @(posedge clk) begin a <= b; b <= c; c <= a; end
沿1: 同时读旧值 -> a=2 b=0 c=1    沿2: a=0 b=1 c=2    沿3: a=1 b=2 c=0   ← 三个值在环里轮转

阻塞    always @(posedge clk) begin a = b; b = c; c = a; end
沿1: a=2(旧b) -> b=0(旧c) -> c=2(新a!)   沿2: a=0 b=2 c=0   沿3: a=2 …   ← c 读到的是刚被改写的 a

结论：非阻塞让三个寄存器在同一沿同时「读旧写新」，结果与语句顺序无关，对应真实的三级触发器；阻塞让后一句读到前一句刚写的新值，结果取决于语句顺序。上例沿 1 的 c 拿到的是「新的 a = 2」而不是旧值 1，整条环路每拍都被短路一次；若把三句顺序改成 c = a; b = c; a = b;，沿 1 立刻变成 a=1、b=1、c=1，结果完全不同。这就是「用阻塞写时序逻辑」的经典坑——仿真结果随书写顺序变，综合后电路可能和你想的也不一样。

三、仿真与时序：让波形说话 ​

仿真是 FPGA 调试的主要手段，比上板找 bug 便宜一百倍。最小 testbench 只要做三件事：产生时钟、施加激励、看输出。

verilog
module tb_cnt_div;
    reg  clk = 0;
    reg  rst_n = 0;
    wire [15:0] cnt;
    wire tick;

    cnt_div uut (.clk(clk), .rst_n(rst_n), .cnt(cnt), .tick(tick));

    always #10 clk = ~clk;   // 20 ns 周期 = 50 MHz

    initial begin
        #25 rst_n = 1;        // 复位保持 25 ns
        #2_000_000 $finish;    // 跑 2 ms，足够看到 2 个 1 kHz tick
    end
endmodule

.clk(clk) 是按名连接，引脚名与线网名各写一遍，比按位置连接安全得多。#10 是延时 10 个时间单位，配合 `timescale 1ns/1ps 就是 10 ns。testbench 里用阻塞赋值完全没问题——它是软件世界，不是在描述电路。

3.1 亚稳态：为什么必须两级同步器 ​

时钟沿到来的一瞬间，如果数据恰好也在翻转，触发器可能既不是 0 也不是 1，输出在中间电平漂一会儿才随机落下——这就是亚稳态。它在单一时钟域内靠建立/保持时间约束可以避免（见 ），但跨时钟域时，源端不知道目的端何时采样，必然偶尔撞上：

一句话原则

跨时钟域的单 bit 控制信号 → 先用两级触发器同步，再用它；多 bit 数据 → 用异步 FIFO 或握手，绝不用两级同步器硬搬。

verilog
module cdc_2ff (
    input  wire clk_b,      // 目的域时钟
    input  wire rst_n,
    input  wire sig_a,      // 来自另一个时钟域的单 bit 信号
    output reg  sig_b       // 已同步
);
    reg mid;
    always @(posedge clk_b or negedge rst_n) begin
        if (!rst_n) begin
            mid   <= 1'b0;
            sig_b <= 1'b0;
        end else begin
            mid   <= sig_a;   // 第一级：可能进入亚稳态
            sig_b <= mid;     // 第二级：再给一个周期恢复时间
        end
    end
endmodule

第一级有概率进入亚稳态，但它有一个完整时钟周期去恢复；到第二级时已经是稳定的 0 或 1。要算的话：单次同步失败的概率约是 e−Tclk/τe^{-T_{clk}/\tau}e−Tclk​/τ，经过两级只剩 e−2Tclk/τe^{-2T_{clk}/\tau}e−2Tclk​/τ。亚稳态不能被消除，只能把 MTBF（平均无故障间隔）提高到比设备寿命长得多，例 3 会把这条算出来。

注意区分两件事：同步器只负责「把单 bit 电平变稳定」，它不负责「数据不丢」。如果源端每个时钟都在丢新数据，同步器再稳也追不上——那种场合要的是 FIFO 缓冲，不是同步器。

3.2 时序分析：建立/保持简单一眼 ​

单个触发器之间一条数据路径，时钟周期至少要装下：源触发器延迟 + 组合逻辑延迟 + 建立时间 + 时钟偏斜。这就是「最高工作频率」的由来：

Tclk≥tcq+tcomb+tsu+tskewT_{clk} \ge t_{cq} + t_{comb} + t_{su} + t_{skew} Tclk​≥tcq​+tcomb​+tsu​+tskew​

其中 tcqt_{cq}tcq​ 是时钟沿到 Q 输出（数据有效）的延迟，tcombt_{comb}tcomb​ 是中间组合逻辑的延迟，tsut_{su}tsu​ 是目的触发器的建立时间，tskewt_{skew}tskew​ 是时钟到达目的触发器的偏斜。保持时间约束走的是另一条路径（tcq+tcomb≥tht_{cq}+t_{comb} \ge t_htcq​+tcomb​≥th​），它与频率无关——降频救不了保持时间违例，这也是 里反复强调的一点。

四、FPGA 开发流程：从代码到芯片 ​

代码写完、仿真通过，还需要四步才能变成芯片里真实的电路：

text
① 综合 Synthesis         Verilog → 门级网表（LUT、触发器、BRAM、DSP 的拼接）
② 布局布线 Place&Route   把网表摆到芯片里具体位置并连好线
③ 时序约束 + 时序分析     告诉工具时钟是多少，检查路径是否满足 T_su / T_h
④ 生成比特流并下载       下载到 SRAM 型 FPGA，掉电丢失；或烧写 Flash 配置

4.1 资源：LUT / FF / BRAM / DSP ​

FPGA 里没有「与门芯片」，只有可编程的资源块：

资源是什么典型用法占比估算
LUTn 输入查找表，4~6 输入最典型，能实现任意 n 输入逻辑组合逻辑、加法器、状态机一个 4 输入与门占 1 个
FF触发器，紧挨着 LUT寄存器、计数器、流水级每一位寄存器占 1 个
BRAM片上块状 RAM，常见 18 Kb / 36 Kb 一块大容量数据缓冲、FIFO、查找表8K×16bit = 16 KiB 要用多块拼
DSP硬核乘法器（18×18 或 25×18）滤波、FFT、电机坐标变换一个 DSP 一拍完成一次乘法

资源怎么估：先数寄存器个数（≈ FF 数），再数组合逻辑层数（≈ LUT 数 × 层数/输入数），最后看大数组用不用 BRAM。一个 8 通道、每通道 16 位、1024 深度的采样缓冲区 = 8×1024×16 bit = 128 Kbit，用 36 Kb 的 BRAM 也要拼上 4 块左右。

4.2 为什么我的设计跑不到 100 MHz ​

时序报告里只会告诉你一句话：关键路径（critical path）太长了。按影响程度排序，跑不到目标频率的原因通常是：

  1. 组合逻辑太深：一个 32 位加法器后面再接 32 位比较，延迟就叠成几十级 LUT，必须插流水级，每级之间放寄存器。
  2. 时钟扇出/偏斜太大：时钟要驱动几千个触发器，偏斜吃掉周期余量。用全局时钟缓冲、别把时钟当普通信号走逻辑门。
  3. 没有写时序约束：不写 create_clock，工具就不知道要跑多快，随便给个结果——约束是承诺，不是愿望。
  4. 高扇出网：一个使能信号扇出几百个触发器，布线延迟拉长。
  5. 异步逻辑与锁存器：工具没法分析，只能给你的路径一个悲观估计。

顺序固定：先看报告 → 找出最慢的那条路径 → 插寄存器或改结构 → 重新跑。降频只是妥协，不是方法。

五、和前八章对照：纸面公式在 Verilog 里长什么样 ​

前八章内容纸面形态Verilog 形态关键差异

5.1 门电路 → assign ​

verilog
assign y = (a & b) | (~a & c);          // 与或式，一行一个组合表达式
assign y2 = (a & b) ^ c;                 // 异或门就是 ^

综合后每个 & 和 | 都落在一个 LUT 里，多层逻辑合并到 4~6 输入。不用你去画卡诺图，但要关心层数：层数多了延迟就大。

5.2 触发器 → always @(posedge clk) ​

verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) q <= 1'b0;      // 异步清零（对应前八章的异步端 R̄_D）
    else        q <= d;          // D 触发器：一拍后 Q = D
end

注意 q <= d 就是 Qn+1=DQ^{n+1}=DQn+1=D，一字不差。

5.3 计数器 → 加 1 与比较 ​

verilog
if (cnt == N - 1) cnt <= 0;
else              cnt <= cnt + 1;

这就是 74LS161 的「置数法/清零法」，只不过比较与清零都在同一拍由综合工具自动完成，不需要外接与非门——同步是默认而不是选项。

七、工程实例：用 FPGA 做 PWM 与舵机信号发生器 ​

嵌入式第 13 章讲过 舵机控制：50 Hz、脉宽 0.5–2.5 ms、角度与脉宽线性。STM32 用定时器 + CCR 实现，FPGA 用计数器 + 比较器——结构上其实是同一件事，只是从「寄存器写数值、硬件比较」变成了「代码直接搭比较逻辑」。

verilog
module servo_pwm (
    input  wire        clk,        // 50 MHz
    input  wire        rst_n,
    input  wire [9:0]  angle,      // 0..1000 对应 -90°..+90°
    output reg         pwm         // 50 Hz 输出
);
    localparam T_20MS = 27'd1_000_000;  // 20 ms = 1,000,000 拍

    reg [26:0] cnt;
    // 0.5 ms 对应 25,000 拍；满量程 2 ms 对应 100,000 拍
    wire [26:0] high = 27'd25_000 + angle * 27'd100;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            cnt <= 27'd0;
            pwm <= 1'b0;
        end else begin
            cnt <= (cnt == T_20MS - 1) ? 27'd0 : cnt + 27'd1;
            pwm <= (cnt < high) ? 1'b1 : 1'b0;
        end
    end
endmodule

几个数字先对一遍：50 MHz 下 20 ms = 1 000 000 拍；0.5 ms = 25 000 拍，2.5 ms = 125 000 拍；角度 −90°…+90° 映射到 500…2500 µs，即 25 000…125 000 拍，量程 100 000 拍对应 180°，每度约 555.6 拍。angle × 100 后从 25 000 起算，angle=1000 正好是 125 000。

并行采样：FPGA 真正的主场 ​

把 8 路 ADC 接到 FPGA 的 8 个引脚，让它们共用同一个采样时钟：

verilog
// 8 路并行采样：每路独立走线，但共用 clk 与同一拍
genvar k;
generate
    for (k = 0; k < 8; k = k + 1) begin : ch
        always @(posedge clk) begin
            sample[k] <= adc_data[k];   // 8 路在同一拍锁存
        end
    end
endgenerate

generate 在综合时展开成 8 份电路，不是循环执行 8 次。8 通道、100 MHz 采样、每路 16 bit，每通道数据率 12.5 MS/s，8 路加起来 1.6 Gbit/s——这个带宽单片机很难顺序顶住，而 FPGA 因为它本来就是并行结构，随手就能接。

八、易错清单 ​

  • 时序逻辑里用阻塞赋值 =：仿真可能对、综合后是三选一覆盖，旧值丢失。记住「综合逻辑用 =、时序逻辑用 <=」。
  • 组合逻辑里用 <=：仿真会出现一个时间单位的延迟伪影，而硬件里不存在，波形与上板表现不一致。
  • always @(*) 里有分支没赋值：推断出锁存器（latch），综合工具报警。所有分支都要赋值。
  • 位宽不声明：reg [15:0] cnt 与 reg [26:0] cnt 差着可表示的最大值；比较常量的字面量也别偷懒不写位宽（27'd1_000_000 比 1000000 安全）。
  • 异步复位写在同步 always 里：always @(posedge clk) 内用 if (!rst_n) 是同步复位，需要复位脉冲至少一个时钟周期；写成 or negedge rst_n 才是异步复位。两者混用会出现「有些寄存器强复位、有些晚一拍」。
  • 用两级同步器同步多 bit 总线：每一位独立恢复，采到的可能是中间值。多 bit 用异步 FIFO 或格雷码。
  • 拿时钟给别的逻辑当数据：always @(posedge clk_div) 把分频后的信号当时钟，工具无法做时序分析。分频出来的时钟只做使能 tick，不要当时钟用。
  • 忘记写时序约束：不写 create_clock，工具不知道你要多快，报告里没有违例不等于满足 100 MHz。
  • for 当循环用：Verilog 的 for 会被展开成多份电路，循环次数太多会直接撑爆 LUT。
  • 仿真通过就以为没问题：testbench 只验证了你的理解，没验证时序收敛与跨时钟域，上板前必须跑时序报告。

07 · 定时器与 PWM ​

核心 约 45 minMCU 里最有用的外设：定时、输出 PWM、测量频率，全靠同一个计数器

公式里那个 fTIMf_{TIM}fTIM​ 从哪来（以及为什么 APB 上的定时器要 ×2），见 。

结论先行 ​

  1. 定时器本质上是一个可配置的计数器：时钟经 PSC 分频后驱动 CNT 计数，数到 ARR 就溢出并产生更新事件。周期 = (PSC+1)(ARR+1)/fTIM(PSC+1)(ARR+1)/f_{TIM}(PSC+1)(ARR+1)/fTIM​。
  2. 三个核心寄存器：PSC（预分频，决定计数快慢）、ARR（自动重装载，决定周期）、CCR（捕获/比较，决定占空比或触发点）。公式里全都有 +1。
  3. PWM 靠「CNT 与 CCR 比较」产生：CNT < CCR 时输出一种电平，超过就翻转。改 CCR 就是改占空比，改 ARR 就是改频率。
  4. 输入捕获是 PWM 的逆过程：外部信号的边沿触发时把 CNT 的值锁存下来，两次锁存之差就是周期——用来测频率、测脉宽。
  5. 分辨率与频率此消彼长：ARR 越大占空比越精细，但 PWM 频率越低。选型时要先定频率，再看剩下多少分辨率。
  6. 定长约束：在计数频率固定时，fPWM×级数=fcntf_{PWM} \times \text{级数} = f_{cnt}fPWM​×级数=fcnt​，两者互为反比。想同时要高频和高分辨率，唯一办法是把 fcntf_{cnt}fcnt​ 抬上去，也就是减小 PSC。
  7. 凡是「靠脉宽认信号」的负载（舵机、RC 接收机、步进驱动脉冲），都先锁频率再调 CCR；凡是「靠平均功率认亮度/转速」的负载（LED、直流电机），才去调占空比。
  8. 时基寄存器与通道寄存器是分工的：ARR/PSC 改了会影响所有通道和溢出频率，CCR 改了只影响本通道。电机与舵机分频不同的定时器时，这一点必须记住。

一、定时器的三个组成部分 ​

PSC、ARR、CCR 都在外设寄存器里——「寄存器是有地址的内存」这件事见 。

部分寄存器作用
时基单元PSC、ARR、CNT产生基本的时间基准（多久数一次、数到多少溢出）
捕获/比较通道CCRx输出 PWM（比较）或测量外部信号（捕获）
时钟与触发内部时钟 / 外部时钟 / 其他定时器决定计数来源，可实现级联和同步

这三个部分可以理解成三级流水线：时钟决定「一拍」多长，PSC 决定「一个计数」多长，ARR 决定「数到哪里算一轮」，CCR 决定「一轮里哪一段翻转」。所有时间参数都是这四个数的函数，没有第五个旋钮。

计数模式：

  • 向上计数（最常用）：CNT 从 0 数到 ARR，溢出后回 0，产生更新事件（可触发中断）；
  • 向下计数：从 ARR 数到 0，溢出回 ARR。溢出时刻与向上计数相同，但翻转点落在周期末端，做某些斩波场合方便；
  • 中心对齐（先上后下）：一个周期内 CNT 走 2(ARR+1)2(ARR+1)2(ARR+1) 步，PWM 波形左右对称，谐波更小。电机与开关电源用中心对齐，因为三角载波的频谱特性优于方波；用它驱动 LED 时频率要按 fcnt/[2(ARR+1)]f_{cnt}/[2(ARR+1)]fcnt​/[2(ARR+1)] 算，这是「实际频率是设定值一半」的常见坑。

计数触发源也可以换：内部时钟、外部脉冲（用引脚直接当计数器，做脉冲数累加/转速测量）、另一个定时器的触发输出（级联，让几个 PWM 同步启动）、编码器接口。

频率与周期公式（记住 +1）：

fcnt=fTIMPSC+1,T更新=(ARR+1)fcnt=(PSC+1)(ARR+1)fTIMf_{cnt} = \frac{f_{TIM}}{PSC + 1},\qquad T_{更新} = \frac{(ARR + 1)}{f_{cnt}} = \frac{(PSC+1)(ARR+1)}{f_{TIM}} fcnt​=PSC+1fTIM​​,T更新​=fcnt​(ARR+1)​=fTIM​(PSC+1)(ARR+1)​

第 1 步定 PSC、第 2 步定 ARR、第 3 步定 CCR——这个顺序反过来就会算错，因为 ARR+1 是从 fTIM/(PSC+1)f_{TIM}/(PSC+1)fTIM​/(PSC+1) 里除出来的。

二、定时中断（最基础用法） ​

配置成「每隔 T 产生一次更新中断」，就能得到精确的周期性任务——取代不靠谱的软件延时。

软件延时的问题在于它的误差来自「循环体每次执行的周期数」：一次循环的耗时被中断、打缓存、分支预测全部污染，几个百分点误差就会累积成定时不准，而且换一个优化等级就变。硬件定时器则与代码无关，只与时钟树有关。

例 1 · 用 72 MHz 定时器做 1 ms 定时中断

定时器时钟 72 MHz（F103 经典配置，APB1 定时器已 ×2）。

第一步：选预分频，让计数频率是个好算的数。取 PSC = 71：

fcnt=72 MHz71+1=1 MHz(即 1 μs 数一次)f_{cnt} = \frac{72\ \text{MHz}}{71 + 1} = 1\ \text{MHz} \quad(\text{即 1 } \mu\text{s 数一次}) fcnt​=71+172 MHz​=1 MHz(即 1 μs 数一次)

第二步：1 ms = 1000 µs，所以数 1000 次，取 ARR = 999：

T=999+11 MHz=1 msT = \frac{999 + 1}{1\ \text{MHz}} = 1\ \text{ms} T=1 MHz999+1​=1 ms

代码：

c
htim2.Instance = TIM2;
htim2.Init.Prescaler = 71;          // PSC
htim2.Init.Period = 999;            // ARR
htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
HAL_TIM_Base_Init(&htim2);
HAL_TIM_Base_Start_IT(&htim2);      // 带中断启动

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
  if (htim->Instance == TIM2) {
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);   // 每 1 ms 翻转一次 → 500 Hz 方波
  }
}

常见错误：把 ARR 写成 1000（想「数 1000 次」），结果周期变成 1001 µs。硬件是「数到 ARR 值再溢出」，所以要 −1。

为什么这么想 PSC 的目的是把 72 MHz 这种「不好用」的频率变成一个好算的频率。1 MHz 每计数正好 1 µs，于是所有时间参数都能用「微秒数」直接当寄存器值写进去，不用任何除法。选 PSC = 71 而不是 72，正因为 PSC 本身要 +1。

三、PWM 输出 ​

PWM（Pulse Width Modulation，脉宽调制）用「高电平占比」来等效地输出一个模拟量：

  • 频率由 ARR 决定：fPWM=fcnt/(ARR+1)f_{PWM} = f_{cnt} / (ARR+1)fPWM​=fcnt​/(ARR+1)
  • 占空比由 CCR 决定：duty=CCR/(ARR+1)\text{duty} = CCR / (ARR+1)duty=CCR/(ARR+1)
  • 等效电压：Vavg=VCC×dutyV_{avg} = V_{CC} \times \text{duty}Vavg​=VCC​×duty（经 RC 滤波后就是真正的直流电压）

后一条的严格说法是低频等效：后级电路若带宽远高于 fPWMf_{PWM}fPWM​，它看到的就近似是一个恒定的直流电压；LED 的热时间常数在几十毫秒量级，1 kHz 的 PWM 对它是「平均电流」而不是「一串闪光」；但如果是音频功放输入，20 kHz 的载波就会直接被放大成可听见的噪声。

配置要点（HAL）：

c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);      // 启动 PWM 输出
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 300);   // 改 CCR（占空比）
__HAL_TIM_SET_AUTORELOAD(&htim3, 999);               // 改 ARR（频率）

__HAL_TIM_SET_COMPARE 只写 CCR，不产生更新事件，所以可以随时调用而不会打断当前这一轮波形；__HAL_TIM_SET_AUTORELOAD 改 ARR 同理，新值在下一个周期生效——这正是「在线调参不产生毛刺」的用法。

PWM 模式 1 vs 模式 2：模式 1 是「CNT < CCR 时输出有效电平」，模式 2 相反。所谓「有效电平」由极性配置决定（TIM_OCPOLARITY_HIGH/LOW）。占空比反了就调这两处。此外还有模式 3/4（PWM+互补），留给高级定时器的死区控制用。

例 2 · 驱动舵机：50 Hz、90°

舵机的控制信号是 50 Hz（周期 20 ms）的 PWM，靠绝对脉宽决定角度：

角度脉宽占空比
0°0.5 ms2.5%
90°1.5 ms7.5%
180°2.5 ms12.5%

用 1 MHz 计数频率（PSC = 71）：

ARR+1=1 MHz50 Hz=20000 ⇒ ARR=19999\text{ARR} + 1 = \frac{1\ \text{MHz}}{50\ \text{Hz}} = 20000 \ \Rightarrow\ \text{ARR} = 19999 ARR+1=50 Hz1 MHz​=20000 ⇒ ARR=19999CCR(90°)=1.5 ms×1 MHz=1500\text{CCR}(90°) = 1.5\ \text{ms} \times 1\ \text{MHz} = 1500 CCR(90°)=1.5 ms×1 MHz=1500

同理 0° → CCR = 500，180° → CCR = 2500。

要点：舵机只认脉宽不认占空比，所以必须先把频率固定在 50 Hz，再调 CCR。如果 ARR 改了（频率变了），同样的 CCR 就对应不同的角度——这也是「舵机角度不准」的常见原因。极端情况下若频率低于约 50 Hz，舵机会持续转到底限或顶到上限而不停机，这是真的会烧掉舵机的。

为什么这么想 舵机的内部是一个闭环：它测自己当前角度，把目标脉宽换算成目标位置，与实测位置比较，驱动电机直到吻合。所以它对外只呈现「一个脉冲意味着多少毫秒」这一条信息，占空比本身只是 ton/Tt_{on}/Tton​/T 的副产品，TTT 一变，角度立刻漂移。

例 3 · 用输入捕获测频率

把输入捕获配成「上升沿捕获」，两次捕获的 CNT 差值就是信号周期。设计数频率 1 MHz：

捕获差值周期频率
10001.000 ms1000 Hz
5000.500 ms2000 Hz
20002.000 ms500 Hz
周期=ΔCNTfcnt,f=fcntΔCNT\text{周期} = \frac{\Delta CNT}{f_{cnt}},\qquad f = \frac{f_{cnt}}{\Delta CNT} 周期=fcnt​ΔCNT​,f=ΔCNTfcnt​​

分辨率问题：1 MHz 计数下，1 kHz 附近相邻两个计数值对应的频率差约 1 Hz（106/1000−106/1001≈110^6/1000 - 10^6/1001 \approx 1106/1000−106/1001≈1）。测 1 kHz 时相对分辨率 0.1%，够用；但测 100 kHz 时 ΔCNT=10\Delta CNT = 10ΔCNT=10，差一个计数就是 10 kHz 的跳变（10% 误差），此时应降低 PSC（提高计数频率）或改用测频法（在固定闸门时间内数脉冲个数）。

测频法 vs 测周期法：测周期法在被测频率低时精度高、快时被测周期装不进计数器（且溢出难处理）；测频法用另一个定时器定 100 ms 闸门，在闸门内累计输入边沿数 NNN，则 f=N/0.1f = N / 0.1f=N/0.1 Hz，误差只来自闸门本身的精度，与被测信号无关——这是测高频时的正解。工程上常两者并用：低频走捕获，高频走测频。

溢出处理：若被测信号周期很长，CNT 可能在两次捕获之间溢出多次，需要记录溢出次数一起计算——这是输入捕获的进阶坑。

例 4 · PWM 分辨率与频率的取舍

同一个计数器，ARR 越大 → 分辨率越高，但频率越低：

ARR频率（1 MHz 计数）占空比步进
9910 kHz1%（100 级）
9991 kHz0.1%（1000 级）
9999100 Hz0.01%（10000 级）
步进=1ARR+1\text{步进} = \frac{1}{ARR + 1} 步进=ARR+11​

怎么选：

  • LED 调光：1 kHz、ARR = 999（0.1% 步进）足够，人眼看不出台阶；
  • 舵机：频率被锁死 50 Hz，ARR = 19999 → 步进 0.005%，分辨率非常富裕；
  • 音频/超声波：需要 20 kHz 以上，ARR 被迫变小，分辨率下降——此时要提高计数频率（减小 PSC）来补偿。

记住这个关系式：fPWM×级数=fcntf_{PWM} \times \text{级数} = f_{cnt}fPWM​×级数=fcnt​。在计数频率固定的情况下，频率和分辨率是此消彼长的。

为什么这么想 满量程永远是 ARR+1 个刻度，刻度总数固定，频率和级数就分的是同一块蛋糕。但这个「此消彼长」只在 fcntf_{cnt}fcnt​ 固定时成立——把 PSC 从 71 改成 35，等于把蛋糕本身放大一倍，于是 16 kHz 与 0.8% 步进可以同时拿到（见例 5）。

四、编码器接口 ​

正交编码器输出 A、B 两相脉冲（相位差 90°）。定时器配成编码器模式后硬件自动根据两相的相位关系判断方向并增减 CNT，不需要软件干预——电机测速、旋钮输入都靠它。

  • 通常配成 TI1 和 TI2 双边沿计数（4 倍频），即编码器转一圈的计数 = 物理线数 × 4；
  • CNT 溢出由 ARR 决定，读速度时用「两次读数之差」并处理溢出回绕。

测速的完整流程：每 10 ms 读一次 CNT，把本次值减上次值得到增量 Δ\DeltaΔ，转速 =Δ/(线数×4)/0.01 s= \Delta / (\text{线数} \times 4) / 0.01\ \text{s}=Δ/(线数×4)/0.01 s。若 Δ\DeltaΔ 长期为负或大幅超过 ARR，说明发生了回绕（低转速时溢出）或转向翻转，必须用有符号减法并判断跨越，否则电机反转时读数会出现正负跳变甚至恒定不变这类反直觉现象。

五、高级定时器（TIM1/TIM8）的额外能力 ​

  • 互补输出 + 死区：输出一对互补的 PWM（驱动 H 桥的上下管），并插入死区时间防止两管直通短路。这是电机控制和开关电源的必需功能。
  • 刹车输入（BKIN）：外部故障信号可直接硬件关断输出，响应速度比软件快得多。
  • 重复计数器：让 PWM 周期是更新周期的若干倍。

死区的物理含义值得单独强调：MOSFET 从栅压超过阈值到完全导通、以及从导通到关断，都需要时间（典型各几十到几百纳秒，加上栅极电荷）。若上管的下降沿与下管的上升沿严格同一时刻，在那个瞬间两管都处于导通状态，母线电压直接短路到地，这就是直通电流：它持续时间极短但峰值可达安培级，反复发生会让开关管和驱动芯片直接烧毁。死区就是强行在这两条边沿之间插一段时间，让前一只管子彻底关断、后一只才开始导通。

代价是有效占空比被压缩：死区同时吃掉两路输出的高电平，因此实际送到电机或变压器上的电压比设定值低，且这个损耗随频率线性增长。所以死区不是「越大越安全」，取到器件手册给出的最小值再加一点余量即可。

六、工程实例 ​

LED 呼吸灯调光：用 PWM 调光，让 CCR 从 0 平滑增加到 ARR 再减回 0，人眼看到的就是亮度渐变。频率取 1~2 kHz、ARR = 999，步进 0.1%。实现上不要用软件延时去扫亮度，而是把 CCR 的更新挂到 100 Hz 左右的更新中断上按查表递增——中断只做一次寄存器写入，扫完一整轮约 10 ms，正好是呼吸一次的时间。

亮度感知是非线性的：人眼对暗部变化更敏感，所以线性 ramp 会觉得「前半段变化快、后半段慢」，实际产品里要用 gamma 校正（如按平方或指数曲线调整），通常做法是直接存一张 256 级的 gamma 表（如 CIE 1931 校准值），用亮度等级号去查 CCR。

直流电机调速：用 PWM 控制电机平均电压。频率选择很关键——太低（<1 kHz）会听到线圈的啸叫并出现抖动，太高（>20 kHz）开关损耗增大；常用 10~20 kHz，既能避开人耳听觉范围，开关损耗也可接受。

具体到参数就是例 5：72 MHz → PSC = 17、ARR = 249 得 16 kHz，CCR = 0~250 连续可调即 0~100% 占空比。若换更小的电机、开关损耗压力不大，可以降到 8 kHz（ARR+1 = 500）换取 0.2% 的更细台阶。频率别直接照搬「电机说明书里的 25 kHz」：说明书给的是电机本体允许的范围，驱动端还要考虑栅极驱动器的驱动能力与死区能否在这个周期里塞得下。

舵机：这是「靠脉宽认信号」的标准场合，参数完全由例 2 锁死：PSC = 71、ARR = 19999、CCR 在 500~2500 之间写。工程上再加两件事：一是用输出比较或输入捕获实测脉宽，确认硬件真的输出了 0.5~2.5 ms（串口转接线的二极管会吃掉约 0.6~0.7 V，压降后脉宽可能不足）；二是上电时先把 CCR 写 1500（中间位）再启动输出，避免初始化瞬间输出一个 0 脉宽让舵机猛撞到底限。

死区与 H 桥：电机与步进驱动的 H 桥每一相都是上下管互补驱动，必须开死区。设 1 µs 死区后，占空比两端（接近 0% 或 100%）会被死区显著压缩甚至钳死，出现「给 100% 也只有 90% 有效」的现象——所以实际可用的调速区间通常收缩到 5%~95%，并且要在软件层面做上下限钳位，不能让 CCR 直通到 0 或 ARR+1。

04 · 时钟系统（RCC 与时钟树） ​

核心 约 50 min所有外设的心跳都从这里来；算错分频 = 时间全错，而 APB1 上定时器时钟要乘二这件事最容易漏

这一页要解决什么：同一句 HAL_Delay(1)，在没配时钟的板子上要等 9 倍的时间；同一段串口代码，换个波特率就满屏乱码；同一个定时器，按手册算出来的频率和实测差一倍。这三件事的根都在一个地方：时钟从哪来、经过哪几级分频、最后到外设手上是多少。这一页要把这条链完整走一遍：认时钟源、画时钟树、算每一级分频、找到每个外设的开关，最后用它把定时器和串口的数字算对。

读这页之前

  • 需要会：频率与周期的倒数关系（f=1/Tf=1/Tf=1/T）；整数乘除与百分比误差的算法（(实际−标称)/标称(\text{实际}-\text{标称})/\text{标称}(实际−标称)/标称）；用十六进制写寄存器地址与位。分频与倍频本身不需要新数学，就是乘除。
  • 这一页用到的符号：fSYSCLKf_{\text{SYSCLK}}fSYSCLK​、fHCLKf_{\text{HCLK}}fHCLK​、fPCLK1f_{\text{PCLK1}}fPCLK1​、fPCLK2f_{\text{PCLK2}}fPCLK2​ 分别表示系统时钟、AHB 总线时钟、APB1 与 APB2 总线时钟；fTIMf_{\text{TIM}}fTIM​ 是定时器的计数时钟；PSC、ARR、CCR 是定时器的三个寄存器。单位用 MHz（10610^6106 Hz）与 kHz（10310^3103 Hz），读法见符号与约定 · 单位词头。
  • 需要会一点寄存器：使能时钟就是往某个寄存器的某一位写 1，位操作的写法在 里讲过，这一页会直接用。
  • 四个词先给一句话：RCC（Reset and Clock Control，复位与时钟控制）是管「谁用哪个频率、开还是关」的那组寄存器；PLL（Phase-Locked Loop，锁相环）是用反馈把输出频率锁成输入频率整数倍的电路；AHB 与 APB（Advanced High-performance Bus、Advanced Peripheral Bus）是 ARM 规定的高速与低速两条片上总线；预分频（prescaler）是「把输入频率除以一个整数」的计数器。正文遇到时再展开。

先看三个真实场景。第一：新板子没配时钟就烧进一个 HAL_Delay(1)，你以为等 1 ms，其实等了 9 ms——因为芯片上电默认跑在内部 8 MHz，而不是标称的 72 MHz。第二：USART2 配 115200，收到的是乱码，而同一条代码把 USART1 换成 115200 就正常。第三：手册写 TIM3 挂在 APB1 上、APB1 是 36 MHz，你按 36 MHz 算分频，实测延时正好差一倍。

三个现象的答案都不在代码里，而在这颗芯片出厂时定下的一张图上：时钟树。这一页把它画出来、算清楚。

结论先行 ​

这一页的结论集中放这里，每条一句话，后面每一节展开其中一条。

  1. 时钟是 MCU 的心跳，而且每个外设都有独立开关；上电后外设时钟默认关闭（省电），不使能就毫无反应。
  2. 上电默认用内部 HSI（8 MHz），要达到标称主频必须手工配置：外部晶振 HSE → PLL 倍频 → SYSCLK。
  3. 时钟树是一条分频链：SYSCLK → AHB(HCLK) → APB1/APB2(PCLK1/PCLK2) → 各外设，每一级的分频都受芯片上限约束。
  4. APB 预分频系数不等于 1 时，挂在该总线上的定时器时钟自动 ×2；忘了这条，延时与 PWM 频率会整体差一倍。
  5. 时钟配错的症状很统一：延时不准、串口乱码、USB 不枚举、卡在等待晶振就绪——都不是逻辑错误，是频率错了。

心智模型：时钟树 = 水厂 + 分区阀门 + 楼内开关

水厂是时钟源（HSI 或 HSE），出厂水压固定。增压泵是 PLL：把 8 MHz 的「水压」按整数倍提上去，变成 72 MHz。分区阀门是 AHB/APB 的分频器：主干管给内核和内存全压，支管给外设降压（APB1 只能承受到 36 MHz，超了会「爆管」，也就是芯片跑飞）。楼内开关是每个外设自己的使能位：管子通到楼下不等于你家有水，得把自家阀门打开。

这条类比还能解释一个反直觉规则：区里降压了，但消防栓（定时器）要求高压——所以硬件给定时器单独接了一根「×2」的增压支管。这就是第五节要讲的规则。

一、为什么需要一棵树 ​

这一节只回答一个问题：为什么不让所有外设跑同一个频率，省掉这一整套分频。

如果所有外设都跑同一个频率，那一个时钟源就够了。但现实是三个需求互相冲突：

  • 性能需求不同：CPU 和 DMA 要最快；UART 只需要几十 kHz 到几 MHz 的时钟来产生波特率；看门狗只需要几十 kHz。
  • 省电是第一约束：不用的外设把时钟关掉，它就几乎不耗电——这叫时钟门控（clock gating），是嵌入式低功耗最基础的一招。
  • 精度需求不同：USB 和串口通信要求时钟精度在千分之几以内，内部 RC 振荡器（误差 1%~2%）做不到，必须用外部晶振。

于是芯片设计成：一个（或几个）时钟源 → PLL 倍频 → 多路分频器 → 分发给各外设，中间每个节点都有开关。这套结构像一棵倒挂的树——根是时钟源，主干是系统时钟，枝杈是各条总线，叶子是每个外设——所以叫时钟树（clock tree）。管这棵树的就是 RCC 模块。

树根上到底有几个源？这是下一节的内容——不认清源，后面每一级都无从算起。

二、五个时钟源 ​

这一节只做一件事：认识树根上的五个源，并说清上电那一刻默认在用哪一个。

时钟源频率精度用途
HSI 高速内部8 MHz（F1）/ 16 MHz（F4）差（±1%~2%，受温漂影响）上电默认时钟；HSE 失效时的备份
HSE 高速外部通常 4~25 MHz（板载晶振）高（几十 ppm）主时钟源，经 PLL 倍频到系统主频
LSI 低速内部约 40 kHz很差独立看门狗 IWDG
LSE 低速外部32.768 kHz高RTC 实时时钟（钟表晶振）
PLL 锁相环—跟随输入倍频器，把 8 MHz 变成 72 MHz / 168 MHz

晶振（crystal oscillator）指的是「石英晶体 + 起振电路」：石英片的机械谐振频率非常稳定，所以它比内部 RC 振荡器准两个数量级。这也是为什么需要精确定时的场合（串口、USB、RTC）都要外接晶振。

上电后的默认状态：芯片复位后跑在 HSI（F103 上就是 8 MHz 直接当 SYSCLK，不分频不倍频）。这意味着你不配时钟，程序照样能跑，只是主频是 8 MHz 而不是 72 MHz——于是所有基于时间的计算（延时、波特率、PWM 频率）都会差 9 倍（72/8=972/8=972/8=9）。这是新手「程序跑了但串口全是乱码」的经典原因。

源认清了，接下来把从源到外设的整条链画出来——这是这一页最重要的一张图。

三、F103 的时钟树：一条从 8 MHz 到 72 MHz 的链 ​

这一节只做一件事：把 F103 的整棵树画出来，并说清每一级分频受什么约束。

各总线上挂什么（F103）：

总线最高频率典型外设
AHB（HCLK）72 MHz内核、内存、DMA、CRC
APB2（PCLK2）72 MHz（高速）GPIO、AFIO、ADC、USART1、SPI1、TIM1、TIM8
APB1（PCLK1）36 MHz（低速）TIM2~7、USART2/3、SPI2/3、I²C、CAN、USB、DAC、看门狗

这里必须解释两个词，否则「挂在哪条总线上」这句话没法读。AHB（Advanced High-performance Bus）是 ARM 定义的片内高速总线，宽、快、直连内核，适合高频大流量；APB（Advanced Peripheral Bus）是慢速外设总线，省线、省功耗，所以频率必须压低，F103 把它分成 APB2（可到 72 MHz）和 APB1（只到 36 MHz）两条。

注意 APB1 的上限只有 36 MHz（F103），所以它必须至少二分频。这就是为什么挂在 APB1 上的外设（USART2、TIM2~7）时钟比 APB2 上的慢一半——选串口、选定时器时要先看它挂在哪条总线上。

例 1 · 把 F103 配到 72 MHz，算出各路时钟

题目：外部晶振 HSE = 8 MHz，PLL 倍频 ×9，AHB 不分频，APB1 二分频，APB2 不分频。求 SYSCLK、HCLK、PCLK1、PCLK2，以及 TIM2~7 与 TIM1 的实际计数时钟。

先想什么：这是一道沿链路逐级乘除的题，不是解方程。做法固定：从源开始，每过一个节点就乘或除一次，并把结果写在节点旁边；定时器要单独再考虑一次 ×2。（为什么必须逐级写：中间任何一级都可能撞上限，跳着算会漏掉「超限」这个致命检查。）

步骤：

  1. PLL 输出即系统时钟：8×9=728\times9=728×9=72 MHz。
  2. AHB 不分频：72÷1=7272\div1=7272÷1=72 MHz，这是 HCLK，内核与内存用它。
  3. APB1 二分频：72÷2=3672\div2=3672÷2=36 MHz。先检查上限：36 ≤ 36 ✓。
  4. APB2 不分频：72÷1=7272\div1=7272÷1=72 MHz。上限 72 ✓。
  5. 定时器：APB1 分频系数为 2（≠1），所以 TIM2~7 的计数时钟 = 36×2=7236\times2=7236×2=72 MHz；APB2 分频为 1，TIM1 就是 72 MHz，不再乘。

验算：三条独立检查。① 上限：PCLK1 = 36 不超过 36、PCLK2 = 72 不超过 72 ✓。② 反向：从 TIM 的 72 MHz 反推——若没有 ×2 规则，定时器只有 36 MHz，与你将要写的分频值对不上（第五节会用具体数字演示差一倍）。③ 常识：F103 标称主频 72 MHz，我们的 SYSCLK 正好等于它 ✓。

顺便看清一个危险：若把 APB1 也设成不分频，PCLK1 就是 72 MHz，超过 36 MHz 上限——芯片可能直接不启动，而症状是「程序不跑」，没有任何报错。超限检查必须写在算完之后。

树配好了，但「时钟到达总线」不等于「时钟到达外设」。中间还有一级开关，这是下一节的主题，也是「代码全对但没反应」的第一号原因。

四、外设时钟使能（最容易漏的一步） ​

这一节只回答一个问题：时钟已经到总线了，为什么外设还是不动。

时钟树配好了只是「时钟到达了总线」，每个外设还有自己的最后一级开关，在 RCC 的使能寄存器里。这就是第一节提到的时钟门控——总线上的时钟一直在跑，但外设的时钟输入被门关着。

c
// F103：APB2 外设使能寄存器 RCC->APB2ENR
RCC->APB2ENR |= (1 << 2);    // IOPAEN：GPIOA 时钟
RCC->APB2ENR |= (1 << 4);    // IOPCEN：GPIOC 时钟
RCC->APB2ENR |= (1 << 14);   // USART1EN：USART1 时钟

// HAL 写法（推荐，可读性好）
__HAL_RCC_GPIOA_CLK_ENABLE();
__HAL_RCC_USART1_CLK_ENABLE();
__HAL_RCC_TIM2_CLK_ENABLE();

忘了使能的症状：配置代码全部正确、寄存器也写了，但外设毫无反应，而且不报错。因为对未使能时钟的外设寄存器写入，硬件根本不响应——写操作不会失败，只是石沉大海。

使能寄存器挂哪些外设（F103）常用位
RCC->AHBENRDMA1、SRAM、Flash 接口bit0 DMA1EN、bit2 SRAMEN
RCC->APB2ENRGPIOA~E、AFIO、ADC1、USART1、SPI1、TIM1bit2 IOPAEN、bit4 IOPCEN、bit14 USART1EN
RCC->APB1ENRTIM2~7、USART2/3、I²C、USB、CANbit0 TIM2EN、bit17 USART2EN

三张表记不住也没关系，只要记住一条动作：用哪个外设，先打开它所在总线的那个位。至于「为什么 APB1 上的定时器时钟要乘二」，那是下一节要解释的硬件细节。

五、定时器时钟为什么会自动 ×2 ​

这一节只回答一个问题：为什么 APB1 明明只有 36 MHz，挂在它上面的定时器却是 72 MHz。

这是 F1/F4 系列一个反直觉的硬件设计，规则只有一句：

fTIM={fPCLK,APB 预分频系数=12 fPCLK,APB 预分频系数≠1f_{\text{TIM}} = \begin{cases} f_{\text{PCLK}}, & \text{APB 预分频系数} = 1 \\ 2\,f_{\text{PCLK}}, & \text{APB 预分频系数} \ne 1 \end{cases} fTIM​={fPCLK​,2fPCLK​,​APB 预分频系数=1APB 预分频系数=1​

用意是：即使你把 APB1 分频降到 36 MHz 来省电，定时器仍能拿到 72 MHz 的高分辨率，不至于因为省电而牺牲定时精度。

这条规则的实战影响：

  • 算定时周期、PWM 频率时，用的时钟是**×2 之后的值**；
  • 算 UART 波特率时，用的却是**×2 之前的 PCLK**（USART 不在 ×2 之列，只有定时器享受这个待遇）——同一个 APB1 上，定时器和串口用的时钟不一样，这是最容易算混的地方。

例 2 · 同一条 1 ms 定时，用 36 还是 72 会差多少

题目：用 TIM3（挂 APB1，PCLK1 = 36 MHz、定时器时钟 72 MHz）做 1 ms 定时。取 PSC = 71、ARR = 999 时实际周期是多少？若误把定时器时钟当成 36 MHz，同样的寄存器值会得到多少？

先想什么：算定时周期只有两个动作——先算计数频率（fTIM/(PSC+1)f_{\text{TIM}}/(PSC+1)fTIM​/(PSC+1)），再算周期（(ARR+1)/fcnt(ARR+1)/f_{cnt}(ARR+1)/fcnt​）。难点不在算术，而在分母上那个 fTIMf_{\text{TIM}}fTIM​ 到底填多少。所以先确定「这颗定时器挂在哪条总线、分频系数是不是 1」，再动笔。（为什么先定时钟再定寄存器：反过来的话，你会先凑出一堆好看的数字，再去解释为什么实测不对。）

步骤：

  1. 确认时钟：TIM3 挂 APB1；APB1 分频 2 ≠ 1，所以 fTIM=36×2=72f_{\text{TIM}}=36\times2=72fTIM​=36×2=72 MHz。
  2. 算计数频率：fcnt=72 MHz/(71+1)=1f_{cnt}=72\ \text{MHz}/(71+1)=1fcnt​=72 MHz/(71+1)=1 MHz，即一个计数 1 µs。
  3. 算周期：T=(999+1)/1 MHz=1T=(999+1)/1\ \text{MHz}=1T=(999+1)/1 MHz=1 ms。
  4. 换成错误假设：fcnt=36/72=0.5f_{cnt}=36/72=0.5fcnt​=36/72=0.5 MHz，T=1000/0.5 MHz=2T=1000/0.5\ \text{MHz}=2T=1000/0.5 MHz=2 ms。

验算：用「计数次数 × 单次时间」独立复核。正确情形：1000 次 × 1 µs = 1 ms ✓；错误情形：1000 次 × 2 µs = 2 ms ✓（两倍）。再补一个比例检查：72/36=272/36=272/36=2，周期应该正好翻倍，与结果一致 ✓。

顺带得到 PWM：同一定时器下，PWM 频率 = fcnt/(ARR+1)=1 MHz/1000=1f_{cnt}/(ARR+1)=1\ \text{MHz}/1000=1fcnt​/(ARR+1)=1 MHz/1000=1 kHz。要让占空比为 30%，比较寄存器取 CCR=(ARR+1)×30%=1000×0.3=300\text{CCR}=(ARR+1)\times30\%=1000\times0.3=300CCR=(ARR+1)×30%=1000×0.3=300，对应高电平时间 300/1 MHz=300300/1\ \text{MHz}=300300/1 MHz=300 µs。

注意所有公式里的 +1：分频器和计数器都是「数到设定值再加一」，写成 PSCPSCPSC 而不是 PSC+1PSC+1PSC+1 是高频错误——差 1 在低频段看不出来，在高频段就是百分之几的误差。

F1 的树讲完了。F4 把这棵树改得更细——多了两级分频，还多出一个给 USB 的分支。下一节看差异在哪。

六、F4 系列的时钟树差异 ​

这一节回答一个问题：换到 F4（比如 F407）之后，同样的配置动作多了哪几个参数。

F4（如 F407）把 PLL 拆得更细，多了两级分频，并多出一条给 USB 的输出：

参数约束
M 输入分频使 PLL 输入落在 1~2 MHz（推荐 2 MHz 以内）
N 倍频使 VCO 输出落在 100~432 MHz
P 输出分频取 2 / 4 / 6 / 8，决定 SYSCLK（F407 上限 168 MHz）
Q 分频给 USB OTG、SDIO 用，需得到 48 MHz

例 3 · 把 F407 配到 168 MHz，并给 USB 凑出 48 MHz

题目：HSE = 8 MHz。要求 SYSCLK = 168 MHz、USB 得到 48 MHz。选 M、N、P、Q，并算出 HCLK、PCLK1、PCLK2 与 TIM1、TIM2~7 的计数时钟（APB1 四分频、APB2 二分频）。

先想什么：四个参数不是自由选的，而是被四条约束夹住的：先定 P（只有 2/4/6/8 四档），再从「SYSCLK × P = VCO」反推 N，最后让 N 能被 Q 整除出 48 MHz。所以顺序是 P → N → Q → M。（为什么不先定 M：M 只影响输入频率的落点，自由度最大、约束最松，放最后调。）

步骤：

  1. 取 P = 2 → VCO 必须是 168×2=336168\times2=336168×2=336 MHz，落在 100~432 内 ✓。
  2. 取 N = 336 → 输入必须是 336/336=1336/336=1336/336=1 MHz，于是 M = 8（8/8=18/8=18/8=1），落在 1~2 MHz ✓。
  3. USB 要 48 MHz：Q=336/48=7Q=336/48=7Q=336/48=7，正好整数 ✓。
  4. 总线分频：AHB ÷1 → HCLK 168；APB1 ÷4 → 42 MHz（≤42 ✓）；APB2 ÷2 → 84 MHz（≤84 ✓）。
  5. 定时器：APB1 分频 4 ≠ 1 → TIM2~7 = 42×2=8442\times2=8442×2=84 MHz；APB2 分频 2 ≠ 1 → TIM1 = 84×2=16884\times2=16884×2=168 MHz。

验算：三条独立检查全部对得上——① 输入 1 MHz 在 1~2 内、VCO 336 在 100~432 内、SYSCLK 168 等于上限；② USB 48 MHz 是 336/7 的整除结果，不是近似值；③ 定时器从 84 反推：若忘了 ×2，TIM1 就只有 84 MHz，与「TIM1 是高级定时器、跑满 168」的常识不符。四点全过 ✓。

检查约束是必须的：VCO 超 432 MHz 或 PLL 输入不在 1~2 MHz，芯片可能根本起不来，且症状是「程序不跑」而非报错。

时钟到这里就全通了：源 → PLL → 总线 → 外设开关 → 定时器。最后一节把它变成两个能立刻用的算式：定时周期与串口波特率。

七、从时钟到定时与 PWM ​

这一节把时钟落到两个最常见的用途上：一个精确定时，一个占空比可调的方波。

定时器时钟确定后，定时周期和 PWM 频率就由两个寄存器决定：

  • PSC（prescaler，预分频器）：把定时器时钟再分一次，得到计数频率 fcnt=fTIM/(PSC+1)f_{cnt} = f_{TIM} / (PSC + 1)fcnt​=fTIM​/(PSC+1)
  • ARR（auto-reload register，自动重装载寄存器）：计数器数到 ARR 就溢出/重装，周期 T=(ARR+1)/fcntT = (ARR + 1) / f_{cnt}T=(ARR+1)/fcnt​
  • CCR（capture/compare register，比较寄存器）：计数值小于 CCR 时输出一种电平，大于时另一种——这就是 PWM 占空比的来源

例 4 · 用 72 MHz 定时器做 1 ms 定时并配出 30% 占空比

题目：定时器时钟 72 MHz。要 1 ms 周期、占空比 30%，取 PSC 与 ARR、算 CCR，并说明测量时该期待什么。

先想什么：PSC 和 ARR 的分工要分清——PSC 决定「一个计数多少时间」，ARR 决定「数多少个计数」。两个都往大调都能延长周期，但只有 ARR 直接对应 PWM 的分辨率，所以习惯上先定「一个计数 = 1 µs」把 PSC 定下来，再用 ARR 凑周期。（为什么这样分工：PSC 只影响分辨率，ARR 影响周期和占空比分辨率，先固定分辨率能让后面的数字都是整数。）

步骤：

  1. 目标分辨率 1 µs/计数 → fcnt=1f_{cnt}=1fcnt​=1 MHz → PSC=72 MHz/1 MHz−1=71PSC=72\ \text{MHz}/1\ \text{MHz}-1=71PSC=72 MHz/1 MHz−1=71。
  2. 周期 1 ms → 需要 1000 个计数 → ARR=1000−1=999ARR=1000-1=999ARR=1000−1=999。
  3. 占空比 30% → CCR=(ARR+1)×0.3=300CCR=(ARR+1)\times0.3=300CCR=(ARR+1)×0.3=300。
  4. 高电平时间 =300×1 μs=300 μs=300\times1\ \mu\text{s}=300\ \mu\text{s}=300×1 μs=300 μs；PWM 频率 =1 MHz/1000=1=1\ \text{MHz}/1000=1=1 MHz/1000=1 kHz。

验算：反算三点。① fcnt=72/(71+1)=1f_{cnt}=72/(71+1)=1fcnt​=72/(71+1)=1 MHz ✓；② T=(999+1)/1 MHz=1T=(999+1)/1\ \text{MHz}=1T=(999+1)/1 MHz=1 ms ✓；③ 占空比 300/1000=30%300/1000=30\%300/1000=30% ✓。再用示波器口径核对：1 kHz 的周期是 1 ms，高电平 300 µs——三个数字互相自洽，说明 PSC/ARR 没有互相抵消的错误（比如 PSC=35、ARR=1999 也能得到 1 ms，但分辨率变成 2 µs，占空比只能取偶数步）。

最容易错的地方：公式里的 +1+1+1。写成 fcnt=fTIM/PSCf_{cnt}=f_{TIM}/PSCfcnt​=fTIM​/PSC 会得到 1.014 MHz，周期 0.986 ms，差 1.4%——在 1 ms 这个量级看不出来，但如果做的是 20 µs 的高频 PWM，误差就是致命的。

定时算对了，还有一个「看起来不是时钟问题、其实是时钟问题」的场合：串口。下一节把误差算到底。

八、工程实例：波特率误差是怎么来的 ​

这一节回答最后一个问题：为什么同一个波特率，一条串口正常、另一条乱码。

串口的波特率由 PCLK 分频得到（16 倍过采样：每个位时间里采 16 次，取中间几次判值，以抵抗噪声与时钟偏差），分频系数是

DIV=fPCLK16×baud\text{DIV} = \frac{f_{PCLK}}{16 \times \text{baud}} DIV=16×baudfPCLK​​

DIV 通常不是整数，硬件只能写「整数部分 + 4 位小数部分」，小数步长是 1/16=0.06251/16=0.06251/16=0.0625，于是产生误差。

例 5 · 算两个串口在 115200 下的实际误差

题目：USART1 挂 APB2（PCLK2 = 72 MHz）、USART2 挂 APB1（PCLK1 = 36 MHz），都配 115200。分别算实际波特率与误差，并判断能否通信。

先想什么：先算 DIV 的真值，再看它的小数部分能不能用 1/161/161/16 精确表示。能表示就没有误差；不能就取最近格点，再用实际 DIV 反推波特率。（为什么不能直接四舍五入到小数点后两位：误差是按比例影响每一位采样的，必须用「实际 DIV」重算波特率才知道真实偏差。）

步骤：

  1. USART1：DIV=72×106/(16×115200)=39.0625\text{DIV}=72\times10^6/(16\times115200)=39.0625DIV=72×106/(16×115200)=39.0625。
  2. 小数 0.0625 正好是 1/161/161/16，4 位小数能精确表示 → 实际波特率就是 115200，误差 0%。
  3. USART2：DIV=36×106/(16×115200)=19.53125\text{DIV}=36\times10^6/(16\times115200)=19.53125DIV=36×106/(16×115200)=19.53125。
  4. 小数 0.53125 不能表示（格点间隔 0.0625），最近格点是 9/16=0.56259/16=0.56259/16=0.5625 → 实际 DIV = 19.5625。
  5. 反推波特率：36×106/(16×19.5625)≈11501636\times10^6/(16\times19.5625)\approx11501636×106/(16×19.5625)≈115016 bps。

验算：误差 =(115016−115200)/115200≈−0.16%=(115016-115200)/115200\approx-0.16\%=(115016−115200)/115200≈−0.16%。这个值远小于串口允许的 ±2%~3% 容差，通信完全正常 ✓。另一个方向的检查：39.0625 的小数部分乘 16 得 1（整数），说明能精确落在格点上；19.53125 的小数部分乘 16 得 8.5（不是整数），说明必然要取近似 ✓。

实用结论：串口通信出问题，先确认「这条 USART 挂在哪条总线、当前 PCLK 是多少」，再算误差，而不是先怀疑代码。误差本身还随帧长累积：10 位一帧、每帧偏 0.16% 的一位时间，累计约 0.016 位——远小于半个位宽，所以能正确采样；但若误差到 3%，10 位就会累积到 0.3 位，靠近临界点，长帧高波特率时就会出错。

波特率误差是这一页的最后一个数字。把它和前面七条坑一起排成清单，就是下一节要做的事——顺序按踩坑频率，不按章节顺序。

九、易错清单（按踩坑频率排序） ​

  1. 忘记开外设时钟 → 配置全对、寄存器也写了，外设毫无反应且不报错 → 先 __HAL_RCC_xxx_CLK_ENABLE()，再写配置。
  2. 以为不配时钟就是 72 MHz → 实际跑在 HSI 的 8 MHz，所有基于时间的量差 9 倍 → 上电默认 HSI，必须手工配时钟树。
  3. 定时器时钟忘了 ×2 → 延时、PWM 频率整体差一倍，波形看着完全正常 → APB 分频 ≠ 1 时定时器时钟 = PCLK × 2。
  4. 把 ×2 规则套到串口上 → 波特率算成两倍，通信直接乱码 → USART 用 PCLK 本身，不 ×2。
  5. PSC / ARR 公式忘了 +1 → 周期偏小百分之几，低频看不出来、高频致命 → 分频与重装都是「数到值再加一」。
  6. 超过总线频率上限 → 芯片跑飞或不启动，且不报错 → F103 的 APB1 ≤ 36 MHz、APB2 ≤ 72 MHz；F407 的 APB1 ≤ 42 MHz、APB2 ≤ 84 MHz。
  7. F4 的 VCO 或 PLL 输入越界 → 芯片直接起不来，症状是「程序不跑」 → VCO 100~432 MHz、PLL 输入 1~2 MHz。
  8. HSE 晶振不起振 → SystemClock_Config() 死在等待就绪的循环里 → 先切 HSI 定位，再查晶振与负载电容。

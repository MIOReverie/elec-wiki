08 · 串口 UART ​

核心 约 40 min嵌入式最常用的对外接口：帧结构、波特率误差、轮询/中断/DMA 三种收法

结论先行 ​

  1. UART 是异步串行通信：没有时钟线，收发双方事先约定波特率，靠起始位的下降沿同步每一帧。
  2. 一帧 = 起始位 + 数据位（通常 8 位）+ 可选校验位 + 停止位。线路空闲时是高电平，第一个下降沿就是起始位。
  3. 数据位是最低位先发（LSB first），和书写顺序相反——用逻辑分析仪读波形时最容易在这里出错。
  4. 三种接收方式：轮询（阻塞，只适合调试）、中断（每字节进一次中断）、DMA（推荐，收完一帧才打扰 CPU）。
  5. 波特率由 PCLK 分频得到，通常有误差，但只要误差在 ±2%~3% 以内通信就正常；出问题先查「这条 USART 挂在哪个总线、PCLK 是多少」。

一、为什么需要「约定波特率」 ​

同步通信（SPI、I²C）有专门的时钟线，接收方照着时钟采样即可。UART 只有一根数据线（各方向一根），没有时钟，于是双方必须事先约定「每位持续多久」——这就是波特率（baud，位/秒）的含义。

发送方按波特率把每一位放到线上，接收方按同样的波特率采样。为了对齐每一帧的起点，UART 规定：

  • 线路空闲时为高电平；
  • 发送时先拉低一位（起始位），这个下降沿就是接收方的同步信号；
  • 接收方检测到下降沿后，等待半个位时间再开始采样（跳过边沿、在位的中间采样最可靠），之后每隔一个位时间采一次。

二、帧结构 ​

字段电平说明
空闲高没有数据时的默认状态
起始位低（1 位）同步信号，下降沿触发接收方开始采样
数据位5~9 位（通常 8）LSB 先发
校验位可选奇校验 / 偶校验，只能发现奇数位错误
停止位高（1 / 1.5 / 2 位）给接收方喘息时间，也保证下一帧前必有高电平

例 2 · 波特率误差从哪来、多大算安全

UART 用 16 倍过采样，分频系数为 DIV=fPCLK/(16×baud)\text{DIV} = f_{PCLK} / (16 \times \text{baud})DIV=fPCLK​/(16×baud)，硬件只能取「整数 + 4 位小数」（步长 1/16）。

以 USART2（挂在 APB1，PCLK1 = 36 MHz）为例：

9600234.375234 + 6/16 = 234.3759600.000%（.375 = 6/16 恰好精确）
11520019.531319 + 9/16 = 19.5625115015.97−0.16%

−0.16% 安全吗？ 一帧 10 位，累积漂移 = 10×0.0016=0.01610 \times 0.0016 = 0.01610×0.0016=0.016 位。接收方在每个位的中点采样，容错约 ±0.5 位，所以 0.016 位远在容限内，通信完全正常。

什么时候会出问题：当误差接近或超过 ±2%~3%（例如用了不标准的晶振频率、或波特率取到接近分频极限的值），采样点会滑到位的边界，表现为偶发的乱码——而且是温度变化时才偶发，极难排查。

三、三种接收方式 ​

方式怎么用CPU 开销适合
轮询HAL_UART_Receive(&huart1, buf, n, timeout)阻塞等待，期间 CPU 干不了别的调试、初始化阶段的简单交互
中断HAL_UART_Receive_IT()，每收到 1 字节进一次中断每字节一次中断低速、数据量小
DMAHAL_UART_Receive_DMA()，DMA 自动搬运，收满或空闲才中断几乎为零大数据量、高波特率（推荐）
c
// 轮询（会阻塞）
HAL_UART_Receive(&huart1, buf, 10, 100);

// 中断（非阻塞，需重写回调）
HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
  ringbuf_put(&rx_buf, rx_byte);
  HAL_UART_Receive_IT(huart, &rx_byte, 1);   // 重新开启下一次接收！
}

// DMA + 空闲中断（推荐：不定长帧）
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buf, sizeof(rx_buf));
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t size) {
  // size 就是本次收到的帧长度
}

中断方式的一个坑：HAL_UART_Receive_IT 只接收指定长度，收完就停止。所以回调里必须重新调用一次才能继续接收，否则只能收到第一字节。

例 3 · 中断方式 vs DMA 方式的 CPU 开销

假设每次中断（进出 + 处理）约消耗 2 µs。

115200、每字节一次中断：每秒 115200/10=11520115200/10 = 11520115200/10=11520 次中断

11520×2 μs=23 ms⇒CPU 占用约 2.3%11520 \times 2\ \mu\text{s} = 23\ \text{ms} \quad\Rightarrow\quad \text{CPU 占用约 } 2.3\% 11520×2 μs=23 ms⇒CPU 占用约 2.3%

921600 时：每秒 92160 次中断 → 92160×2 μs=184 ms92160 \times 2\ \mu\text{s} = 184\ \text{ms}92160×2 μs=184 ms，CPU 占用 18.4%。

改用 DMA：让 DMA 收满 1024 字节才产生一次中断，115200 下每秒只需约 11 次中断，CPU 占用降到千分之一量级。

结论：低波特率、少量数据时中断方式够用；高波特率或大数据量必须用 DMA，否则 CPU 会被中断淹没，主循环几乎无法执行。

四、环形缓冲与不定长帧 ​

串口数据是流式的，一帧数据可能分多次到达。标准做法是 ISR/DMA 只负责往环形缓冲里放数据，主循环负责解析：

DMA/中断 → 环形缓冲区（生产者）
                          ↓
主循环 while(1) → 取数据、找帧头、校验、处理（消费者）

这样解耦后，即使主循环正在忙别的事，数据也不会丢（缓冲有容量兜底）。

不定长帧怎么判断一帧结束：常用 IDLE 空闲中断——线路上超过一个字节时间没有新数据，就认为一帧结束（HAL 的 ReceiveToIdle 系列就是干这个的）。这是目前最实用的方案。

六、工程实例 ​

例 4 · 设计一个简单可靠的帧协议

裸的字节流无法区分「帧边界」和「数据内容」。最小可用的帧格式：

字段长度值
帧头2 字节0xAA 0x55（固定，用于定位帧起始）
长度1 字节后续数据长度 N
数据N 字节有效载荷
校验2 字节CRC16

开销分析（115200、10 位/帧）：

数据长度帧长协议开销传输耗时
8 字节13 字节38.5%1.13 ms
32 字节37 字节13.5%3.21 ms
128 字节133 字节3.8%11.55 ms

结论：帧头 + 长度 + 校验共 5 字节固定开销，数据越短，协议开销占比越高。所以高频小数据（如传感器采样值）应尽量打包成较长的帧批量发送，而不是一字节一帧。

解析要点：

  1. 用状态机解析（等帧头 → 收长度 → 收数据 → 收校验 → 校验通过才处理），不要假设一次就能收完整帧；
  2. 校验失败要能重新同步：丢弃当前帧并回到「找帧头」状态；
  3. 若数据里可能出现帧头字节（0xAA 0x55），要做转义（如 0xAA 在数据中发成 0xBB 0xAA），否则会误判帧边界。

七、易错清单 + 自检 ​

  • [ ] TX/RX 接反：TX 接对方的 RX，交叉连接；接成 TX-TX 永远收不到
  • [ ] 波特率不一致：双方必须一致；注意波特率包含起始/停止位开销
  • [ ] 电平标准混接：RS232 的 ±12 V 直接进 MCU 会烧片
  • [ ] 忘了在中断回调里重新启动接收（HAL_UART_Receive_IT 只收一次）
  • [ ] 主循环里用轮询接收导致系统卡顿：改用中断或 DMA
  • [ ] 读波形时按正常顺序读：UART 是 LSB 先发，波形顺序与书写顺序相反
  • [ ] 没做帧同步：直接按「收到的第一字节是数据」解析，一旦丢一字节就永久错位
  • [ ] printf 的浮点格式化打不出来：新工具链默认裁剪了 %f 支持

自检：115200-8-N-1 下，一帧几位、有效速率多少字节/秒、传 1000 字节多久？USART2 在 36 MHz 下跑 115200 的误差是多少、是否安全？（答案：10 位 / 11520 字节每秒 / 86.8 ms；−0.16%，一帧累积 0.016 位，远小于 0.5 位容限，安全）

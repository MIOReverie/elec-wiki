09 · SPI 与 I²C ​

核心 约 40 min两种最常用的板级总线：一个快而费线，一个省线而优雅

结论先行 ​

  1. SPI 用 4 根线（SCK / MOSI / MISO / CS）全双工同步传输，速度可达几十 MHz，没有地址概念，靠片选 CS 选择从机。
  2. I²C 只用 2 根线（SCL / SDA）半双工，靠 7 位（或 10 位）地址在同一条总线上挂多个设备，代价是速度较慢（100 kHz / 400 kHz）。
  3. SPI 有四种模式（CPOL 决定时钟空闲电平、CPHA 决定第几个边沿采样），主从必须一致，否则数据会整体错位一位。
  4. I²C 是开漏 + 上拉的「线与」结构：任何器件都只能把线拉低，没人拉低时由上拉电阻变高——所以上拉电阻是必需的，不是可选。
  5. 选型依据：要高速、点对点、大数据量（屏、Flash、高速 ADC）→ SPI；引脚紧张、多设备、低速（传感器、EEPROM、IO 扩展）→ I²C。

一、为什么需要串行总线 ​

并行总线（8/16 根数据线 + 若干控制线）速度快但太费引脚。一颗 48 脚的 MCU 根本禁不起这样的消耗。串行总线用少数几根线分时传数据，用时间换引脚。

代价是协议复杂度——需要时钟同步、需要寻址、需要应答。SPI 和 I²C 就是两种不同取舍的产物。

二、SPI ​

四根线 ​

线方向作用
SCK主 → 从时钟，由主机产生
MOSI主 → 从Master Out Slave In，主机发数据
MISO从 → 主Master In Slave Out，从机回数据
CS / NSS主 → 从片选，低电平选中某个从机（每个从机一根）

全双工：主机在 MOSI 上发一位的同时，也在 MISO 上收一位。所以读操作也必须「发」——想读一个字节，就得先发一个字节（通常发 0xFF 这种无关值）来产生时钟。

四种模式 ​

两个参数决定时序：

  • CPOL（Clock Polarity）：时钟空闲时的电平（0 = 低，1 = 高）
  • CPHA（Clock Phase）：在第几个边沿采样数据（0 = 第一个边沿，1 = 第二个边沿）

组合成模式 0~3。绝大多数器件用模式 0 或模式 3。

F103 的 SPI1 挂在 APB2（PCLK2 = 72 MHz），SCK 由分频系数决定：

注意区分两个上限：一个是 SPI 外设本身的时钟上限（F103 是 18 MHz），另一个是从机器件的上限（比如某款 SPI Flash 只支持 10 MHz，某款屏幕支持 20 MHz）。取两者较小值。

另一个易错点：SPI2/SPI3 挂在 **APB1（36 MHz）**而不是 APB2，同样的分频系数得到的 SCK 只有 SPI1 的一半。

例 2 · 主从模式不一致会怎样

某 OLED 屏的手册写着「支持 SPI 模式 3（CPOL=1, CPHA=1）」，而工程师把 MCU 配成了模式 0（CPOL=0, CPHA=0）。

现象：屏幕要么全黑，要么显示错乱的数据。原因是采样边沿错位——从机在 SCK 的上升沿采样，而主机在下降沿才更新数据（或反过来），导致从机采到的永远是「上一位」或「正在变化中的位」。

表现特征：数据看起来整体偏移了一位（比如发送 0x9A = 1001 1010，收到的是 0x4D = 0100 1101，正好右移一位）。这是判断「模式配错」的典型指纹。

排查顺序：① 查从机器件手册确认它支持的模式；② 主从配成同一模式；③ 优先试模式 0 和模式 3（这两者覆盖绝大多数器件）。

三、I²C ​

两根线与「线与」 ​

I²C 只有 SCL（时钟）和 SDA（数据），两者都是开漏输出 + 上拉电阻。这意味着：

  • 任何器件只能把线拉低，不能主动驱动为高；
  • 只要有一个器件拉低，线就是低；所有器件都释放，线才被上拉变高。

这就是「线与」（wire-AND）逻辑，好处是：

  • 天然支持多主机（谁拉低谁说话，冲突可被检测）；
  • 不同电压的器件可以共存（上拉到各自电平，配电平转换）；
  • 从机可以通过拉低 SCL 来延长时钟（clock stretching），告诉主机「我还没准备好」。

代价：上拉电阻 + 总线电容构成一个 RC 充电回路，限制了上升沿速度和最高通信速率。

时序与地址 ​

一次「写寄存器」的完整时序：

START → 地址字节(写) → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP
  • START：SCL 为高时，SDA 出现下降沿
  • STOP：SCL 为高时，SDA 出现上升沿
  • ACK：每传完 8 位，接收方在第 9 个时钟把 SDA 拉低表示收到
  • 地址字节：7 位地址左移 1 位，最低位表示方向（0 = 写，1 = 读）

例 3 · 7 位地址和实际发出的字节不是一回事

MPU6050 的手册写着「从机地址 0x68」。但你在代码里/逻辑分析仪上看到的字节是：

写=0x68≪1  ∣  0=0xD0,读=0x68≪1  ∣  1=0xD1\text{写} = 0\text{x}68 \ll 1 \;|\; 0 = \text{0xD0},\qquad \text{读} = 0\text{x}68 \ll 1 \;|\; 1 = \text{0xD1} 写=0x68≪1∣0=0xD0,读=0x68≪1∣1=0xD1

同理：

器件7 位地址写字节读字节
MPU60500x680xD00xD1
SSD1306 OLED0x3C0x780x79
PCF8574 IO 扩展0x270x4E0x4F

这是最常见的困惑来源：手册给的是 7 位地址（未含方向位），而 HAL 的 HAL_I2C_Master_Transmit(hi2c, DevAddress, ...) 要求传的却是左移一位后的地址。用 HAL 时写成 0x68 会找不到器件——得写 0xD0（或者自己 addr << 1）。

判断方法：若你的地址是偶数、且器件手册地址是它的一半，说明你传对了（已左移）；若两者相等，说明忘了左移。

下限由驱动能力决定：电阻太小，器件拉低时需要吸收的电流过大（I=VCC/RpI = V_{CC}/R_pI=VCC​/Rp​），可能超出引脚的灌电流能力（一般要求 ≥ 3 mA 时的最小值约 1 kΩ @3.3 V）。

实用结论：

  • 100 kHz、短距离：4.7 kΩ（最常见）
  • 400 kHz：1.5~2.2 kΩ
  • 多器件、长线：先减小电阻，若还不行就降低速率

顺便算一下传输效率：100 kHz 下传一个字节需要 9 个位（8 数据 + 1 ACK）：

400 kHz 下则是 22.5 µs/字节。所以 I²C 传大量数据会很慢——这也是高速场合选 SPI 的原因。

五、工程实例 ​

SPI 的片选管理：多个 SPI 从机时，CS 一般用普通 GPIO 软件控制（不用硬件 NSS）。关键纪律：每次传输前拉低对应 CS、传输完立刻拉高；CS 期间不能被打断（否则从机会收到半个命令而状态错乱）。多任务环境里要给 SPI 总线加互斥。

I²C 死锁与恢复：若主机在传输中途复位（或从机拉住 SDA 不放），总线可能卡在 SDA 为低的状态，此后主机再也发不出 START。恢复方法：主机把 SCL 强行翻转 9 个周期（用 GPIO 模拟时钟），让从机释放 SDA，然后补发一个 STOP。很多产品的 I²C 驱动里都有这段「总线恢复」代码。

六、易错清单 + 自检 ​

  • [ ] SPI 主从模式（CPOL/CPHA）不一致：数据整体错位一位
  • [ ] SPI 时钟超过器件或外设上限
  • [ ] SPI2/3 挂在 APB1，同样分频下速度只有 SPI1 的一半
  • [ ] 读操作忘了发 dummy 字节：SPI 全双工，不给时钟就收不到数据
  • [ ] I²C 忘了接上拉电阻：开漏总线没有上拉就永远读不到高电平
  • [ ] I²C 地址忘了左移一位（或重复左移）
  • [ ] 没检查 ACK：地址错、器件没上电、总线被拉死时都会无 ACK，应检测并报错
  • [ ] CS 在传输中途被释放（多任务下未加互斥）

自检：SPI 有哪四根线、CPOL 和 CPHA 各决定什么？I²C 的 7 位地址 0x68 在写操作时发出的字节是什么？100 kHz、200 pF 总线下上拉电阻取多大？（答案：SCK/MOSI/MISO/CS；CPOL 决定时钟空闲电平、CPHA 决定第几个边沿采样；0xD0；约 4.7 kΩ）

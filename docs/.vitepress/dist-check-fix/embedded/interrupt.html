06 · 中断与 NVIC ​

核心 约 40 min抢占优先级决定能不能嵌套，ISR 必须快进快出——搞反了系统会变得极难调

抢占优先级与子优先级的分工、优先级分组的位数分配，见 。

结论先行 ​

  1. 中断是硬件打断 CPU 的机制：外设（按键、定时器、串口）有事件时主动通知 CPU，CPU 暂停当前代码去执行中断服务程序（ISR），执行完再回来。它让 MCU 不用空转轮询。
  2. 抢占优先级决定「能不能打断」：只有抢占优先级更高的中断才能嵌套进正在执行的 ISR。
  3. 子优先级只决定「排队顺序」：当多个中断同时挂起时，子优先级高的先执行；它永远不会造成嵌套。
  4. 数值越小优先级越高（0 最高）——这一点和很多 RTOS 里「任务优先级数字越大越优先」的习惯相反，极易记反。
  5. ISR 必须快进快出：只做「置标志 / 存数据 / 清中断」，具体处理交给主循环。在 ISR 里打印、延时、跑算法都是错误做法。

一、中断是怎么发生的 ​

Cortex-M 内核里有个 NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）统一管理所有中断。流程是：

外设事件发生（如按键按下）
   → 外设置位自己的中断标志
   → NVIC 收到请求，比较它与当前执行代码的优先级
   → 若允许，CPU 保存现场（自动压栈 R0-R3、R12、LR、PC、xPSR）
   → 从「中断向量表」里取出该中断对应的 ISR 地址，跳过去执行
   → ISR 结束，自动恢复现场，回到被打断的地方继续

向量表是一张放在 Flash 最开头的地址表，每个中断占一项，存着对应 ISR 的入口地址。所谓「中断号」就是这张表里的行号——编号越小，向量表里越靠前。

硬件自动压栈是 Cortex-M 相对于老架构的一大优势：进入中断不需要软件保存寄存器，所以中断延迟很短（通常十几个时钟周期）。

二、优先级：抢占 vs 子优先级 ​

两组概念的完整判据见 ；下面把它套到 STM32 的实际配置上。

Cortex-M 用 4 位表示优先级（STM32 实际只用高 4 位），这 4 位怎么分给「抢占」和「子」由优先级分组决定：

分组抢占位数抢占级数子优先级位数子级数
001 级416 级
112 级38 级
224 级24 级
338 级12 级
4416 级01 级

分组用 HAL_NVIC_SetPriorityGrouping() 设置，通常在 HAL_Init() 之后、SystemClock_Config() 里完成。整个系统只用一种分组，改来改去会导致优先级解读错乱。

例 1 · 该选哪个优先级分组

某系统有 3 个中断：按键（外部中断）、串口接收、定时采样，要求定时采样可以打断另外两个（因为它最紧急），另外两个之间不需要互相打断。

分析：需要至少 2 级抢占（定时采样用 0，其余用 1）。查表：

  • 分组 2：抢占 4 级 + 子 4 级 → 满足（抢占够用，还剩 4 级子优先级给「同时挂起」排序）
  • 分组 3：抢占 8 级 + 子 2 级 → 也满足，且抢占余量更大

选分组 3：抢占级数多一点，将来加中断不用改分组（改分组会使所有已设的优先级含义变化，风险大）。

配置：

c
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_3);
HAL_NVIC_SetPriority(TIM2_IRQn,     0, 0);   // 定时采样：抢占 0（最高），可打断别人
HAL_NVIC_SetPriority(USART1_IRQn,   1, 0);   // 串口：抢占 1
HAL_NVIC_SetPriority(EXTI0_IRQn,    1, 1);   // 按键：抢占 1，子 1（与串口同时挂起时排在后面）
HAL_NVIC_EnableIRQ(TIM2_IRQn);
HAL_NVIC_EnableIRQ(USART1_IRQn);
HAL_NVIC_EnableIRQ(EXTI0_IRQn);

例 2 · 判断会不会嵌套

设分组 2（抢占 4 级），三种情形：

情形结果
A 抢占 = 1 正在执行，B 抢占 = 0 到来B 抢占 A（0 < 1）：A 被暂停，B 执行完 A 继续
A 抢占 = 1 正在执行，B 抢占 = 2 到来B 不能打断：等 A 执行完后 B 才执行
A 抢占 = 1、子 = 0；B 抢占 = 1、子 = 1；A 正在执行不嵌套，B 排队。因为抢占相同——子优先级再高也不能打断正在执行的中断

第三种情形是最常见的误解：以为「子优先级高」就能插队打断。记住一句话：抢占管打断，子优先级管排队。

三、EXTI 外部中断 ​

GPIO 的电平变化要触发中断，要经过 EXTI（External Interrupt/Event Controller）。

关键约束：EXTI 有 16 条线（EXTI0~EXTI15），同一条线在同一时刻只能分配给一个端口。也就是说：

  • PA0、PB0、PC0、PD0…… 都「能」连到 EXTI0，但只能选其中一个；
  • 若你把 PA0 配成了 EXTI0，就不能同时用 PB0 做外部中断（会冲突）。

这一点在做板子引脚分配时非常重要——很多人原理图上把两个按键分别接到 PA0 和 PB0，然后发现两个中断只有一个能用。

触发方式：上升沿、下降沿、双边沿。按键通常配成下降沿（配合上拉输入：按下时从高变低）。

例 3 · 两个按键分别接 PA0 和 PB0，能都用外部中断吗

不能。 EXTI 线是按引脚编号组织的：Pin0 对应 EXTI0、Pin1 对应 EXTI1……而 PA0、PB0、PC0 等所有端口的 0 号引脚都连到同一条 EXTI0，由 AFIO->EXTICR 寄存器选择「此刻选哪个端口」。所以：

  • PA0 → EXTI0，PB0 → 也是 EXTI0，两者互斥；
  • 但 PA0（EXTI0）和 PB1（EXTI1）可以共存，因为它们用不同的 EXTI 线。

这个坑的表现：配好了两个中断，结果只有一个能用，或者第二个按键触发时进的是第一个的中断——因为两条线被挤在同一条 EXTI 上。

解决办法（任选）：

  1. 改引脚分配：把两个按键放到不同编号的引脚上（如 PA0 和 PB1），各用一条 EXTI 线；
  2. 用同一条 EXTI 线 + 在 ISR 里读 IDR 判断：把 PA0、PB0 都配成 EXTI0（共享中断），触发后在回调里读两个引脚的电平来区分是谁被按下；
  3. 不用外部中断：改用定时扫描（每 10 ms 读一次），顺便完成消抖，代码更简单也更可靠。

设计阶段就要查这个约束：画原理图时若把多个需要中断的信号放在同编号引脚上，改板的代价很高。

四、HAL 的中断处理链条 ​

HAL 把中断处理分成三层，理解这个链条才知道用户代码该写在哪：

c
// ① 向量表里的入口（在 stm32f1xx_it.c），由 CubeMX 生成
void EXTI0_IRQHandler(void) {
  HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);   // ② 交给 HAL 的公共处理函数
}

// ② HAL 公共处理（在库里）：检查中断标志、清除标志，然后调用回调
void HAL_GPIO_EXTI_IRQHandler(uint16_t GPIO_Pin) {
  if (__HAL_GPIO_EXTI_GET_IT(GPIO_Pin) != RESET) {
    __HAL_GPIO_EXTI_CLEAR_IT(GPIO_Pin);          // 清标志（必须！）
    HAL_GPIO_EXTI_Callback(GPIO_Pin);            // ③ 调用弱定义的回调函数
  }
}

// ③ 用户在自己的文件里重写这个弱函数
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
  if (GPIO_Pin == GPIO_PIN_0) key_flag = 1;      // 只置标志，不做重活
}

要点：

  • 不要改 stm32f1xx_it.c 里 IRQHandler 的内容（CubeMX 会重新生成）；
  • 用户逻辑写在 HAL_xxx_Callback 里（它是 __weak 弱定义，你重写一份即可覆盖）；
  • 清中断标志是必须的，否则中断会不断重复进入（HAL 公共函数已经帮你清了，自己写寄存器版时千万别忘）。

五、ISR 的编写纪律 ​

c
// ✅ 好的 ISR：短、只做必要的事
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
  ringbuf_put(&rx_buf, rx_byte);   // 存数据
  // 不打印、不延时、不做复杂运算
}

// ❌ 坏的 ISR
void HAL_GPIO_EXTI_Callback(uint16_t pin) {
  printf("key pressed\n");         // 串口打印很慢（毫秒级）
  HAL_Delay(20);                   // 延时 = 让 CPU 在中断里空转
  process_data();                  // 耗时算法，会阻塞所有低优先级中断
}

ISR 里绝对不要做的事：调用阻塞函数（HAL_Delay）、打印日志、做浮点运算（M3 上没有 FPU，很慢）、调用不可重入的函数（malloc、printf）。

共享数据的保护：ISR 与主循环共享的变量要加 volatile（见 03 章）；若是多字节结构（如环形缓冲的读写指针），访问时要关中断形成临界区：

c
__disable_irq();
uint16_t n = ringbuf_count(&rx_buf);
__enable_irq();

例 4 · 中断里调 HAL_Delay 为什么会卡死

HAL_Delay() 的实现是「死等 uwTick 增加到目标值」，而 uwTick 由 SysTick 中断里的 HAL_IncTick() 递增。

假设你在某个外部中断的 ISR 里调用了 HAL_Delay(10)，而这个外部中断的抢占优先级数值 ≤ SysTick 的抢占优先级（即它不低于 SysTick）：

  • 该 ISR 正在执行，抢占优先级不比 SysTick 低；
  • SysTick 中断无法抢占它；
  • uwTick 永远不增加；
  • HAL_Delay 永远等不到 → 程序彻底卡死。

解决方法（任选）：

  1. 不要在 ISR 里用 HAL_Delay——这是根本解法，ISR 本来就该快进快出；
  2. 若必须延时，把 SysTick 的抢占优先级设成最高（数值最小），保证它能抢占任何用户中断；
  3. 用 CubeMX 检查「Timebase Source」的优先级设置（默认是 SysTick，抢占 0；但一旦把某个用户中断也设成抢占 0，问题就出现了）。

这也是为什么「中断里不能阻塞」不是风格建议，而是硬性规则。

六、临界区与开关中断 ​

需要一段代码「不被打断」时（比如操作共享的环形缓冲），要临时关中断：

c
uint32_t primask = __get_PRIMASK();   // 保存当前状态
__disable_irq();                      // 关总中断
/* —— 临界区：尽量短 —— */
__set_PRIMASK(primask);               // 恢复（而不是无条件打开）

注意用 __get_PRIMASK() 保存状态再恢复，而不是粗暴地 __enable_irq()——否则在「调用前中断本来就是关的」场景下会错误地打开中断。

关中断的时间越短越好：它会增加系统的中断延迟，关太久会导致丢失中断事件。

七、工程实例 ​

用中断代替轮询的收益：一个需要每 1 ms 采集一次 ADC 的系统，若用轮询（while(1) 里不断查询），CPU 要么空转等待，要么被其他任务拖慢导致采样间隔不均。改成定时器中断触发采样后，采样时刻由硬件保证，抖动只有几个时钟周期，而且 CPU 在空闲时可以进入睡眠省电。

中断风暴：某产品把某个外部中断配成了双边沿触发并接到了一个有干扰的信号上，结果每秒产生上万次中断，系统几乎全部时间都在进出中断，主循环几乎不执行。教训：外部中断要确认信号干净（必要时加硬件滤波），并考虑用定时扫描 + 消抖替代边沿中断。

八、易错清单 + 自检 ​

  • [ ] 把优先级数值记反：0 是最高优先级，不是最低
  • [ ] 以为子优先级也能嵌套：只有抢占优先级更高才能打断
  • [ ] EXTI 线冲突：PA0 和 PB0 不能同时用作 EXTI0
  • [ ] 忘记清中断标志：中断会重复进入，程序像卡死一样反复执行 ISR
  • [ ] 在 ISR 里调用 HAL_Delay / printf / 浮点运算
  • [ ] 共享变量没加 volatile 或没保护临界区
  • [ ] 优先级分组前后不一致：改分组会使所有已设优先级含义改变
  • [ ] 开了中断没使能 NVIC（HAL_NVIC_EnableIRQ）

自检：抢占优先级和子优先级分别在什么时候起作用？EXTI0 能不能同时接 PA0 和 PB0？为什么 ISR 里不能调用 HAL_Delay？（答案：抢占管能否嵌套打断，子优先级只管同时挂起时的排队顺序；不能，同一条 EXTI 线同时只能分配给一个端口；因为 HAL_Delay 依赖 SysTick 中断递增 uwTick，若 SysTick 无法抢占当前 ISR 就会永远死等）
